DSUL is the language behind the foundation. It is an open-source, declarative language that describes and orchestrates full-stack, AI-powered applications in YAML. This is what makes the platform's promise concrete: a single, versionable definition that bridges front-end interfaces, backend workflows, and AI capabilities. It is the [Infrastructure-as-Code](/get-started/platform-overview#the-development-lifecycle) layer that keeps agents and applications reproducible instead of scattered across silos.

## Everything is a workspace

The unit DSUL describes is a **workspace**: a self-contained, full-stack application that runs on the platform. Every product (Chat, Agent Creator, Knowledges, and the others) is itself a workspace. [Builder](/products/ai-builder/overview) is the tool that creates workspaces and opens them to edit.

## Apps are SDKs

Publish a workspace and it becomes a versioned **App** in the [App Store](/apps-store/overview), behaving like an SDK. Import that App into another workspace and its instructions become available inside your automations. It is workspaces composing workspaces.

## Traditional development vs DSUL

**Traditional development**, per use case:

```
Frontend (React/Angular) → APIs → Microservices → Databases → AI Models
```

Multiple languages and frameworks, siloed teams, dedicated infrastructure per solution, duplicated effort, and inconsistent security and governance.

**DSUL approach:**

```
YAML Definitions → Builder Framework → Complete Application
```

One declarative language, a unified component model, standardized integration and databases, accessible to technical and non-technical stakeholders, with security policies enforced centrally. When you need custom logic, the Custom Code App and external APIs are always available.

## Core components

- **Pages**: declarative UI containers that define complete views and user journeys
- **Automations**: backend processes that orchestrate logic, workflows, and AI operations
- **Imports**: connectors, apps, MCP servers, and custom code installed into a workspace
- **Workspaces**: the project environment that encapsulates all resources and configuration
- **RBAC**: fine-grained access control

## Why DSUL for the enterprise

- **Shared, standardized infrastructure**: many agents run on the same multi-tenant platform with logical isolation, instead of dedicated infrastructure per agent. See [Platform Overview](/get-started/platform-overview).
- **Cloud and LLM agnostic**: the same definitions run on any major cloud or on-premises, with no vendor lock-in.
- **Native observability and traceability**: every action is a normalized event with a correlation ID, so monitoring and audit are built in.
- **Software-engineering discipline**: Git versioning, merge requests, and environment promotion. See [versioning](/products/ai-builder/versioning) and [deployment](/products/ai-builder/deployment).
- **Governed by design**: RBAC, audit trails, and central policy across every workspace. See [Governe](/products/ai-governance/overview).
- **Non-invasive integration**: connect legacy systems through declarative API connectors and an event-driven layer, without rewriting them.
