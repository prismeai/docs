The Excel connector exposes Microsoft Excel workbooks through the [Microsoft Graph](https://learn.microsoft.com/en-us/graph/api/resources/excel) workbook API. It ships as two pieces: the **Excel** app, installed from the Apps marketplace into a Builder workspace, which provides 56 deterministic DSUL instructions; and the **Excel MCP** connector workspace, which installs that app and republishes the same 56 operations as MCP tools over JSON-RPC 2.0 for **Agent Creator** agents. Both run in the app-instance context of the workspace that hosts them and resolve their Microsoft credential server-side. Agents and automations read, write, and manipulate cells, ranges, tables, charts, named items, and pivot tables in workbooks hosted on OneDrive or SharePoint.

Authentication has two modes, selected by the **Authentication Mode** (`authMode`) configuration field:

- **Client credentials** (`clientCredentials`, the mode used when `authMode` is empty): the connector requests a token from `https://login.microsoftonline.com/<tenant>/oauth2/v2.0/token` with `grant_type=client_credentials` and `scope=https://graph.microsoft.com/.default`. Microsoft sees the Entra application, not the end user. Best for unattended back-office automations over a shared document library.
- **Per-user delegated OAuth** (`oauth`): each user signs in with their own Microsoft account through an authorization-code flow with PKCE, and Microsoft enforces that user's own file permissions. Best for interactive Chat experiences over user-owned workbooks.

## Prerequisites (Microsoft side)

- A **Microsoft 365 / Microsoft Entra ID** tenant, with the workbooks you want to reach stored in **OneDrive** or **SharePoint**. The Graph workbook API operates on `.xlsx` files.
- An **app registration** in [Microsoft Entra ID](https://entra.microsoft.com) (**App registrations > New registration**), with a **client secret** created under **Certificates & secrets**.
- Note the **Application (client) ID**, the **client secret value**, and the **Directory (tenant) ID**. For SharePoint-hosted files, also note the **site ID**.

For the **client credentials** mode, grant Microsoft Graph **application** permissions and have a Global Administrator grant admin consent. The connector's own `403` message names the permissions it expects:

```text
Files.ReadWrite.All
Sites.ReadWrite.All
```

Read-only deployments can grant `Files.Read.All` and `Sites.Read.All` instead, at the cost of every write instruction failing with `Access denied`.

For the **per-user delegated OAuth** mode, grant the equivalent **delegated** permissions and add a **Redirect URI** of type **Web**:

```text
<api-url>/workspaces/<workspace-id>/webhooks/OAuth Core/oauthCallback
```

<Warning>
  The `OAuth Core` path segment is the slug of the imported OAuth Core app instance and contains a literal space. Register the redirect URI exactly as the connector builds it; a mismatch makes Microsoft reject the authorization request before the user ever reaches the consent screen.
</Warning>

The **Excel MCP** connector workspace requests this delegated scope string:

```text
openid profile email offline_access Files.ReadWrite.All Sites.ReadWrite.All User.Read
```

An **Excel** app instance used on its own in Builder requests `.default` instead, so the effective delegated permissions are whatever is consented on the app registration:

```text
openid profile email offline_access https://graph.microsoft.com/.default
```

    ## Agent builder

    **Goal:** let an agent you build in Agent Creator read and write Excel workbooks through Excel MCP tools.

    <Note>
      Before an agent can call the connector, a workspace builder must have configured the **Excel MCP** connector workspace with Microsoft Entra credentials and generated its MCP API key (see [Workspace builder (DSUL)](#workspace-builder-dsul)). A platform admin may also have published an **Excel** capability in the catalog (see [Platform admin (Governance): one-time platform setup](#platform-admin-governance-one-time-platform-setup)).
    </Note>

    The connector resolves its Microsoft credential server-side; it is never exposed to the agent.

    <Steps>
      <Step title="Get the MCP endpoint">
        From the connector workspace, copy its MCP endpoint URL, or use the published **Excel** capability if a platform admin declared one in [Platform admin (Governance): one-time platform setup](#platform-admin-governance-one-time-platform-setup):

        ```text
        <api-url>/workspaces/<workspace-id>/webhooks/mcp
        ```
      </Step>
      <Step title="Add the capability to your agent">
        In your agent in Agent Creator, add a capability pointing at the MCP endpoint URL, and set its **Scope** to:

        ```text
        context_id,agent_id,user_id
        ```

        The `user_id` is what lets the connector resolve the calling user's delegated token when the connector runs in `oauth` mode.
      </Step>
      <Step title="Test a read before a write">
        Ask the agent to list the worksheets of a workbook you can reach. It calls `listWorksheets` with the file's `itemId`. A successful call returns the worksheet names, which confirms credentials, permissions, and file addressing in one step.
      </Step>
      <Step title="Publish the agent">
        Select **Publish**. Only the tools you enabled on the capability are exposed to end users.
      </Step>
    </Steps>

    ### First connection for an end user (delegated OAuth only)

    When the connector workspace runs in `oauth` mode and the user has no valid token, the tool call fails with a message that carries the connect link:

    ```text
    OAuth authentication required. Connect your Microsoft account: <pages-url>/connect-excel
    ```

    The user opens that page, selects **Connect with Microsoft**, signs in, and returns to the connect page with a **Connected** banner. Retrying the request in Chat then succeeds. The same page offers **Disconnect** to revoke the stored tokens.

    ### Brief the agent in its system prompt

    Wiring the capability is not enough: the agent must know the tools exist and how to address a file. Copy-pasteable starter:

    ```text
    You have access to the Excel MCP server (Microsoft Graph). Use it to read, write, and reshape Excel workbooks stored in OneDrive or SharePoint.
    Always address a workbook by its itemId (the Graph drive item id). For SharePoint-hosted files, also pass siteId (and driveId to target a specific document library). Use A1 notation for ranges, for example A1:C10.
    Call listWorksheets before reading a sheet: worksheet names are localised, so a French tenant uses "Feuil1" where an English one uses "Sheet1".
    Read with getRange or getUsedRange before writing. Write values with updateRange. Use the table tools (createTable, addTableRow, applyTableFilter) for structured data, and executeExcelFunction to evaluate a workbook function. Call calculateWorkbook after bulk edits.
    ```

    <Note>
      **Legacy AI Knowledge agents** (no native MCP picker): add the connector under **Advanced > Tools > MCP** and paste the MCP endpoint URL.
    </Note>

    ## Output formats

    Every tool accepts an `outputFormat` argument that controls the MCP response shape:

    - `verbose` (the default when the argument is omitted): a human-readable text summary of the operation, optimized for LLM consumption.
    - `structured`: the payload serialized as JSON in `content[0].text`, and the same object in `structuredContent`.
    - `both`: the same response as `structured`.

    ## Tool details

    ### getRange

    ```json
    {
      "name": "getRange",
      "arguments": {
        "itemId": "01ABCDEF",
        "worksheetId": "Sheet1",
        "address": "A1:C10"
      }
    }
    ```

    | Parameter | Required | Description |
    |-----------|----------|-------------|
    | `itemId` | Yes | Graph drive item id of the workbook. |
    | `worksheetId` | Yes | Worksheet name or id. |
    | `address` | Yes | Range in A1 notation, for example `A1:C10`. |
    | `siteId` | No | SharePoint site id, for SharePoint-hosted files. |
    | `driveId` | No | Specific document library or drive id. |
    | `outputFormat` | No | `verbose`, `structured`, or `both`. |

    ### updateRange

    ```json
    {
      "name": "updateRange",
      "arguments": {
        "itemId": "01ABCDEF",
        "worksheetId": "Sheet1",
        "address": "A1:C2",
        "values": [
          ["Name", "Age", "City"],
          ["Ada", 30, "Paris"]
        ]
      }
    }
    ```

    | Parameter | Required | Description |
    |-----------|----------|-------------|
    | `itemId` | Yes | Graph drive item id of the workbook. |
    | `worksheetId` | Yes | Worksheet name or id. |
    | `address` | Yes | Target range in A1 notation. Its dimensions must match `values`. |
    | `values` | Yes | 2D array of cell values to write. |
    | `formulas` | No | 2D array of formulas to write. |
    | `numberFormat` | No | 2D array of number-format strings. |
    | `siteId`, `driveId` | No | SharePoint targeting. |

    ### createTable

    ```json
    {
      "name": "createTable",
      "arguments": {
        "itemId": "01ABCDEF",
        "worksheetId": "Sheet1",
        "address": "A1:C10",
        "hasHeaders": true
      }
    }
    ```

    | Parameter | Required | Description |
    |-----------|----------|-------------|
    | `itemId` | Yes | Graph drive item id of the workbook. |
    | `worksheetId` | Yes | Worksheet name or id. |
    | `address` | Yes | Source range for the table in A1 notation. |
    | `hasHeaders` | No | Whether the first row contains column headers. |

    ### addChart

    ```json
    {
      "name": "addChart",
      "arguments": {
        "itemId": "01ABCDEF",
        "worksheetId": "Sheet1",
        "type": "ColumnClustered",
        "sourceData": "A1:C10",
        "seriesBy": "Auto"
      }
    }
    ```

    | Parameter | Required | Description |
    |-----------|----------|-------------|
    | `itemId` | Yes | Graph drive item id of the workbook. |
    | `worksheetId` | Yes | Worksheet name or id. |
    | `type` | Yes | Chart type, for example `ColumnClustered`, `Pie`, or `LineMarkers`. |
    | `sourceData` | Yes | Range that supplies the chart data, in A1 notation. |
    | `seriesBy` | No | How series are grouped: `Auto`, `Columns`, or `Rows`. |

    ### executeExcelFunction

    The function name is lowercased before the call, and `parameters` is sent as the request body, so its keys must match the Graph workbook function signature.

    ```json
    {
      "name": "executeExcelFunction",
      "arguments": {
        "itemId": "01ABCDEF",
        "functionName": "SUM",
        "parameters": {
          "values": [1, 2, 3]
        }
      }
    }
    ```

    | Parameter | Required | Description |
    |-----------|----------|-------------|
    | `itemId` | Yes | Graph drive item id of the workbook. |
    | `functionName` | Yes | Excel workbook function name, for example `SUM`, `PMT`, or `AVERAGE`. |
    | `parameters` | Yes | Function parameters as a JSON object. |

    ## Workspace builder

    **Goal:** configure the Excel connector with a Microsoft Entra credential and call Excel instructions from your automations, or expose them to agents over MCP.

    ## Installation

    1. Go to **Apps** in your workspace.
    2. Search for **Excel** and install it.
    3. Open the app instance configuration, fill in the Microsoft Entra values, and select **Save**.

    <Note>
      Excel predates the App + MCP configuration-app model used by newer connectors, so [Install a connector in your workspace](/apps-store/marketplace/connectors/install-in-workspace) does not describe this connector. There is no **Configuration app** link on the instance and no configuration SPA: you type the credentials into the app instance configuration form itself, and they are stored in the workspace secrets listed below. There is also no **Authorized agents** allowlist. The **MCP API Key** is the only gate on the MCP endpoint, so any caller holding the endpoint URL and that key can invoke every tool.
    </Note>

    To expose the same operations as MCP tools instead, use the **Excel MCP** connector workspace: it installs the **Excel** app for you, stores the Entra values in its own workspace secrets, and publishes the MCP endpoint at `<api-url>/workspaces/<workspace-id>/webhooks/mcp`.

    ## Configuration

    | Field | Description |
    |-------|-------------|
    | **Azure Client ID** (`clientId`) | Microsoft Entra application (client) ID used to call Microsoft Graph. Backed by the `azureClientId` workspace secret. |
    | **Azure Client Secret** (`clientSecret`) | Client secret value of that application. Backed by the `azureClientSecret` workspace secret and masked in the form. |
    | **Azure Tenant ID** (`tenant`) | Microsoft Entra directory (tenant) ID (GUID). Backed by the `azureTenant` workspace secret. |
    | **SharePoint Site ID** (`siteId`) | Optional default SharePoint site ID for SharePoint-hosted files. Backed by the `azureSiteId` workspace secret. |
    | **Authentication Mode** (`authMode`) | `clientCredentials` or `oauth`. Backed by the `authMode` workspace secret. |
    | **OAuth Client ID** (`oauthClientId`) | Microsoft Entra application (client) ID used for the delegated flow. Read only when **Authentication Mode** is `oauth`. |
    | **OAuth Client Secret** (`oauthClientSecret`) | Client secret for that delegated application. Masked in the form. |

    The **Excel MCP** connector workspace adds one secret of its own, **MCP API Key** (`mcpApiKey`), and reuses `azureClientId` and `azureClientSecret` for the delegated flow. Generate the key from the MCP Core **API Key** page rather than typing a value: `tools/call` is refused outright when no key is configured.

    ## Authentication modes

    | Mode | What you provide | Identity Microsoft sees | Best for |
    |------|------------------|-------------------------|----------|
    | `clientCredentials` (used when `authMode` is empty) | Azure Client ID, Client Secret, Tenant ID | The Entra application, with the application permissions consented on it | Unattended automations and shared document libraries |
    | `oauth` | OAuth Client ID and Secret, plus a per-user connect flow | The signed-in Microsoft user, with that user's own file permissions | Interactive Chat over user-owned workbooks |

    <Warning>
      In `clientCredentials` mode every caller shares one Entra identity, so every workbook that identity can reach is reachable by any agent or automation bound to the instance, and Microsoft audit logs attribute the change to the application rather than to a person. Grant the narrowest Graph application permissions the workflow needs, and prefer `oauth` whenever a workbook belongs to a person.
    </Warning>

    <Warning>
      When `siteId` and `driveId` are both absent, the connector targets `https://graph.microsoft.com/v1.0/me/drive`, which an application-permission token cannot resolve. In `clientCredentials` mode, set a **SharePoint Site ID** on the instance or pass `driveId` on every call.
    </Warning>

    Per request, an MCP tool call also forwards two HTTP headers to the underlying instruction: `accesstoken` supplies a caller-managed Microsoft Graph token that bypasses credential resolution, and `auth-mode` overrides the configured mode. Leave both unset unless a caller genuinely owns its own Graph token; a request that carries `accesstoken` runs with whatever permissions that token holds.

    ### Delegated OAuth token lifecycle

    Access tokens are stored as a user-scoped platform secret named `excel_delegated_token` with a time to live matching the provider's `expires_in`. Refresh tokens are stored as `excel_refresh_token` with a 90-day time to live and are rotated when Microsoft returns a new one. An expired access token is refreshed transparently; a failed refresh returns `OAuth session expired` with the action `reauthorize`, and the user has to connect again.

    ## File addressing

    **OneDrive** files need only an `itemId`. **SharePoint** files need `itemId` plus `siteId`, and optionally `driveId` to target a specific document library. A `siteId` passed on the call overrides the instance default; `driveId` has no instance default and must always come from the call.

    <Note>
      Worksheet names are localised. A `404` on a worksheet path is most often a wrong sheet name (`Feuil1` on a French tenant, `Sheet1` on an English one). The connector adds that hint to its own `404` message and tells the caller to run `listWorksheets` first.
    </Note>

    ## Response shape

    Instructions do not return the raw Microsoft Graph payload. They return a presentation envelope, and the data lives under `structuredData`:

    ```yaml
    - Excel.getRange:
        itemId: '{{workbookItemId}}'
        worksheetId: Sheet1
        address: "A1:C10"
      output: range
    # range.operation          -> read
    # range.itemType           -> Range
    # range.identifier         -> Sheet1!A1:C10
    # range.structuredData     -> address, rowCount, columnCount, cellCount, values, formulas, numberFormat, text
    ```

    A failing call returns `{ error, status, details }` instead, so branch on `{{range.error}}` before reading `structuredData`.

    ## DSUL examples

    ### Read a range

    ```yaml
    - Excel.getRange:
        itemId: '{{workbookItemId}}'
        worksheetId: Sheet1
        address: "A1:C10"
      output: range
    - conditions:
        '{{range.error}}':
          - break: {}
    - set:
        name: rows
        value: '{{range.structuredData.values}}'
    ```

    ### Read a SharePoint-hosted range

    ```yaml
    - Excel.getRange:
        itemId: '{{workbookItemId}}'
        siteId: '{{sharePointSiteId}}'
        worksheetId: Sheet1
        address: "A1:C10"
      output: range
    ```

    ### Write values

    ```yaml
    - Excel.updateRange:
        itemId: '{{workbookItemId}}'
        worksheetId: Sheet1
        address: "A1:C2"
        values:
          - ["Name", "Age", "City"]
          - ["Ada", 30, "Paris"]

    ```

    ### Create a table from a range

    ```yaml

        itemId: '{{workbookItemId}}'
    ```

    ```yaml

        itemId: '{{workbookItemId}}'
        calculationType: Full
      output: recalc
    ```

    3. Only then run a write instruction such as `Excel.updateRange` against a scratch workbook, and confirm the change in Excel.

## Error handling

The connector maps Microsoft Graph HTTP statuses to fixed messages and returns `{ error, status, details }`.

| HTTP status | Message | Resolution |
|-------------|---------|------------|
| 400 | `Invalid request: <Graph message>`, or an operation-specific hint such as `Invalid range address. Use A1 notation like 'A1:C10'.` | Fix the argument named in the hint. |
| 401 | `Authentication failed. Token may have expired or credentials are invalid.` | Re-check the client secret and tenant ID, or reconnect the Microsoft account in `oauth` mode. |
| 403 | `Access denied. Check application permissions (Files.ReadWrite.All, Sites.ReadWrite.All).` | Grant the missing Graph permissions on the app registration and have an administrator grant admin consent. |
| 404 | `Resource not found. Verify the ID is correct.`, or an operation-specific hint. On a worksheet path the message adds a localisation hint and asks you to call `listWorksheets`. | Verify `itemId`, plus `siteId` and `driveId` for SharePoint, and confirm the worksheet name. |
| 409 | `Conflict. The resource may have been modified by another request.` | Re-read the resource and retry. |
| 423 | `File is locked. Close it in the Office desktop app and try again.` | Close the workbook in the desktop app or wait for autosave to release the lock. |
| 429 | `Rate limited by Microsoft Graph API. Please wait and try again.` | Back off and retry, honouring the `Retry-After` header returned by Microsoft Graph. |
| Any other status at or above 400 | `API call failed with status <status>` | Inspect `details`, which carries the raw Graph error object. |

### Common Issues

**`Missing Azure credentials. Please configure clientId, clientSecret, and tenant in the app configuration.`**: the instance has no `clientId`, `clientSecret`, or `tenant`. Open the Excel app instance, fill the three fields, and select **Save**.

**`Client credentials auth failed: <description>`**: Microsoft Entra rejected the token request. The tenant ID is wrong, the client secret expired, or the application has no Graph application permissions. The description is the raw `error_description` returned by Microsoft.

**`OAuth authentication required. Please connect your Microsoft account first: <connect-url>`**: the instance runs in `oauth` mode and the calling user has no valid delegated token. Open the connect page, select **Connect with Microsoft**, then retry. Over MCP the same condition is returned as `OAuth authentication required. Connect your Microsoft account: <pages-url>/connect-excel`.

**`OAuth is not configured for this workspace. Contact the administrator.`**: `oauthClientId` is empty. The connect page shows the same condition as an **OAuth is not configured** banner and hides the connect button.

**`Error: Invalid state parameter. Please retry authentication.`**: the OAuth state no longer matches the pending value, usually because the browser session changed mid-flow. Reopen the connect page and start over.

**`Missing required parameter: <name>`**: the tool or instruction was called without a mandatory argument. JSON-RPC code `-32602`.

**`Tool not found: <name>`**: the MCP client asked for a tool the router does not know. Re-run `tools/list` to refresh the manifest.

**`API key not configured. Generate one from the API Key page.`**: the MCP endpoint has no `apiKey`. Generate one on the MCP Core **API Key** page of the connector workspace. JSON-RPC code `-32001`.

**MCP API key header rejected**, with either of these messages:

```text
Missing mcp-api-key header. Add header "mcp-api-key" with a valid API key.
Invalid mcp-api-key. Check that the API key value is correct.
```

The `tools/call` request did not carry the MCP API key header, or carried a value that does not match the configured key. `initialize`, `notifications/initialized`, and `tools/list` are answered without a key; `tools/call` is not. JSON-RPC code `-32001`.

**`Cannot delete the last worksheet in a workbook.`**: `deleteWorksheet` refuses to leave a workbook with no sheets. Add a worksheet first.

## Revoke, rotate, and remove

- **Disconnect one user (delegated OAuth):** on the `/connect-excel` page, select **Disconnect**. The connector deletes the `excel_delegated_token` and `excel_refresh_token` user secrets and the stored OAuth metadata, then emits `excel.oauth.disconnected`. The next tool call returns the `OAuth authentication required` message with the connect link.
- **Offboard a departing user:** disconnecting removes the platform-side tokens. Revoke the user's Microsoft sessions in Microsoft Entra as well, so the refresh token cannot be replayed.
- **Rotate the client secret:** create a new secret on the app registration in Microsoft Entra, update the `azureClientSecret` workspace secret, and select **Save**. In `clientCredentials` mode the next call uses the new secret; in `oauth` mode existing refresh tokens keep working until they expire, and a failed refresh sends the user back through the connect page.
- **Rotate the MCP API key:** generate a new key on the MCP Core **API Key** page, then update every agent capability and MCP client that sends the MCP API key header. Calls that still carry the previous key are rejected with the invalid-key message shown in [Common Issues](#common-issues).
- **Remove the connector:** uninstall the **Excel** app instance from the workspace, and delete the **Excel** capability from AI Governance if a platform admin declared one. Uninstalling stops all access but does not delete the per-user token secrets, so ask each connected user to select **Disconnect** first.
