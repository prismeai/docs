The Tableau connector exposes the Tableau platform (REST API 3.x, Metadata GraphQL, VizQL Data Service and Pulse) to your Prisme.ai workspaces. It can be consumed two ways: as a remote MCP server that **Agent Creator** agents call as tools, or as a Builder app whose instructions (`Tableau.<operation>`) you call directly from DSUL. Authentication is a Tableau **Personal Access Token** (PAT) stored as a workspace secret; the connector exchanges it server side for a short-lived `X-Tableau-Auth` session token, so the credential is never exposed to the agent.

## Operating model and runtime identity

Tableau ships a single authentication mode, so there is no credential decision to make: the connector always authenticates with one **Tableau Personal Access Token** per installing workspace. Read this table before you configure anything.

| Question | Answer for this connector |
|---|---|
| Credential model | Shared service credential (a Tableau Personal Access Token), one set per installing workspace |
| Runtime identity at Tableau | The **Tableau user who owns the PAT**, never the invoking end user or the agent builder |
| Where the credential lives | Four workspace secrets in the installing workspace: `tableauServerUrl`, `tableauSiteContentUrl`, `tableauPatName`, `tableauPatSecret` |
| What the agent sees | Tool results only. The PAT and the session token are resolved server side |
| Permission enforcement point | Tableau, based on the site role and content permissions of the PAT owner |
| Audit attribution at Tableau | All reads and writes are attributed to the PAT owner, not to the person who asked |
| Supported deployments | Tableau Cloud and Tableau Server. Site administration and server schedule operations are Tableau Server only |

<Warning>
  Because every call uses one shared PAT, Tableau attributes all activity to that single account, and every agent wired to this connector inherits that account's permissions, including writes and deletes. Create the PAT on a Tableau user whose site role and content permissions are the narrowest that cover your use case, and treat the four workspace secrets as production credentials.
</Warning>

## How a tool call is resolved

The MCP endpoint is **shared by every workspace that installs the connector**. Tenants are told apart by a signed key, not by a per-workspace URL.

1. On install, the app instance asks the central Tableau workspace for a signed **MCP API Key**. The key encodes the installing workspace id and the URL of that instance's credential webhook, and is signed with an HMAC secret that only the central workspace holds.
2. On every `tools/call`, the endpoint verifies the key, decodes the workspace id, and calls that workspace's credential webhook.
3. The credential webhook resolves the four secrets, signs in to Tableau with `POST /api/{apiVersion}/auth/signin`, and returns a short-lived `X-Tableau-Auth` session token plus the resolved `siteId`, `userId`, `serverUrl` and `apiVersion`.
4. The endpoint caches those credentials for 10 minutes per workspace and dispatches the tool call.
5. A Tableau PAT allows only one active session. If a concurrent sign-in revoked the cached token, the call returns `401`; the endpoint then forces a fresh sign-in and replays the call once.

`initialize` and `tools/list` are answered without the key. Only `tools/call` requires it. The MCP server announces itself as `tableau-mcp` version `1.0.0`.

## Prerequisites

- A **Tableau Cloud** site or a **Tableau Server** installation reachable from Prisme.ai over HTTPS.
- A **Personal Access Token** created on the target site under **My Account Settings > Personal Access Tokens**. You need its **name** and its **secret**; the secret is displayed only once, at creation.
- The Tableau user who owns the PAT must exist on the target site and already hold the site role and content permissions you want to expose. The connector never elevates beyond that account.
- The site `contentUrl` when you are not on the *Default* site: the segment after `/site/` in the Tableau browser URL.
- Optional: the **REST API version** to target. It defaults to `3.21`.
- In Prisme.ai, the workspace role required to install an app and to write workspace secrets in Builder.

<Accordion title="Platform admin (Governance): one-time platform setup" icon="shield-halved">
  <Note>
    **No platform-level Tableau credential is required.** Every installing workspace supplies its own Personal Access Token, and the connector resolves it server side. There is no shared Tableau account, no central OAuth client and no per-user OAuth flow to register, so [Central OAuth client](/apps-store/marketplace/connectors/central-oauth) does not apply to Tableau. The only platform-side secret is the HMAC signing secret used to mint MCP API keys, and the central workspace generates and stores it automatically on the first key request.
  </Note>

  Publishing a capability is optional. Do it when you want agent builders to pick **Tableau** from the capability catalog instead of wiring an MCP endpoint by hand.

  Tableau ships no configuration app, so the button-driven paths of the shared guide do not exist here: there is no **Install capability** action and no **Add to catalog** action. Use the manual path, [Declare the capability manually in AI Governance](/apps-store/marketplace/connectors/declare-capability#declare-the-capability-manually-in-ai-governance), and enter these Tableau values:

  | Capability field | Value for Tableau |
  |---|---|
  | Capability type | `mcp` |
  | Server URL (**SSE/WebSocket URL**) | The **MCP Endpoint** field of an installed Tableau app instance. It is the same shared URL for every workspace |
  | **Scope** | `context_id,agent_id,user_id`. See [What the Scope means](/apps-store/marketplace/connectors/declare-capability#what-the-scope-means) |
  | Request header | The workspace's **MCP API Key**, added exactly as shown in [Agent builder (Agent Creator)](#agent-builder-agent-creator). The key, not the URL, is what selects the workspace whose Tableau credentials are used |
  | Authorization block | None. Tableau has no per-user OAuth flow, so no `oauth2` block is added |

  Because the endpoint is shared and the key carries the workspace identity, a capability you publish here always resolves to the credentials of the workspace whose key it carries. Access to the catalog follows your organization's existing roles; there is no per-capability role grant for this connector.

  <Warning>
    This connector has no per-agent allowlist. The final step of the shared guide, allowlisting each agent at the connector, has no equivalent for Tableau: any agent that holds the endpoint URL and a valid workspace key can call every tool with that workspace's PAT, and [Availability is not authorization](/apps-store/marketplace/connectors/declare-capability#availability-is-not-authorization) therefore collapses into a single gate here. Publish a capability only for a workspace whose PAT you are comfortable exposing to every builder in the organization, and keep the key out of agent instructions, prompts and logs.
  </Warning>
</Accordion>

    **Goal:** let an agent you build in Agent Creator query and act on Tableau through MCP tools.

    <Note>
      Before an agent can call the connector, a workspace builder must have installed the Tableau app in a workspace and filled the four Tableau secrets, as described in [Workspace builder (DSUL)](#workspace-builder-dsul).       <Step title="Add the MCP capability to your agent">

        ```text
        mcp-api-key: <MCP API Key value>
        ```

        The **Scope** field lists the identifiers Agent Creator injects into every call; it is not a list of Tableau permissions. See [What the Scope means](/apps-store/marketplace/connectors/declare-capability#what-the-scope-means).

        If a platform admin published a **Tableau** capability in the catalog, as described in [Platform admin (Governance): one-time platform setup](#platform-admin-governance-one-time-platform-setup), pick it instead; the endpoint, the scope and the header are already wired.
      </Step>
      <Step title="Save and publish the agent">
        Select **Save**, then publish the agent so the capability is active outside the playground.
      </Step>
      <Step title="Verify with a read-only call">
        Ask the agent a question that resolves to a read, for example "List the workbooks in the Marketing project". A correct setup returns a workbook list. Missing or malformed header values fail before Tableau is contacted, with the JSON-RPC errors listed in [MCP endpoint errors](#mcp-endpoint-errors).

    ## Brief the agent in its system prompt

    Wiring the capability is not enough: the agent must know the tools exist and when to use them. Use this as a starting point and adapt the trigger words to your context.

    ```text
    You have access to the Tableau MCP server. Use it whenever the user asks about Tableau content (workbooks, views, datasources, projects, Prep flows, schedules, jobs, subscriptions, Pulse metrics or insights), wants to query a published datasource, or wants to trace lineage. Prefer the vizqlData tool for analytical questions (aggregations, top N, filters) and call vizqlData with action readMetadata before queryDatasource to discover the exact field captions. To read a single view, use views with action getByPath or a name filter instead of listing the whole site. Never claim you can attach an image, PDF or file: those actions are not available, so call the matching get action and share the webpageUrl instead. Ask the user to confirm before any destructive action (deleting a workbook, datasource, project, group or schedule, cancelling a job, removing a permission).
    ```

    <Note>
      **Legacy AI Knowledge agents** (no native MCP picker): add the connector under **Advanced > Tools > MCP**, paste the **MCP Endpoint** URL, and add the same request header.
    </Note>

    ## Output formats and payload limits

    Every tool accepts an `outputFormat` argument that controls the MCP response shape:

    - `verbose` (default): human-readable text for LLM consumption.
    - `structured`: JSON in `structuredContent`.
    - `both`: text and structured content.

    Responses are bounded before they reach the agent:

    | Limit | Value | Effect |
    |---|---|---|
    | Page size | `100` | `pageSize` and `page_size` are clamped to `100`. Read `pagination.totalAvailable` to know how much is left. |
    | Array items | `100` | Every array in a response is truncated to its first 100 items. |
    | Text responses | `20000` characters | CSV from `views` `getData` and `getSummaryData` is cut on the last complete row, and the reply states how many rows were kept out of the total. |
    | Nested objects | Reference collapsing | Nested objects that look like references are reduced to `id`, `name`, `type` and `contentUrl`. |

    <Warning>
      **Binary content is not available through MCP.** These operations are short-circuited with an explanatory message instead of a file: `views` `getImage`, `getPdf`, `getCrosstabExcel`; `workbooks` `download`, `downloadPdf`, `downloadPreviewImage`, `downloadPowerPoint`, `downloadRevision`; `datasources` `download`, `downloadRevision`; `flows` `download`. To give a user access to that content, call the matching `get` action and share the asset `webpageUrl`. For the underlying numbers, use `views` `getData` or the `vizqlData` tool.
    </Warning>

    ```json
    {
      "name": "metadata",
      "arguments": {
        "action": "search",
        "name": "Quarterly Review"
      }
    }
    ```

    | Parameter | Required | Description |
    |-----------|----------|-------------|
    | `action` | Yes | `query`, `search`, `workbookLineage` or `datasourceLineage`. |

    ### `vizqlData`

    ```json
    {
      "name": "vizqlData",
      "arguments": {
        "action": "queryDatasource",
        "datasource": { "datasourceLuid": "<datasource LUID>" },
        "query": {
          "fields": [
            { "fieldCaption": "Region" },
            { "fieldCaption": "Sales", "function": "SUM", "fieldAlias": "Total" }
          ],
          "filters": [
            { "field": { "fieldCaption": "Region" }, "filterType": "SET", "values": ["EMEA"] }
          ]
        }
      }
    }
    ```

    | Parameter | Required | Description |
    |-----------|----------|-------------|
    | `action` | Yes | `readMetadata` or `queryDatasource`. Call `readMetadata` first to discover the exact field captions. |
    | `datasource` | Yes | Object with `datasourceLuid`, taken from `workbooks` `getConnections` (field `datasource.id`) or `datasources` `list`. |
    | `query` | Conditional | Required for `queryDatasource`. Must contain `fields`; supports `filters` and per-field `function`, `fieldAlias`, `sortDirection`, `sortPriority`. |
    | `options` | No | `returnFormat` (`OBJECTS` or `ARRAYS`) and `debug`. |

    Supported aggregation functions: `SUM`, `AVG`, `MEDIAN`, `COUNT`, `COUNTD`, `MIN`, `MAX`, `STDEV`, `VAR`, `YEAR`, `QUARTER`, `MONTH`, `WEEK`, `DAY`. Supported `filterType` values: `SET` (`values`, `exclude`), `QUANTITATIVE_NUMERICAL` and `QUANTITATIVE_DATE` (`quantitativeFilterType` `MIN`, `MAX`, `RANGE`, `ONLY_NULL`, `ONLY_NON_NULL`, plus `min`, `max`, `minDate`, `maxDate`), `MATCH` (`contains`, `startsWith`, `endsWith`), `DATE`, and `TOP` (`howMany`, `direction`).

    ## Workspace builder

    **Goal:** install the connector in a workspace, supply the Tableau Personal Access Token, and call Tableau operations from your automations.

    ## Installation

    <Note>
      Tableau does **not** follow the standard flow described in [Install a connector in your workspace](/apps-store/marketplace/connectors/install-in-workspace). Three differences change what you do here:

      - **No configuration app.** Credentials are typed into the workspace **Secrets** in Builder, not into a configuration app, so the warning on the shared page about never editing secrets by hand does not apply to this connector.
      - **No authorized-agents allowlist.** Tableau provisions no `AuthorizedAgents` secret and performs no per-agent check, so [Authorize the agents that may call the connector](/apps-store/marketplace/connectors/install-in-workspace#authorize-the-agents-that-may-call-the-connector) has no equivalent step and the `This agent is not authorized to use this connector.` error never occurs.
      - **A shared MCP endpoint.** The endpoint is not derived from your workspace slug; it is one central URL, and your workspace's **MCP API Key** is what identifies you on it.

      Follow the steps below instead. The Tableau equivalent of [Rotate credentials and uninstall](/apps-store/marketplace/connectors/install-in-workspace#rotate-credentials-and-uninstall) is the last section of this tab.
    </Note>

    <Steps>
      <Step title="Install the app">
        In your workspace, open **Apps**, search for **Tableau** and install it. Installation generates the read-only **MCP Endpoint** and **MCP API Key** values, and provisions four empty Tableau secrets in the workspace.
      </Step>
      <Step title="Fill the Tableau secrets">
        Open **Secrets** in the workspace and fill `tableauServerUrl`, `tableauPatName` and `tableauPatSecret`. Fill `tableauSiteContentUrl` only when you are not on the *Default* site. Each secret carries a description explaining what it expects. Select **Save**.
      </Step>
      <Step title="Optional: pin the REST API version">
        In the app instance configuration, set **REST API Version** only when your Tableau Server release requires a version other than `3.21`.
      </Step>
      <Step title="Verify with a read-only call">
        Run an automation containing a single `Tableau.listProjects` instruction. A correct setup returns the Tableau REST response body listing your projects. A workspace with unfilled secrets returns `{ "error": "Tableau auth not configured. Required: patName, patSecret, serverUrl." }` without contacting Tableau.
      </Step>
    </Steps>

    <Note>
      The four credential fields in the app instance configuration (`serverUrl`, `siteContentUrl`, `patName`, `patSecret`) are bound to the workspace secrets on install. Edit the values in **Secrets**, not in the app configuration form, so the binding is preserved.
    </Note>

    ## Configuration

    | Field | Type | Required | Description |
    |-------|------|----------|-------------|
    | `serverUrl` | string | Yes | Full URL of the Tableau Cloud pod or Tableau Server instance, for example `https://<pod>.online.tableau.com` or `https://tableau.example.com`. Trailing slashes are stripped. Bound to the `tableauServerUrl` secret. |
    | `siteContentUrl` | string | No | Site identifier from the Tableau URL, the segment after `/site/`. Leave empty for the *Default* site on Tableau Server. Bound to the `tableauSiteContentUrl` secret. |
    | `patName` | string | Yes | Personal Access Token name. Bound to the `tableauPatName` secret. |
    | `patSecret` | string (secret) | Yes | Personal Access Token secret value, shown only once at creation. Bound to the `tableauPatSecret` secret. |
    | `apiVersion` | string | No | REST API version. Defaults to `3.21`. |
    | `mcpEndpoint` | string | Read-only | URL of the shared MCP endpoint. Hand this to the [agent builder](#agent-builder-agent-creator). |
    | `mcpApiKey` | string | Read-only | Signed key identifying this workspace on the shared MCP endpoint. Auto-generated on install. Hand this to the [agent builder](#agent-builder-agent-creator) and treat it as a secret. |

    ### Authentication

    | Auth mode | What you provide | When to use it |
    |-----------|------------------|----------------|
    | **Personal Access Token** (only mode) | `patName` and `patSecret` for a Tableau user, plus `serverUrl` and, off the Default site, `siteContentUrl` | Every Tableau Cloud and Tableau Server setup. There is no per-user OAuth flow and no alternative mode |

    The connector exchanges the PAT for an `X-Tableau-Auth` session token with `POST /api/{apiVersion}/auth/signin` and caches the token for 3 hours, keyed on the PAT name, the server URL and the site, so several PATs or sites stay isolated.

    <Note>
      A Tableau PAT allows a single active session, so a concurrent sign-in elsewhere (a script, another tool, a parallel agent run) revokes the cached token. The connector detects the resulting `401`, forces a fresh sign-in and replays the call once, so occasional revocations are transparent. Persistent `401` responses mean the PAT itself is wrong or expired.
    </Note>

    ### API surfaces reached

    | Surface | Path | Version handling |
    |---|---|---|
    | REST API | `/api/{apiVersion}/...` | Follows the `apiVersion` setting, default `3.21` |

    ## Available instructions

    The app exposes **131 instructions**, one per Tableau operation, callable as `Tableau.<operation>`. Every instruction resolves the credential from the workspace secrets and reuses the cached session token.

    On success, an instruction returns the **Tableau API response body unchanged**: REST 3.x JSON for REST operations, the GraphQL envelope `{ "data": { ... } }` for Metadata operations, and Pulse JSON for Pulse operations. On an API failure it returns `{ success: false, error: { isError: true, content: [...] }, data, status }`, and when the credential cannot be resolved it returns `{ error: "..." }`. Test `success` or `error` before you read the payload.

    ## DSUL examples

    ### List the workbooks of a project

    ```yaml
    - Tableau.listWorkbooks:
        filter: 'projectName:eq:Marketing'
        pageSize: 50
      output: workbooks
    ```

    `filter`, `sort` and `fields` use the Tableau REST filter syntax, and `pageSize` is clamped to `100`.

    ### Trigger an extract refresh and follow the job

    ```yaml
    - Tableau.updateDatasourceNow:
        datasourceId: '{{datasourceId}}'
      output: refreshJob

    - Tableau.getJob:
        jobId: '{{refreshJob.job.id}}'
      output: jobStatus
    ```

    `updateDatasourceNow` returns the Tableau REST response body, whose `job` object identifies the background job it queued.

    ### Find an asset and walk its lineage

    ```yaml
    - Tableau.searchAssets:
        name: 'Quarterly Review'
      output: matches

    - Tableau.getWorkbookLineage:
        workbookLuid: '{{workbookLuid}}'
      output: lineage
    ```

    `searchAssets` matches the **exact** asset name, so pass the name as it appears in Tableau. Read `matches.data.workbooks` and `matches.data.publishedDatasources` to pick the `luid` you pass as `workbookLuid`. For partial matching, write your own filter with `Tableau.metadataQuery`.

    ### Query a published datasource

    ```yaml
    - Tableau.readMetadata:
        datasource:
          datasourceLuid: '{{datasourceLuid}}'
      output: fields

    - Tableau.queryDatasource:
        datasource:
          datasourceLuid: '{{datasourceLuid}}'
        query:
          fields:
            - fieldCaption: 'Region'
            - fieldCaption: 'Sales'
              function: 'SUM'
      output: rows
    ```

    Always call `readMetadata` first: `fieldCaption` values must match the datasource captions exactly.

    ### Create a Pulse subscription

    ```yaml
    - Tableau.createPulseSubscription:
        subscription:
          metric_id: '{{metricId}}'
          user_id: '{{userId}}'
      output: subscription
    ```

    ## Rotate, revoke and remove

    - **Rotate the Personal Access Token:** create a new PAT in Tableau under **My Account Settings > Personal Access Tokens**, update `tableauPatName` and `tableauPatSecret` in the workspace **Secrets**, select **Save**, then revoke the old PAT in Tableau. Calls made with the cached old session token fail with `401` until the new values are saved, then recover automatically.
    - **Revoke access immediately:** revoke the PAT in Tableau. Every workspace and agent using it starts failing with `401` on the next call, including cached sessions once they are replayed.
    - **Cut off one agent:** because the connector has no per-agent allowlist, remove the capability from the agent and rotate the workspace's MCP API Key by reinstalling the app. Rotating the Tableau PAT alone does not stop an agent that still holds a valid key.
    - **Uninstall the connector:** uninstall the Tableau app from the workspace, then clear the four Tableau secrets in **Secrets**, then revoke the PAT in Tableau. Uninstalling alone leaves the secrets in the workspace.

## Error handling

### Errors raised before Tableau is contacted

These are returned by the connector itself, so no Tableau call is made.

| Message | Where | Cause and fix |
|---|---|---|
| `Tableau auth not configured. Required: patName, patSecret, serverUrl.` | App instructions and MCP | One of the three mandatory secrets is empty. Fill them in the workspace **Secrets**. |
| `Tableau signin failed (<status>): <summary> <detail>` | App instructions and MCP | Tableau rejected the sign-in. Re-copy the PAT secret, check `serverUrl` and `siteContentUrl`, and confirm the PAT has not expired. |
| ``Missing required argument `action` for <tool>. Available: ...`` | MCP | The tool call omitted `action`. The message lists the valid actions. |
| ``Unknown action `<action>` for <tool>. Available: ...`` | MCP | The action does not exist on that tool. |
| `Unknown entity: <tool>` | MCP | The tool name is not one of the 20 entity tools. |
| `Missing required path param: <param> (or <camelCaseParam>)` | App instructions and MCP | A required identifier was not supplied and could not be injected from the session, for example `workbookId`. |
| ``getViewByPath requires `viewUrl` `` | App instructions and MCP | Pass `viewUrl` in the form `MyWorkbook/sheets/MySheet`. |
| ``searchAssets requires `name` (exact asset name to match)`` | App instructions and MCP | Pass the exact asset name. |
| ``metadataQuery requires a `query` argument`` | App instructions and MCP | Pass a GraphQL document in `query`. |

### MCP endpoint errors

These are JSON-RPC errors with code `-32001`, returned before any Tableau call:

```text
Missing required header: mcp-api-key
Invalid API key: Invalid key format
Invalid API key: Invalid signature
Invalid API key: Invalid payload
Credentials lookup failed (<status>): <error>
```

The first four mean the request header carrying the workspace's **MCP API Key** is absent or does not verify. Re-copy the value from the app instance configuration. `Credentials lookup failed` means the endpoint reached the installing workspace but could not obtain credentials, usually because the Tableau secrets there are empty or Tableau refused the sign-in.

### Tableau API errors

Tableau failures are normalized into a single message that always names the operation and appends Tableau's own `code`, `summary` and `detail`.

| HTTP code | Message pattern | Typical cause |
|-----------|-----------------|---------------|
| 400 | `Bad request while <operation>` | Invalid filter, malformed body, or a parameter the operation does not accept. |
| 401 | `401 while <operation>` | The session token was rejected or revoked, or the operation is Tableau Server only. The connector retries once with a fresh sign-in before surfacing this. |
| 403 | `Forbidden while <operation>. Check Tableau permissions for the user behind the PAT.` | The PAT owner lacks the required content permission or site role. |
| 404 | `Resource not found while <operation>` | The resource does not exist on this site, or `siteContentUrl` points at the wrong site. |
| 405 | `Method not allowed while <operation>` | The operation is not available on this Tableau release. |
| 409 | `Conflict while <operation>` | Publishing over an existing asset without `overwrite`, a name collision, or a concurrent update. |
| 429 | `Rate limit exceeded while <operation>. Wait and retry.` | Tableau throttled the request. Back off and retry. |
| 500 | `Tableau server error while <operation>` | Transient Tableau failure. Retry, then check Tableau's own status. |

<Note>
  The `401` message names "Connected App credentials". This connector authenticates with a Personal Access Token, so read that wording as "the credentials the connector signed in with".
</Note>

### Common issues

**Every call fails with `401` even after retrying.** The PAT name or secret is wrong, the PAT expired, or it was revoked in Tableau. A Tableau PAT also allows only one active session, so a script or another tool signing in with the same PAT revokes the connector's session. Give the connector its own dedicated PAT.

**A site or schedule action returns an error on Tableau Cloud.** Site administration (`sites` `list`, `create`, `update`, `delete`) and server schedule creation are Tableau Server features. Tableau Cloud rejects them. Check the operation in the Tableau REST API reference before relying on it.

**Reads return nothing although the content exists.** The connector sees only what the PAT owner sees. Grant that Tableau user access to the project or asset, or point the connector at a PAT owned by an account that already has it. `siteContentUrl` pointing at the wrong site produces the same symptom, with `404` on direct lookups.

**`vizqlData` `queryDatasource` returns `403` mentioning API access permission.** A Tableau administrator must grant **API Access** on the published datasource before VizQL Data Service can query it.

**A `getData` reply is cut short.** CSV responses are truncated at 20000 characters on the last complete row, and the reply states how many rows were kept. Narrow the result with `viewFilters`, or run the aggregation through `vizqlData` instead.

**A list looks incomplete.** `pageSize` and `page_size` are clamped to `100`, and arrays are truncated to 100 items. Page through the results with `pageNumber` or `page_token`, using `pagination.totalAvailable` to size the loop.

**An agent claims it will send a chart image or PDF.** Binary responses are not available. Instruct the agent to call the matching `get` action and share the `webpageUrl` instead.
