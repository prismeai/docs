The Google Workspaces app provides read/write access to five [Google Workspace](https://workspace.google.com) APIs (Drive, Docs, Sheets, Gmail and Calendar) through their official REST endpoints. It can be consumed two ways: as a remote MCP server that **Agent Creator** agents call as tools, or as a Builder app whose instructions you call directly from DSUL. The MCP surface groups every operation into **five entity tools** (`drive`, `docs`, `sheets`, `gmail`, `calendar`), each driven by an `action` argument, and also exposes **MCP Resources** that present Google Drive as a browsable, id-addressed tree for knowledge ingestion. The endpoint runs in the **tenant app-instance context**: it resolves the installing workspace's own credentials and gates which agents may call it. Authentication supports four modes:

- **Per-user OAuth2 with a central client** (`oauthCentral`, recommended): one Google OAuth client is registered once by the platform maintainer; every end user signs in with their own Google account. Nothing to register per tenant: each workspace installs the app and its users click **Connect**.
- **Per-user OAuth2 with a tenant client** (`oauth`, the default when no mode is set): enter your own Google OAuth client ID and secret in the connector configuration app. Each user signs in with their own account against your client (authorization code with PKCE).
- **Service account with JWT Bearer** (`jwt`): a Google service-account client email and private key, with optional domain-wide delegation (`saSubject`) to impersonate a user in your Workspace domain. No interactive sign-in.
- **Direct access token** (`accessToken`): a caller-managed Google access token, used as-is with no exchange.

## Prerequisites (Google side)

The Prisme.ai-side prerequisites (workspace role, and the decision to make before installing) are in [Before you begin](/apps-store/marketplace/connectors/install-in-workspace#before-you-begin). On the Google side you need:

- A **Google** account, or a Google Workspace domain when you use a service account with domain-wide delegation.
- The Google APIs you intend to call must be **enabled** in the Google Cloud project: Drive, Docs, Sheets, Gmail and Calendar. A call to a disabled API fails with `403`.
- An OAuth client (modes `oauthCentral` and `oauth`), a service-account key (mode `jwt`) or a pre-minted access token (mode `accessToken`).

The OAuth scopes requested by default in the `oauthCentral` and `oauth` modes are:

```text
https://www.googleapis.com/auth/drive
https://www.googleapis.com/auth/documents
https://www.googleapis.com/auth/spreadsheets
https://www.googleapis.com/auth/gmail.modify
https://www.googleapis.com/auth/calendar
openid
email
```

<Note>
  The connector requests exactly the scopes set in the **Scopes** field of the configuration app. A tenant value overrides the central default; when neither is set, the list above is used. The `jwt` mode falls back to the same list **without** `openid` and `email`, which are meaningless for a service account. Enabling more scopes on the Google OAuth client has no effect until you also add them to the Scopes field, and the Scopes field can never grant a permission the Google client does not expose.
</Note>

## Runtime identity and blast radius

The authentication mode decides which Google identity the provider sees, and therefore which files, mailboxes and calendars a tool call can reach. Choose it before configuring anything; the generic form of this decision is in [Before you begin](/apps-store/marketplace/connectors/install-in-workspace#before-you-begin), and [When to use a central client](/apps-store/marketplace/connectors/central-oauth#when-to-use-a-central-client) covers `oauthCentral` versus `oauth`.

| Mode | Identity Google sees | Permissions come from | Who consents, who revokes | Use it for |
|------|----------------------|-----------------------|---------------------------|------------|
| `oauthCentral` | The invoking Prisme.ai user's own Google account | That user's Google permissions, limited to the granted scopes | The user consents at first use; the user or a Google admin revokes | Interactive Chat and agents acting on behalf of the person talking to them |
| `oauth` | The invoking Prisme.ai user's own Google account, on your own OAuth client | Same as above | Same as above, plus you own the client registration | The same use cases when you must own and audit the Google OAuth client |
| `jwt` | The service account, or the user named by `saSubject` under domain-wide delegation | The service account's own shares, or the impersonated user's permissions | A Google Workspace admin grants domain-wide delegation and can withdraw it | Unattended automations and scheduled runs with no signed-in user |
| `accessToken` | Whichever account the token was minted for | Whatever the token already carries | Whoever minted the token | Short-lived, caller-managed tokens |

<Warning>
  `jwt` and `accessToken` are **shared identities**. Every user of the workspace acts as the same Google principal, Google's audit log attributes every action to that principal rather than to the person who asked for it, and domain-wide delegation lets the service account impersonate any user in the domain. Prefer `oauthCentral` or `oauth` whenever an agent reads user-owned data or performs an attributable write. Reserve the shared modes for background workloads, and grant the service account the narrowest scope list that still works.
</Warning>

In the OAuth modes, each user's access token is cached in their own user scope and refreshed automatically shortly before expiry. The refresh token is additionally deposited as a workspace secret named `gwsRefresh_<usageKey>_<userId>`, so a scheduled run with no signed-in user can replay it for a named `targetUserId`. That secret can never be read back by a browser: only the runtime resolves it.

The same person may hold **several separate connections**, one per usage: `connection:<id>` for a knowledge base's ingestion and `agent:<id>` for a reader consulting an agent, even when both point at the same Google account. Disconnecting one leaves the others intact.

  **Goal:** two one-time tasks: (1) configure the shared **central OAuth client** so every workspace lets its users sign in with their own Google account, and (2) expose Google Workspaces as a reusable **capability** in AI Governance so agent builders can pick it without pasting endpoint URLs.

  Both are standard connector flows. The procedures live on [Central OAuth client](/apps-store/marketplace/connectors/central-oauth) and [Declare a connector capability](/apps-store/marketplace/connectors/declare-capability); this section supplies the Google-specific values.

  ## 1. Configure the connector

  <Steps>
    <Step title="Register the OAuth client at Google">
      In the [Google Cloud Console](https://console.cloud.google.com/apis/credentials), open **APIs & Services > Credentials > Create credentials > OAuth client ID** and choose the *Web application* type. Set the single authorized redirect URI to the core workspace callback:

      ```text
      <api-url>/workspaces/slug:google-workspaces/webhooks/oauthCallback
      ```

      For example, `https://api.studio.prisme.ai/v2/workspaces/slug:google-workspaces/webhooks/oauthCallback` on production. Enable the Drive, Docs, Sheets, Gmail and Calendar APIs in the same project, declare the scopes listed in [Prerequisites (Google side)](#prerequisites-google-side) on the consent screen, then save the **Client ID** and **Client Secret**.

      Only this one redirect URI is needed, whatever the number of tenant workspaces: Google always returns to the core callback, which proxies the authorization code back to the tenant callback packed into the OAuth `state`. See [Callback URLs](/apps-store/marketplace/connectors/central-oauth#callback-urls) for why the core URI and a tenant instance URI are never interchangeable.
    </Step>
    <Step title="Enter the credentials through the configuration app">
      Open the core `google-workspaces` workspace and launch its **Configuration app** at `<studio>/apps/google-workspaces` (for example `https://studio.prisme.ai/apps/google-workspaces`), also linked as `Configuration app` on the installed instance. In the maintainer view, paste the **Client ID**, the **Client Secret** and, optionally, the **Scopes**, then save. The full procedure, including the role check and what a save writes, is in [Configure the central client](/apps-store/marketplace/connectors/central-oauth#configure-the-central-client).

      You must be an **owner**, **editor** or **admin** of the core `google-workspaces` workspace, or a platform superadmin. Any other caller is rejected with `Forbidden — you must be an editor of the core workspace.`

      The profile is stored in the core workspace secret `googleWorkspacesCentralOAuth` and never exposed to tenants or end users: tenant instances read only the public part (client id and scopes) from the core `getOAuthClientPublic` webhook, and every token exchange is proxied through the core `centralTokenExchange` webhook, so the client secret never leaves the core workspace ([How the client secret stays in the core workspace](/apps-store/marketplace/connectors/central-oauth#how-the-client-secret-stays-in-the-core-workspace)). Do not edit Studio's raw Secrets by hand.
    </Step>
    <Step title="Tell workspaces to use the central client">
      Each consuming workspace selects auth mode **`oauthCentral`** in the connector configuration app (no client id or secret to enter on their side). Their users then click **Connect**. Hand the workspace builders [Select the central client in a workspace](/apps-store/marketplace/connectors/central-oauth#select-the-central-client-in-a-workspace).
    </Step>
  </Steps>

  ## 2. Declare the capability in AI Governance

  Generic connectors (broad tool surfaces meant to be shared across many agents, like Google Workspaces) are best exposed as a named **capability** in AI Governance. Agent builders then enable that capability on their agents instead of pasting a raw MCP endpoint. Follow [Publish the connector to the Capabilities catalog](/apps-store/marketplace/connectors/declare-capability#publish-the-connector-to-the-capabilities-catalog) or [Declare the capability manually in AI Governance](/apps-store/marketplace/connectors/declare-capability#declare-the-capability-manually-in-ai-governance), with these values:

  | Field | Value for Google Workspaces |
  |---|---|
  | Capability name | **Google Workspaces** |
  | MCP server URL, shared core instance | `<api-url>/workspaces/slug:google-workspaces/webhooks/mcp` |
  | MCP server URL, tenant instance | `<api-url>/workspaces/slug:<workspace>/webhooks/<app-instance>.mcp` |
  | **Scope** | `context_id,agent_id,user_id` (see [What the Scope means](/apps-store/marketplace/connectors/declare-capability#what-the-scope-means)) |
  | Authorization block | Nothing to author. There is **no OAuth auth-config JSON** to attach in Governance: connect, status and disconnect are handled by the connector's own `oauthConnect`, `oauthStatus` and `oauthDisconnect` webhooks, wired automatically. |

  Smoke-test it: from an agent that has the capability, in a workspace configured for `oauthCentral`, trigger any tool. The user is prompted to connect once through Google sign-in; subsequent calls reuse the stored token and refresh it automatically.

  <Warning>
    Declaring the capability makes the connector **available**; it does not by itself authorize a specific agent (see [Availability is not authorization](/apps-store/marketplace/connectors/declare-capability#availability-is-not-authorization)). This connector follows the **tenant-context model**: which agents may actually call a tenant instance is gated per-workspace by the **authorized-agents allowlist** in the configuration app (see [Workspace builder (DSUL)](#workspace-builder-dsul)). The shared core endpoint behaves differently: because the central OAuth client is configured there, it accepts **every** calling agent and relies on per-user Google sign-in as the real gate, as described in [Agent authorization on the core endpoint](/apps-store/marketplace/connectors/central-oauth#agent-authorization-on-the-core-endpoint).
  </Warning>
</Accordion>

    ## Agent builder

    **Goal:** let an agent you build in Agent Creator read and act on Google Workspace through MCP tools.

    <Note>
      Before an agent can call the connector, a workspace builder must have installed and configured the Google Workspaces app in a workspace (see [Workspace builder (DSUL)](#workspace-builder-dsul)), and, for the central OAuth mode, a platform admin must have provisioned the shared OAuth client (see [Platform admin (Governance)](#platform-admin-governance-one-time-platform-setup)).
    </Note>

    This connector runs in the **tenant app-instance context**. On a tenant instance your agent is authorized two ways at once: it is identified by the `agent_id` that Agent Creator injects through the capability **Scope**, and that agent must appear in the connector's **authorized-agents allowlist** (managed in the configuration app). The Google access token itself is resolved server-side from the configured auth mode; no credential ever travels in a header from the agent. The generic wiring is documented in [Declare a connector capability](/apps-store/marketplace/connectors/declare-capability).

    There are two ways to wire it up. Pick based on how much isolation you need.

    ## Option A: enable the shared capability from the catalog

    The fastest path: a platform admin has already published a **Google Workspaces** capability (see [Declare the capability in AI Governance](#2-declare-the-capability-in-ai-governance)), so you pick it from the catalog.

    <Steps>
      <Step title="Open your agent in Agent Creator">
        Open the agent you want to extend and go to its capabilities.
      </Step>
      <Step title="Add the Google Workspaces capability">
        Browse the capability catalog, select **Google Workspaces**, and enable it. The MCP endpoint URL and the **Scope** (`context_id,agent_id,user_id`) are already wired by the admin; there is nothing to paste, and the shared core instance accepts every agent, so there is no allowlist step on your side ([Agent authorization on the core endpoint](/apps-store/marketplace/connectors/central-oauth#agent-authorization-on-the-core-endpoint)).
      </Step>
      <Step title="Connect a Google account (OAuth modes)">
        On the first tool call, an unconnected user is prompted to sign in; Agent Creator surfaces a `connect_url` pointing at the connector's `oauthConnect` webhook. The `jwt` and `accessToken` modes need no per-user sign-in and report as connected.
      </Step>
    </Steps>

    <Note>
      Convenient, but your agent runs against a **shared, platform-managed instance**: its Google client is owned by someone else and the instance accepts every agent that is granted the capability. Prefer Option B for anything beyond quick experiments.
    </Note>

    ## Option B: run it from your own workspace (recommended)

    For production agents, install the connector in **your own workspace** and point the agent at that workspace's MCP endpoint.

    <Warning>
      **Prefer this mode for security.** Because the MCP runs in your app-instance context, the Google credentials, the per-user OAuth tokens and the authorized-agents allowlist are all **scoped to your workspace**, not shared platform-wide. You decide exactly which agents may call it and which Google account or auth mode backs them, and a misconfiguration elsewhere cannot expose your data. The shared catalog capability (Option A) is a broad surface many agents can reach; your own workspace is an isolated, least-privilege boundary.
    </Warning>

    <Steps>
      <Step title="Install and configure the connector in your workspace">
        Follow [Workspace builder (DSUL)](#workspace-builder-dsul): install **Google Workspaces** in your workspace, open its **Configuration app**, choose the auth mode and connect a Google account.
      </Step>
      <Step title="Allowlist your agent">
        In that workspace's configuration app, open **Authorized agents** and tick your agent, then save, as described in [Authorize the agents that may call the connector](/apps-store/marketplace/connectors/install-in-workspace#authorize-the-agents-that-may-call-the-connector). The **Install capability** button does this and attaches the tool in one action ([Install the capability on one agent](/apps-store/marketplace/connectors/declare-capability#install-the-capability-on-one-agent)). Setting the allowlist to **Allow all agents** stores the `*` wildcard and disables the per-agent gate entirely.
      </Step>
      <Step title="Add the MCP capability to your agent">
        In your agent, add a capability pointing at your workspace's MCP endpoint:

        ```text
        <api-url>/workspaces/slug:<your-workspace>/webhooks/<app-instance>.mcp
        ```

        Set its **Scope** to:

        ```text
        context_id,agent_id,user_id
        ```

        The `agent_id` is what lets the connector identify and authorize your agent; without it, every call is rejected with an explicit "the calling agent could not be identified" message. This **Scope** is separate from the Google OAuth scopes; see [What the Scope means](/apps-store/marketplace/connectors/declare-capability#what-the-scope-means).
      </Step>
      <Step title="Connect a Google account (OAuth modes)">
        On the first tool call, the user is prompted to sign in, or connects beforehand from the configuration app.
      </Step>
    </Steps>

    ## Brief the agent in its system prompt

    Whichever option you pick, wiring the capability is not enough; the agent must know the MCP server exists and when to use it. Copy-pasteable starter:

    ```text
    You have access to the Google Workspaces MCP server (tools: drive, docs, sheets, gmail, calendar). Each tool takes an `action` argument. Use it whenever the user asks about their Google Drive files, Docs, Sheets, Gmail or Calendar: listing, searching, reading, creating or updating. Prefer calling a tool over guessing, and confirm with the user before any destructive action (delete, trash, overwrite, share changes).
    ```

    <Note>
      **Legacy AI Knowledge agents** (no native MCP picker): add the connector under **Advanced > Tools > MCP** and paste the MCP endpoint URL. The agent still has to be allowlisted in the configuration app on a tenant instance, and its identity propagated so the connector can read its `agent_id`. See [Declare the capability manually in AI Governance](/apps-store/marketplace/connectors/declare-capability#declare-the-capability-manually-in-ai-governance).
    </Note>

    <Note>
      **Restricting to read-only (least privilege).** Google Workspaces tools cover both reads and writes (edit Docs and Sheets, modify Gmail, create events). The requested OAuth scopes **are** the grant, so the connector only obtains what the **Scopes** field in the configuration app asks for. To allow only read access, set a read-only scope list, for example:

      ```text
      https://www.googleapis.com/auth/drive.readonly https://www.googleapis.com/auth/documents.readonly https://www.googleapis.com/auth/spreadsheets.readonly https://www.googleapis.com/auth/gmail.readonly https://www.googleapis.com/auth/calendar.readonly openid email
      ```

      With central OAuth (`oauthCentral`) you do not create your own Google client: keep `oauthCentral` and enter the read-only scopes, and your tenant list overrides the platform default. The central client's consent screen must already declare those scopes. Write calls are then rejected by Google with `403`. This is set at the workspace level, so a workspace editor can widen it again; a provider-side restriction is the only hard guarantee. Users who already consented keep their previous grant until they disconnect and reconnect.
    </Note>

    ## Available tools

    Each tool takes an `action` argument selecting the concrete operation, plus the per-action parameters. The manifest served by `tools/list` is derived from the connector's own automations, so it always matches the deployed version.

    | Tool | Description |
    |------|-------------|
    | `drive` | Google Drive files and permissions. Actions: `list`, `get`, `create`, `update`, `delete`, `copy`, `export`, `permissionsList`, `permissionsCreate`, `permissionsDelete`. |
    | `docs` | Google Docs. Actions: `get`, `create`, `batchUpdate`. |
    | `sheets` | Google Sheets. Actions: `get`, `create`, `valuesGet`, `valuesUpdate`, `valuesAppend`, `valuesClear`, `batchUpdate`. |
    | `gmail` | Gmail, always the connected account (`users/me`). Actions: `getProfile`, `messagesList`, `messagesGet`, `messagesSend`, `messagesModify`, `messagesTrash`, `draftsCreate`, `labelsList`, `threadsGet`. |
    | `calendar` | Google Calendar. Actions: `eventsList`, `eventsGet`, `eventsInsert`, `eventsUpdate`, `eventsDelete`, `calendarList`, `freebusy`. |

    Beyond tools, the same endpoint serves **MCP Resources** for Google Drive; see [Google Drive MCP Resources](#google-drive-mcp-resources).

    <Note>
      Each tool's input schema allows **additional properties**, so any query parameter the underlying Google endpoint accepts is forwarded even when it is not listed in the parameter tables below. For example `drive` with `action: list` also accepts `pageSize`, `pageToken`, `orderBy`, `spaces`, `corpora`, `driveId`, `includeItemsFromAllDrives` and `supportsAllDrives`.
    </Note>

    <Note>
      The five tool webhooks refuse direct HTTP calls with `403` and the message `Direct calls are not allowed — use the MCP endpoint.` Always go through the `mcp` endpoint.
    </Note>

    ## Output formats

    Every tool accepts an `outputFormat` argument with two accepted values, `verbose` (the default) and `compact`. Both return the same payload: a `content[]` text block containing a short confirmation line followed by the Google API response rendered as JSON. Treat `outputFormat` as reserved rather than as a way to obtain a `structuredContent` field.

    ## Tool details

    ### drive

    ```json
    {
      "name": "drive",
      "arguments": {
        "action": "list",
        "q": "name contains 'report' and trashed = false",
        "fields": "files(id,name,mimeType,modifiedTime)"
      }
    }
    ```

    | Parameter | Required | Description |
    |-----------|----------|-------------|
    | `action` | Yes | One of `list`, `get`, `create`, `update`, `delete`, `copy`, `export`, `permissionsList`, `permissionsCreate`, `permissionsDelete`. |
    | `fileId` | For get/update/delete/copy/export/permissions* | Drive file id. |
    | `permissionId` | For permissionsDelete | Permission id to revoke. |
    | `q` | No | Search query (list), for example `mimeType='application/vnd.google-apps.folder'`. |
    | `fields` | No | Partial-response fields selector. |
    | `mimeType` | For export | Target MIME type, for example `application/pdf`. |
    | `body` | For create/update/copy/permissionsCreate | File metadata, or `{role,type,emailAddress}` for a permission. |
    | `outputFormat` | No | `verbose` (default) or `compact`. |

    ### docs

    ```json
    {
      "name": "docs",
      "arguments": {
        "action": "batchUpdate",
        "documentId": "1AbcD...",
        "body": { "requests": [{ "insertText": { "location": { "index": 1 }, "text": "Hello" } }] }
      }
    }
    ```

    | Parameter | Required | Description |
    |-----------|----------|-------------|
    | `action` | Yes | One of `get`, `create`, `batchUpdate`. |
    | `documentId` | For get/batchUpdate | Target document id. |
    | `body` | For create/batchUpdate | Create: `{title}`. Batch update: `{requests:[...]}`. |
    | `outputFormat` | No | `verbose` (default) or `compact`. |

    ### sheets

    ```json
    {
      "name": "sheets",
      "arguments": {
        "action": "valuesUpdate",
        "spreadsheetId": "1AbcD...",
        "range": "Sheet1!A1:C2",
        "valueInputOption": "USER_ENTERED",
        "body": { "values": [["Name", "Email", "Score"], ["Ada", "ada@example.com", 99]] }
      }
    }
    ```

    | Parameter | Required | Description |
    |-----------|----------|-------------|
    | `action` | Yes | One of `get`, `create`, `valuesGet`, `valuesUpdate`, `valuesAppend`, `valuesClear`, `batchUpdate`. |
    | `spreadsheetId` | For all but create | Target spreadsheet id. |
    | `range` | For values* | A1 notation, for example `Sheet1!A1:C10`. |
    | `valueInputOption` | For valuesUpdate/valuesAppend | `RAW` or `USER_ENTERED`. |
    | `majorDimension` | No | `ROWS` or `COLUMNS`. |
    | `body` | For create/values*/batchUpdate | Spreadsheet resource, `{values:[[...]]}`, or `{requests:[...]}`. |
    | `outputFormat` | No | `verbose` (default) or `compact`. |

    ### gmail

    ```json
    {
      "name": "gmail",
      "arguments": {
        "action": "messagesSend",
        "body": { "to": "ada@example.com", "subject": "Hello", "text": "Plain body, no base64." }
      }
    }
    ```

    | Parameter | Required | Description |
    |-----------|----------|-------------|
    | `action` | Yes | One of `getProfile`, `messagesList`, `messagesGet`, `messagesSend`, `messagesModify`, `messagesTrash`, `draftsCreate`, `labelsList`, `threadsGet`. |
    | `id` | For messagesGet/Modify/Trash, threadsGet | Message or thread id. |
    | `q` | No | Gmail search query (messagesList), for example `from:ada is:unread`. |
    | `labelIds` | No | Restrict messagesList to these label ids. |
    | `maxResults` | No | Page size for messagesList. |
    | `format` | No | `minimal`, `full`, `raw` or `metadata` for messagesGet and threadsGet. |
    | `body` | For messagesSend/draftsCreate/messagesModify | Send or draft: `{to,subject,text\|html,cc,bcc,replyTo,inReplyTo,threadId}` as plain strings (the server builds the MIME message and base64-encodes it; never encode it yourself). Modify: `{addLabelIds,removeLabelIds}`. |
    | `outputFormat` | No | `verbose` (default) or `compact`. |

    <Note>
      Resolve "me" or "my email" with a single `getProfile` call; it returns the connected account's `emailAddress` and mailbox counters. Never list messages to discover the connected address.
    </Note>

    ### calendar

    ```json
    {
      "name": "calendar",
      "arguments": {
        "action": "eventsList",
        "calendarId": "primary",
        "timeMin": "2026-07-01T00:00:00Z",
        "timeMax": "2026-07-08T00:00:00Z",
        "singleEvents": true,
        "orderBy": "startTime"
      }
    }
    ```

    | Parameter | Required | Description |
    |-----------|----------|-------------|
    | `action` | Yes | One of `eventsList`, `eventsGet`, `eventsInsert`, `eventsUpdate`, `eventsDelete`, `calendarList`, `freebusy`. |
    | `calendarId` | No | Calendar id, defaults to `primary`. |
    | `eventId` | For eventsGet/Update/Delete | Target event id. |
    | `timeMin`, `timeMax` | No | RFC 3339 bounds for eventsList. |
    | `q` | No | Free-text event search (eventsList). |
    | `singleEvents` | No | Boolean; expands recurring events into instances. |
    | `orderBy` | No | `startTime` or `updated`. |
    | `sendUpdates` | No | `all`, `externalOnly` or `none`; controls guest notifications. |
    | `body` | For eventsInsert/Update, freebusy | Event resource `{summary,start,end,attendees}`, or free/busy request `{timeMin,timeMax,items}`. |
    | `outputFormat` | No | `verbose` (default) or `compact`. |

    ## Workspace builder

    **Goal:** install the connector in a workspace, configure authentication and the agent allowlist, and call Google operations from your automations.

    ## Installation

    Google Workspaces follows the standard App + MCP installation flow: search for **Google Workspaces** in **Apps**, install it, then open the **Configuration app** link the install populates. The step-by-step procedure is in [Install a connector in your workspace](/apps-store/marketplace/connectors/install-in-workspace#install-the-app); come back here for the Google-specific values.

    What the install provisions for this connector ([what installing provisions](/apps-store/marketplace/connectors/install-in-workspace#what-installing-provisions)):

    | Provisioned | Value for Google Workspaces |
    |---|---|
    | Authentication secret | `googleWorkspacesAuth` (auth mode and credentials) |
    | Agent allowlist secret | `googleWorkspacesAuthorizedAgents` (comma-separated agent ids, or `*`) |
    | Configuration app link | `configAppUrl` on the app instance |
    | OAuth callback URL | `oauthCallbackUrl` on the app instance, `<api-url>/workspaces/slug:<your-workspace>/webhooks/<app-instance>.oauthCallback`. Register it at Google only in the `oauth` mode; `oauthCentral` uses the core callback instead. |

    The operation is idempotent, so reinstalling never overwrites credentials you already entered.

    ## Configuration

    | Field | Description |
    |-------|-------------|
    | **Configuration app** (`configAppUrl`) | Auto-populated on install; open this link to configure authentication (mode and credentials), connect a Google account in the OAuth modes, and manage the authorized-agents allowlist. Read-only on the instance. |
    | **Knowledge-sync** (`knowledgeSync`) | Delegated MCP Resource access settings. `trustedCallers` lists the workspace ids allowed to invoke the delegated access check with a server-verified `targetUserId`. Non-secret, stored directly in the configuration value. |

    The configuration app drives authentication; the app instance itself has no per-field credential form. From it you pick one of:

    | Auth mode | What you provide | Identity Google sees | Best for |
    |-----------|------------------|----------------------|----------|
    | `oauthCentral` | Nothing; users click **Connect** | Each invoking user's own Google account | Workspaces on a platform where the admin set up the [central client](/apps-store/marketplace/connectors/central-oauth#select-the-central-client-in-a-workspace) |
    | `oauth` | Your own Google **Client ID and Secret** (redirect URI `<api-url>/workspaces/slug:<your-workspace>/webhooks/<app-instance>.oauthCallback`) | Each invoking user's own Google account | You manage your own Google OAuth client |
    | `jwt` | A service-account **client email** and **private key**, plus an optional `saSubject` for domain-wide delegation | The service account, or the impersonated `saSubject` user | Server-to-server work with no interactive sign-in |
    | `accessToken` | A pre-minted Google **access token** | Whichever account minted the token | Short-lived, caller-managed tokens |

    <Note>
      Credentials are provisioned into the workspace's Secrets by the install flow and resolved server-side; they are never sent to the browser or to an agent. Enter them only through the configuration app, never by hand in Studio **Secrets** ([Configure credentials in the configuration app](/apps-store/marketplace/connectors/install-in-workspace#configure-credentials-in-the-configuration-app)). The **Authorized agents** allowlist gates which Agent Creator agents may call this instance's MCP endpoint **and its Drive Resources**; manage it as described in [Authorize the agents that may call the connector](/apps-store/marketplace/connectors/install-in-workspace#authorize-the-agents-that-may-call-the-connector), and hand the endpoint to the agent builder as in [Copy the MCP endpoint](/apps-store/marketplace/connectors/install-in-workspace#copy-the-mcp-endpoint).
    </Note>

    ## Available instructions

    Every instruction resolves credentials from the workspace configuration. Operations are grouped by Google product; the MCP server exposes the same operations behind the five entity tools (see [Available tools](#available-tools)). Call them with the app slug prefix, for example `GoogleWorkspaces.driveList:`.

    ### Drive

    | Instruction | Description | Returns |
    |-------------|-------------|---------|
    | `driveList` | List or search files and folders. Filter with `q` (Drive query syntax), paginate with `pageToken`, shape the payload with a `fields` selector. | `{ files: [{ id, name, mimeType, modifiedTime, … }], nextPageToken }` |
    | `driveGet` | Fetch one file's metadata by `fileId`. | A File resource `{ id, name, mimeType, parents, webViewLink, … }`, fields-selectable. |
    | `driveCreate` | Create a file or folder from a `body` metadata object (`{ name, mimeType, parents }`). | The created File resource `{ id, name, mimeType, … }`. |
    | `driveUpdate` | Update file metadata or move it across folders with `addParents` / `removeParents`. | The updated File resource. |
    | `driveDelete` | Permanently delete a file by `fileId`. | Empty (HTTP 204). |
    | `driveCopy` | Duplicate a file by `fileId`; override metadata via `body`. | The new (copied) File resource `{ id, name, … }`. |
    | `driveExport` | Export a Google-native file (Doc, Sheet, Slide) to a `mimeType`, for example `application/pdf`. | The exported file content in the requested format. |
    | `drivePermissionsList` | List the sharing permissions on a file. | `{ permissions: [{ id, type, role, emailAddress }] }` |
    | `drivePermissionsCreate` | Share a file: `body` = `{ role, type, emailAddress }`; optional `sendNotificationEmail`, `emailMessage`, `transferOwnership`. | The created Permission `{ id, type, role }`. |
    | `drivePermissionsDelete` | Revoke a permission by `permissionId`. | Empty (HTTP 204). |

    ### Docs

    | Instruction | Description | Returns |
    |-------------|-------------|---------|
    | `docsGet` | Read a document's full content tree by `documentId`. | A Document resource `{ documentId, title, body, … }`. |
    | `docsCreate` | Create a document; `body` = `{ title }`. | The created Document `{ documentId, title }`. |
    | `docsBatchUpdate` | Apply an ordered list of edit requests (`body.requests[]`: insert text, format, tables) to a document. | `{ documentId, replies: [...] }` |

    | Instruction | Description | Returns |
    |-------------|-------------|---------|
    | `sheetsGet` | Read spreadsheet structure by `spreadsheetId`; add `ranges` and `includeGridData` for cell data. | A Spreadsheet resource `{ spreadsheetId, properties, sheets: [...], spreadsheetUrl }`. |
    | `sheetsCreate` | Create a spreadsheet from a `body` resource, for example `{ properties: { title } }`. | The created Spreadsheet `{ spreadsheetId, spreadsheetUrl, sheets }`. |
    | `sheetsValuesGet` | Read cell values in A1 `range`; `majorDimension`, `valueRenderOption` and `dateTimeRenderOption` shape the result. | `{ range, majorDimension, values: [[ … ]] }` |
    | `sheetsValuesUpdate` | Overwrite cells in `range`; `body` = `{ values: [[ … ]] }`, with `valueInputOption` `RAW` or `USER_ENTERED`. | `{ spreadsheetId, updatedRange, updatedRows, updatedColumns, updatedCells }` |

    | Instruction | Description | Returns |
    |-------------|-------------|---------|
    | `gmailGetProfile` | Resolve the connected account ("me" or "my email") in one call. | `{ emailAddress, messagesTotal, threadsTotal, historyId }` |

    | Instruction | Description | Returns |
    |-------------|-------------|---------|
    | `calendarEventsList` | List events on `calendarId` (default `primary`) between `timeMin` and `timeMax`; `singleEvents` expands recurrences. | `{ items: [ Event ], nextPageToken, nextSyncToken }` |
    | `calendarEventsGet` | Fetch one event by `eventId`. | An Event resource `{ id, summary, start, end, attendees, … }`. |
    | `calendarEventsInsert` | Create an event; `body` = `{ summary, start, end, attendees }`. `sendUpdates` notifies guests. | The created Event `{ id, htmlLink, start, end, … }`. |
    | `calendarEventsUpdate` | Update an event by `eventId` with a new `body`. | The updated Event resource. |
    | `calendarEventsDelete` | Delete an event by `eventId`. | Empty (HTTP 204). |
    | `calendarCalendarList` | List the calendars the account can access. | `{ items: [{ id, summary, accessRole, primary, … }] }` |
    | `calendarFreebusy` | Query busy intervals; `body` = `{ timeMin, timeMax, items: [{ id }] }`. | `{ timeMin, timeMax, calendars: { <calendarId>: { busy: [{ start, end }] } } }` |

    <Note>
      `Returns` shows the shape of the operation output, which is the underlying Google API resource. `calendarId` defaults to `primary` when omitted. Instructions do not raise on failure: they return `{ error }`, where `error` carries a `content[]` text explanation, so test `{{result.error}}` before using the payload.
    </Note>

    <Note>
      **Running without a signed-in user.** In the OAuth modes a scheduled automation has no user session, so it must name whose stored refresh token to replay. Pass `targetUserId` on the instructions that accept it: `gmailGetProfile`, `gmailMessagesGet`, `gmailMessagesSend`, `gmailDraftsCreate`, `gmailHistoryList`, `gmailWatch`, `calendarEventsList` and `calendarEventsInsert`. The value must come from your own trusted configuration, never from inbound request data or from an agent argument, and that user must have connected once beforehand. Every other instruction resolves the current user only.
    </Note>

    **List the 10 most recently modified Drive files:**

    ```yaml
    - GoogleWorkspaces.driveList:
        q: "trashed = false"
        orderBy: modifiedTime desc
        pageSize: 10
        fields: "files(id,name,mimeType,modifiedTime)"
      output: files
    ```

    ```yaml
    - GoogleWorkspaces.sheetsCreate:
        body:
          properties:
            title: '{{reportName}}'
      output: sheet
    - GoogleWorkspaces.sheetsValuesUpdate:
        spreadsheetId: '{{sheet.spreadsheetId}}'

        valueInputOption: USER_ENTERED
        body:
          values:
            - ["Date", "Customer", "Amount"]
    ```

    - GoogleWorkspaces.gmailGetProfile: {}
      output: profile

          subject: 'Daily summary'
          text: '{{summaryText}}'
    ```

          end:
            dateTime: '2026-07-01T11:00:00+02:00'
          attendees:
            - email: '{{attendeeEmail}}'
      output: event
    ```

## Google Drive MCP Resources

Besides the five tools, the same MCP endpoint exposes Google Drive as **MCP Resources**, so a knowledge base can browse and ingest Drive content without an agent having to script `drive` calls. The connector advertises the `resources` capability during `initialize`, and serves three URI templates:

| URI template | What it addresses |
|---|---|
| `gdrive://profile/knowledge` | The public machine-readable connector profile: hierarchy, page-size and inline-size limits, revision fields, and the supported authentication modes. Served without authentication so a catalog can test compatibility on an unconfigured connector. |
| `gdrive://drive/{driveId}` | My Drive (`driveId` is `my-drive`) or a shared drive, addressed by its stable id. |
| `gdrive://drive/{driveId}/item/{fileId}` | A Drive file or folder, addressed by its stable, globally unique file id. |

Behavior and limits, all fixed by the connector:

- **Listing.** `resources/list` with no parent URI enumerates My Drive first, then every shared drive the caller can see. Pages are bounded: the page size defaults to `50` and is capped at `200`, and the cursor is Drive's own `nextPageToken`. Drive delta listing is not supported.
- **Reading.** Google-native documents (Docs, Sheets, Slides) are exported to `text/plain` and inlined. Other files are downloaded with the caller's token and inlined as a data URL, because Drive offers no anonymous pre-signed download URL. The inline ceiling is 4194304 bytes (4 MiB) and can be lowered or raised with the `connector_inline_max_bytes` configuration value. A file above the ceiling, or one that cannot be downloaded, comes back as metadata only, marked `unfetchable` with a reason.
- **Revision.** A file's revision is its Drive `version`, falling back to `modifiedTime`.
- **Authorization.** `resources/list` and `resources/read` apply the same agent allowlist as `tools/call`, then resolve Google auth for the caller. An unauthorized agent gets JSON-RPC error `-32003`.

### Delegated access checks for knowledge bases

A knowledge base indexed from Drive must still refuse a document to a reader who cannot open it in Drive. The connector answers that question through a delegated access check: a batch of canonical resource URIs is probed with the reader's own token, and only files that answer successfully are returned as allowed. The check **fails closed**: a malformed URI, a Drive denial or a provider outage all leave the document out.

This check is not a general-purpose tool. It is restricted to the workspace ids listed in `knowledgeSync.trustedCallers`, because an unguarded `targetUserId` would let any MCP caller ask about another user's Drive. Any other caller receives `The delegated Resource access action is restricted to the trusted Knowledge Sync caller.`

Resolving another user's token reads a workspace-scoped secret, which the runtime grants only to a run that has no user of its own, such as a scheduled synchronization. A check triggered from an interactive conversation therefore reports `delegation_unavailable` rather than asking the reader to reconnect an account that is already connected.

## Verify the setup

Run these checks in order; each one is independent of the previous actor's word. They are the Google-specific form of the generic checks in [Verify the installation](/apps-store/marketplace/connectors/install-in-workspace#verify-the-installation), [Verify the central client](/apps-store/marketplace/connectors/central-oauth#verify-the-central-client) and [Verify the capability](/apps-store/marketplace/connectors/declare-capability#verify-the-capability).

<Steps>
  <Step title="Platform admin: confirm the central client is stored">
    Open the maintainer view of the configuration app on the core `google-workspaces` workspace. It reports whether the central client is configured and prefills the client id and scopes, never the secret. If it reports that you are not allowed, your role on the core workspace is not owner, editor or admin.
  </Step>
  <Step title="Workspace builder: test the credentials">
    In the configuration app of your own instance, run the connection test. It resolves the configured auth mode and performs an authenticated `GET https://www.googleapis.com/drive/v3/about` call. A failure returns the exact reason, for example a missing connection, a rejected service-account key or an insufficient scope list.
  </Step>
  <Step title="Agent builder: confirm the tools are advertised">
    In the agent, open the capability and check that the five tools `drive`, `docs`, `sheets`, `gmail` and `calendar` are listed. An empty list means the capability points at a URL that is not the connector's `mcp` webhook.
  </Step>
  <Step title="End user: run one safe read">
    Ask the agent to list your Google Drive files, or to give your Gmail address. The first call in an OAuth mode opens the Google consent screen; after consent you are returned to the configuration app callback view with a connected status, and the interrupted request completes. Verify that the returned files are the ones your own Google account can see, not someone else's.
  </Step>
  <Step title="Security: check a negative case">
    Point the agent at a Drive file it should not reach, or remove the agent from the allowlist and call any tool again. The call must fail with an explicit authorization message rather than returning data.
  </Step>
</Steps>

## Disconnect, revoke and remove

The generic lifecycle is documented in [Rotate credentials and uninstall](/apps-store/marketplace/connectors/install-in-workspace#rotate-credentials-and-uninstall), [Rotate and revoke the central client](/apps-store/marketplace/connectors/central-oauth#rotate-and-revoke-the-central-client) and [Remove or update a capability](/apps-store/marketplace/connectors/declare-capability#remove-or-update-a-capability). What follows is what those actions do for Google Workspaces specifically.

| Action | Who performs it | How | Effect |
|---|---|---|---|
| Disconnect one Google account | End user | The disconnect action in the configuration app, or the agent's disconnect flow in Chat | Revokes the token at `https://oauth2.googleapis.com/revoke`, deletes the stored user-scope token and the workspace refresh-token secret for that usage, and leaves the other usages connected. Without a usage key, every connection this user holds is dropped. |
| Force re-consent after a scope change | Workspace builder | Change the **Scopes** field, then ask users to disconnect and reconnect | Existing users keep their previous grant until they reconnect, so a widened or narrowed scope list only takes effect on the next consent. |
| Rotate the central client secret | Platform admin | Re-enter the client id and secret in the maintainer view of the configuration app | New token exchanges use the new secret immediately. Rotating at Google without updating the connector makes every refresh fail with `invalid_grant`, which drops the stored refresh tokens and prompts users to reconnect. |
| Rotate a tenant client secret or a service-account key | Workspace builder | Re-enter the credentials in the configuration app | Applies to the whole workspace on the next call. |
| Offboard a departing user | Organization administrator | Have the user disconnect, or revoke the grant from the Google account's third-party access page | The stored refresh token stops working; the connector deletes it on the first rejected refresh, so scheduled runs that named that user fail with an explicit reconnection message instead of silently continuing. |
| Stop an agent from calling the connector | Workspace builder | Remove the agent from **Authorized agents** in the configuration app and save | The next tool call is refused with the authorization message, on both tools and Drive Resources. |
| Remove the connector | Workspace builder | Uninstall the app from the workspace | The MCP endpoint and the OAuth webhooks disappear. Delete the `googleWorkspacesAuth` and `googleWorkspacesAuthorizedAgents` secrets, and any remaining `gwsRefresh_*` secrets, to purge stored credentials. |

## Error handling

Google API failures are normalized before they reach the agent or the automation. The message always names the operation that failed and appends the detail Google returned.

| HTTP code | Message shape | Meaning |
|-----------|---------------|---------|
| `400` | `Bad request while <operation>: <detail>` | Invalid parameters or malformed body, for example a bad A1 range or invalid file metadata. |
| `401` | `Authentication failed while <operation>. Check Google credentials / OAuth connection.` | The Google access token is missing, expired or revoked. In an OAuth mode the user must reconnect. |
| `403` | `Forbidden while <operation>. Check the user's Google permissions / OAuth scopes.` | Insufficient OAuth scope, the target API is not enabled in the Cloud project, or the account lacks access to the resource. |
| `404` | `Resource not found while <operation>.` | The file, document, spreadsheet, message or event id does not exist or is not visible to the account. |
| `429` | `Rate limit / org limit exceeded while <operation>. Wait and retry.` | Google quota exceeded; back off and retry. |
| `500` | `Google server error while <operation>.` | Transient Google failure; retry shortly, no reconnection needed. |
| Any other | `Error <status> while <operation>: <detail>` | Includes `503`. Treat 5xx as transient. |

When no recognized error field is present, the detail reads `(no further detail)`: the raw provider response is deliberately not echoed, because it can carry credential fragments.

### Common issues

Problems that are not Google-specific (an empty **Configuration app** field, a stale catalog entry, a maintainer view refusing to render) are covered in the shared troubleshooting sections of [Install a connector in your workspace](/apps-store/marketplace/connectors/install-in-workspace#troubleshooting), [Central OAuth client](/apps-store/marketplace/connectors/central-oauth#troubleshooting) and [Declare a connector capability](/apps-store/marketplace/connectors/declare-capability#troubleshooting).

**`This agent is not authorized to use this connector.`**: The calling agent is not in the allowlist of that tenant instance. Open the configuration app, go to **Authorized agents**, tick this agent (the message quotes its id) or enable **Allow all agents**, and save. See [Authorize the agents that may call the connector](/apps-store/marketplace/connectors/install-in-workspace#authorize-the-agents-that-may-call-the-connector).

**`The calling agent could not be identified, so it cannot be authorized.`**: The MCP capability **Scope** does not declare `agent_id`, so Agent Creator never injects the agent identity. Set the Scope to `context_id,agent_id,user_id` on the capability, then allow the agent in the configuration app. See [What the Scope means](/apps-store/marketplace/connectors/declare-capability#what-the-scope-means).

**Unknown tool**: The message reads `Unknown tool` followed by the name the agent used. The name does not match one of the five entity tools. Refresh the capability so the agent picks up the current `tools/list`.

**Missing or unknown action**: The messages read `Missing required argument` or `Unknown action`, each naming the tool. The agent called an entity tool without a valid `action`. Both messages list the available actions; add the action to the agent's instructions if it keeps guessing.

**`Google is not connected for this user.`**: No per-user OAuth token exists. Open the configuration app in an OAuth mode and select **Connect**, or use the agent's connect flow.

**`No stored Google token for this user.`**: A non-interactive run named a `targetUserId` who never connected. That user must connect once from the configuration app as a workspace editor.

**`Google token refresh failed …`**: The stored refresh token was revoked or expired, so Google rejected it permanently. The connector drops the stored token automatically and reports the connection as disconnected; the user must reconnect.

**`Google token endpoint temporarily unavailable …`**: Google's token endpoint returned a 5xx. This is transient: retry shortly. Do not ask users to reconnect, it fixes nothing.

**`Google OAuth is not configured.`**: Neither a tenant OAuth client nor the central platform client is available. Set the OAuth client id and secret in the configuration app, or ask the platform maintainer to provision the [central OAuth client](/apps-store/marketplace/connectors/central-oauth#configure-the-central-client) from the core workspace.

**`Google is not authenticated.`**: No auth mode resolved at all, usually an instance where the configuration app was never opened. Choose the auth mode and enter its credentials in the configuration app.

**`Google service-account token exchange failed …`**: The `jwt` mode could not obtain a token. Check the service-account key, the scopes enabled for it, and, for domain-wide delegation, that `saSubject` is authorized for those scopes in the Google Workspace admin console.

**`Direct calls are not allowed — use the MCP endpoint.`**: Something called a tool webhook directly. Route the call through the connector's `mcp` endpoint.

**Gmail send fails or arrives garbled**: Pass `to`, `subject` and `text` or `html` as plain strings in `body`. The server builds and base64-encodes the MIME message itself; never encode the content yourself.

**A Drive Resource returns metadata but no content**: The file exceeded the 4 MiB inline ceiling, or the download failed. The response is marked `unfetchable` with the reason; lower the file size, export the document, or fetch it through the `drive` tool instead.
