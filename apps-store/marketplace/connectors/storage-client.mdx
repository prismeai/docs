<Warning>
  **This connector is deprecated. Use [Knowledges](/apps-store/marketplace/connectors/knowledges) instead.**

  Knowledges covers the same knowledge-base surface with the aligned naming (`knowledges`, `documents`, `webSources` instead of `vectorStores`, `vectorStoreFiles` and `crawling`) and the same credential-free authentication. Install it for any new agent or automation, and migrate existing ones when convenient.

  This page is kept for the workspaces that still run the Storage connector. It stays functional, and remains the only connector exposing the administrative surface: per-knowledge-base API keys, RBAC access bindings, agent skills and admin diagnostics, none of which Knowledges covers. The `files` registry operations documented below are deprecated on the backend and will be removed with the legacy API.
</Warning>

The Prisme.ai Storage app is a **client connector to the Prisme.ai Storage backend** (the `slug:storage` workspace of the current environment). It can be consumed two ways: as a remote MCP server that **Agent Creator** agents call as tools, or as a Builder app whose instructions you call directly from DSUL automations. Eight entity tools group 40 actions over knowledge bases, their documents, web crawl sources, RBAC bindings, per-knowledge-base API keys, agent skills, admin diagnostics and the deprecated files registry.

The backend calls the same objects **knowledge bases** and **documents**, while the connector keeps its historical tool and argument names (`vectorStores`, `vectorStoreFiles`, `vector_store_id`). Identifiers are unchanged: a `vector_store_id` is a knowledge base id.

Unlike third-party SaaS connectors, **this connector requires no credential to paste**. It runs in the installing workspace's app-instance context and forwards the caller's Prisme.ai identity to the Storage backend over the platform's cross-workspace forward authentication: every call inherits the permissions of whoever triggered it, and the Storage backend applies its own RBAC bindings on top.

## Prerequisites

- A Prisme.ai workspace with the **Prisme.ai Storage** app installed. **No API key, OAuth client or third-party account is required**: the connector calls the platform's own Storage backend.
- The Storage backend of the current environment. There is no base URL or service address to configure in App mode: the connector resolves it from the environment as `{apiUrl}/workspaces/slug:storage/webhooks`.
- A role on each knowledge base you intend to reach. The Storage backend resolves the caller's effective role from the knowledge base ownership and from its access bindings:

  | Role | Granted permissions | Typical actions |
  |------|---------------------|-----------------|
  | `reader` | `read` | List and get knowledge bases and documents, run `vectorStores` action `search`, read chunks. |
  | `editor` | `read`, `write` | Everything a reader can do, plus add, update, delete and reindex documents, and trigger recrawls. |
  | `admin` | `read`, `write`, `share` | Everything an editor can do, plus list and manage access bindings and API keys. |
  | `owner` | `read`, `write`, `share`, `delete` | Everything an admin can do, plus delete the knowledge base. Held by its creator; it is not a grantable binding role. |

- A platform `superadmin` or `root` role for `admin` action `healthCheck`, which is reserved to platform superadmins.
- For URL ingestion (`vectorStoreFiles` action `add` with `source_url`), a URL the Storage backend can fetch: a publicly reachable URL, or a Prisme.ai share URL such as the ones injected through the `attachment_urls` capability scope.
- Optionally, a **credential override** if the connector must act under a fixed identity instead of the caller's. Accepted credentials are an organization API key (`iak_…`), a user access token (`at:…`) or a session JWT.

<Note>
  Knowledge bases reached through this connector are the same objects you see in the **Knowledges** product UI and through the [Knowledges connector](/apps-store/marketplace/connectors/knowledges). This connector does not create a separate store.
</Note>

<Accordion title="Platform admin (Governance): one-time platform setup" icon="shield-halved">
  <Note>
    **No platform-level credential to provision.** This connector carries no third-party API key. Each workspace installs the app, and the caller's Prisme.ai identity is forwarded to the Storage backend automatically. The only secret in the package, **App HMAC Secret** (`appSecret`), is set once on the central connector workspace by the connector maintainer and is used to sign per-tenant MCP API keys. It is never provisioned per tenant.
  </Note>

  The one optional platform task is to publish Storage as a reusable **capability** in AI Governance, so agent builders can enable it from the capability picker instead of pasting an MCP endpoint URL by hand.

  <Note>
    The generic capability concepts are documented once in [Declare a connector capability](/apps-store/marketplace/connectors/declare-capability), in particular why [availability is not authorization](/apps-store/marketplace/connectors/declare-capability#availability-is-not-authorization) and [what the Scope means](/apps-store/marketplace/connectors/declare-capability#what-the-scope-means). The procedure stays written out below because this deprecated connector diverges from the standard flow: it ships no configuration app, so there is no **Install capability** action and no **Authorized agents** allowlist to tick, and it attaches no OAuth authorization block. Follow the steps below rather than the shared ones.
  </Note>

  ## Declare the capability in AI Governance

  <Steps>
    <Step title="Open AI Governance > Capabilities">
      Create (or edit) a **Prisme.ai Storage** capability.
    </Step>
    <Step title="Point it at the MCP endpoint">
      Set the capability's MCP server URL to the connector's shared MCP endpoint, which is the value of the **MCP Endpoint** field of any installed app instance:

      ```text
      https://api.<your-instance>/v2/workspaces/slug:storage-client/webhooks/mcp
      ```

      Add the app instance's **MCP API Key** as a request header, so the endpoint can resolve which tenant workspace is calling:

      ```text
      mcp-api-key: <MCP API Key of the app instance>
      ```
    </Step>
    <Step title="Set the capability scope">
      Set the capability's **Scope** to:

      ```text
      context_id,agent_id,user_id,attachment_urls
      ```

      `attachment_urls` is read by the connector: when the caller does not pass an explicit `url` or `source_url`, `vectorStoreFiles` action `add` ingests the first attachment URL injected by Agent Creator, instead of a URL the model may have invented from a filename.
    </Step>
    <Step title="Save the capability">
      Save it. It then appears in the capability picker for agent builders in your organization. Access to the catalog follows your organization's existing roles; there is no per-capability role grant for this connector.
    </Step>
    <Step title="Smoke-test the capability">
      From an agent that has the capability, ask it to list knowledge bases. The call runs as the agent's user, and the Storage backend returns only the knowledge bases that user owns or holds a binding on.
    </Step>
  </Steps>

  <Warning>
    Declaring the capability makes the connector **available**; it does not authorize a specific agent against any data. Authorization is enforced by the Storage backend's own RBAC bindings, evaluated against the forwarded caller identity. There is no OAuth authentication configuration to attach here, since the connector forwards the caller's Prisme.ai identity rather than a per-user OAuth token. Connectors that do authenticate per user attach a [central OAuth client](/apps-store/marketplace/connectors/central-oauth#when-to-use-a-central-client) instead; this one never does.
  </Warning>

  <Warning>
    The MCP endpoint is shared by every tenant and is disambiguated by the signed **MCP API Key**, which encodes the tenant workspace id. Treat that key as a tenant credential: anyone holding it can call the endpoint on behalf of that workspace's app instance. Store it in the capability configuration only, never in an agent prompt or a chat message.
  </Warning>
</Accordion>

    ## Agent builder

    **Goal:** let an agent you build in Agent Creator manage knowledge bases, documents and RAG through the Storage MCP tools.

    <Note>
      Before an agent can call the connector, a workspace builder must have installed the Prisme.ai Storage app in a workspace (see [Workspace builder (DSUL)](#workspace-builder-dsul)), or a platform admin must have published the capability in AI Governance (see [Platform admin (Governance)](#platform-admin-governance-one-time-platform-setup)).
    </Note>

    No credential is pasted into the agent. The connector forwards the calling user's Prisme.ai identity to the Storage backend, which applies that user's permissions, so an agent can only reach the knowledge bases its user is allowed to reach.

    <Steps>
      <Step title="Get the endpoint and the key">
        Install the Prisme.ai Storage app in your workspace (see [Workspace builder (DSUL)](#workspace-builder-dsul)) and copy the **MCP Endpoint** and **MCP API Key** values from the app instance configuration. If a [platform admin](#platform-admin-governance-one-time-platform-setup) already published the capability, skip to the capability picker instead.
      </Step>
      <Step title="Add the capability to your agent">
        In your agent, add a capability pointing at the **MCP Endpoint** URL with the **MCP API Key** sent as a request header, or pick the published **Prisme.ai Storage** capability from the catalog. Set its **Scope** to:

        ```text
        context_id,agent_id,user_id,attachment_urls
        ```

        `attachment_urls` lets `vectorStoreFiles` action `add` ingest a file the user dropped in the conversation without the model guessing a URL for it.
      </Step>
      <Step title="Brief the agent in its system prompt">
        Wiring the capability is not enough: the agent also needs to know the tools exist and when to reach for them. Add a paragraph to the agent's system prompt, then save the agent. Copy-pasteable starter:

        ```text
        You have access to the Prisme.ai Storage MCP server. Use `vectorStores` to list, create, inspect and search knowledge bases, `vectorStoreFiles` to attach documents, follow their indexing status and resolve download links, `crawling` to follow and retrigger web crawls, and `access`, `apiKeys` and `skills` for administration. Every tool takes an `action` argument. Calls run with the user's identity, so the user only reaches knowledge bases they have access to. Always confirm with the user before a destructive action: vectorStores delete, vectorStoreFiles delete, access revoke, apiKeys revoke or rotate, skills delete.
        ```

        Refine the trigger keywords (knowledge base names, business domains, typical user phrasings) so the agent reliably picks up the right intent in your context.
      </Step>
      <Step title="Test it">
        Ask the agent to list your knowledge bases. It should return only the ones the signed-in user owns or holds a binding on.
      </Step>
    </Steps>

    <Note>
      **Restricting to read-only (least privilege).** The connector never adds permissions: it acts as the caller, so what an agent may do is exactly what its user may do on each knowledge base. To make an agent read-only, grant the calling users the `reader` role on the target knowledge bases rather than `editor` or `admin`. Write calls then fail with `403` while search keeps working. The Storage backend enforces this on every call, so it is a hard boundary rather than a declarative hint.
    </Note>

    <Note>
      **Legacy AI Knowledge agents** (no native MCP picker): add the connector under **Advanced > Tools > MCP**, paste the **MCP Endpoint** URL and add the **MCP API Key** header. The caller identity is still forwarded so the Storage backend can resolve the caller's RBAC.
    </Note>

    ## Available Tools

    The MCP server exposes 8 entity-level tools, each with an `action` argument that selects the operation. Every tool also accepts an `outputFormat` argument (`verbose` by default, `structured` or `both`) and an `accessToken` argument that overrides the workspace default credential for that call.

    ### `vectorStores`

    Knowledge bases (RAG indexes).

    | Action | Description |
    |--------|-------------|
    | `list` | List knowledge bases. `scope` accepts `owned`, `shared`, `all`, `agents` (comma-separated; legacy `own` is translated to `owned`). Filters: `name` substring, `status`, `agent_id`, `limit`, `page`. |
    | `create` | Create a knowledge base. `name` is required. `embedding` is an object `{model, dimensions?}`, `chunking_strategy` an object. `provider` selects the vector index backend, not the embedding provider. `expires_after` is accepted on create only. |
    | `get` | Get a knowledge base by `vector_store_id`. Pass `include: "processing"` to embed the crawl and indexing status object. |
    | `update` | Update `name`, `description`, `chunking_strategy`, `parser`, `file_parsing`. `expires_after` is not updatable and is ignored. |
    | `delete` | Delete a knowledge base. Answers `202` and cascades documents, chunks, web sources and bindings asynchronously. |
    | `search` | Semantic search. `query` is required. Optional `limit`, `min_score`, `filter` AST, `scope`, `conversation_id`. |
    | `reindexAll` | Deprecated. Still calls the legacy bulk reindex route, which the knowledge-bases surface does not replace. Use `vectorStoreFiles` action `list` plus action `reindex` per document. |
    | `getAdminUrl` | Format a deep link to the knowledge base admin page. Pure formatter, no HTTP call. Returns `{ url, vector_store_id }`. |

    ### `vectorStoreFiles`

    Documents of a knowledge base. Every per-document action takes `document_id`, the `id` returned by `list` and `add`. `file_id` is a deprecated alias carrying the same document id, not a files-registry id.

    | Action | Description |
    |--------|-------------|
    | `list` | List documents. Filters: `status`, `source_type` (`uploaded_file`, `web_page`, `external`), `origin` (`user`, `web_crawl`), `web_source_id`, `scope`, `conversation_id`, `search` substring, `tags` and `metadata` exact-match objects, `limit`, `page`. |
    | `add` | Attach a source: `native_file_id` (a platform file id) and/or `source_url`. Optional `fetch_url`, `filename`, `mime_type`, `bytes`, `chunking_strategy`, `expires_at`, `tags` object, `metadata`. Adds are upserts on the source key. |
    | `get` | Get a document with its indexing state. |
    | `update` | Edit `tags`, `metadata`, `expires_at`, `filename`. Source fields are immutable. |
    | `delete` | Delete the document and its chunks. |
    | `getChunks` | List the chunks produced for a document; `limit`, `page`. A legacy `offset` is converted to the nearest page. |
    | `reindex` | Re-index an existing document, optionally overriding `parser` or `chunking_strategy`, with a `reason` recorded for observability. Returns `404` if the document does not exist; it never upserts. |
    | `getSourceUrl` | Resolve a browser-usable URL: a short-lived download URL for uploaded files, the original `source_url` otherwise. Replaces `files` action `download`. |

    ### `crawling`

    Web crawl status, per-seed metrics and recrawl triggers.

    | Action | Description |
    |--------|-------------|
    | `getStatus` | Return the knowledge base with its `processing` object (crawl and indexing counters). |
    | `recrawl` | Fan out over the per-seed recrawl routes: every seed when `websites` is empty, otherwise the seeds whose URL matches an entry exactly. Per-seed results are returned, including the `409` crawl-already-running guard. |
    | `recrawlSeed` | Trigger a single web source recrawl by `seed_id`. |
    | `getSourceCounts` | List the knowledge base web sources with per-seed metrics, plus a knowledge-base-level `summary` (`total_web_pages`, `unattributed_count`). |

    ### `access`

    RBAC access bindings on a knowledge base.

    | Action | Description |
    |--------|-------------|
    | `list` | List bindings; `limit`, `page`. Requires the `admin` or `owner` role. |
    | `grant` | Grant a role to a principal. Idempotent on `(knowledge base, principal_type, principal_id)`: re-granting updates the role instead of duplicating the binding. |
    | `update` | Change an existing binding's role. |
    | `revoke` | Remove a binding. |

    ### `apiKeys`

    Per-knowledge-base API keys.

    | Action | Description |
    |--------|-------------|
    | `list` | List keys; `limit`, `page`. Metadata only, never a secret. |
    | `create` | Mint a key. An expiry is required. The raw `secret` is returned once. |
    | `revoke` | Revoke a key by `key_id`. Returns `{ deleted: true }`. |
    | `rotate` | Rotate a key by `key_id`. Returns the key with a new one-time `secret`. |

    ### `skills`

    Reusable agent skills (instructions plus tools).

    | Action | Description |
    |--------|-------------|
    | `list` | List skills; optional `search`, `pageSize`, `page`. |
    | `create` | Create a skill; `name`, `display_name`, `description`, `instructions`, `tools`. |
    | `get` | Get a skill by `skill_id`. |
    | `update` | Update `name`, `display_name`, `description`, `instructions`. `tools` is not updatable. |
    | `delete` | Delete a skill by `skill_id`. |

    ### `admin`

    Aggregate statistics and end-to-end diagnostics.

    | Action | Description |
    |--------|-------------|
    | `getStats` | Aggregate counters. `scope` accepts `own`, `shared`, `all` (comma-separated, default `own,shared`). |
    | `healthCheck` | End-to-end smoke test of the Storage backend. Reserved to platform superadmins. Returns `{ ok, steps: [{ name, ok, error?, response? }] }`. |

    ### `files`

    <Warning>
      Every `files` action is deprecated. The legacy storage files registry has no equivalent on the knowledge-bases surface and will be removed with the legacy API. Migrate now: upload through the native platform files API, then call `vectorStoreFiles` action `add` with `native_file_id`; browse documents with `vectorStoreFiles` action `list`; resolve a download URL with `vectorStoreFiles` action `getSourceUrl`.
    </Warning>

    | Action | Description |
    |--------|-------------|
    | `list` | Deprecated. List registry files; `conversation_id`, `purpose`, `status`, `limit`, `page`. |
    | `upload` | Deprecated. Upload from a `url` or raw `bytes`; `purpose`, `file_name`, `mime_type`. |
    | `get` | Deprecated. Get registry file metadata by `file_id`. |
    | `delete` | Deprecated. Delete a registry file by `file_id`. |
    | `download` | Deprecated. Download content by `file_id`; `redirect`, `share_token`. Replaced by `vectorStoreFiles` action `getSourceUrl`. |

    ## Output Formats

    Every tool accepts an `outputFormat` argument that controls the MCP response shape:

    - **`verbose`** (default): a human-readable text summary of the operation, with the payload rendered as JSON inside it. No `structuredContent`.
    - **`structured`**: the raw payload as JSON, both as text and in `structuredContent`.
    - **`both`**: the human-readable text, plus the raw payload in `structuredContent`.

    ## Tool Details

    ### `vectorStores` (action: `create`)

    ```json
    {
      "name": "vectorStores",
      "arguments": {
        "action": "create",
        "name": "Customer support knowledge base",
        "description": "Searchable knowledge base for the support team",
        "embedding": {
          "model": "text-embedding-3-large",
          "dimensions": 3072
        },
        "chunking_strategy": { "type": "auto" }
      }
    }
    ```

    | Parameter | Required | Description |
    |-----------|----------|-------------|
    | `action` | Yes | Must be `create`. |
    | `name` | Yes | Display name of the knowledge base. |
    | `description` | No | Free-text description. |
    | `embedding` | No | Object `{ model, dimensions? }`. Never pass a string. Defaults to the workspace embedding settings. |
    | `dimensions` | No | Shorthand for `embedding.dimensions`. |
    | `chunking_strategy` | No | Object `{type: "auto"}` (default) or `{type: "static", max_chunk_size_tokens, chunk_overlap_tokens}`. Never pass a string. |
    | `parser` | No | Parsing backend override for the knowledge base. |
    | `file_parsing` | No | Per-modality parsing model overrides: `{ image, audio, document }`. |
    | `provider` | No | Vector index backend: `elasticsearch`, `opensearch` or `mock`. Not the embedding provider. Omit for the workspace default. |
    | `expires_after` | No | Expiration configuration, for example `{anchor: "last_active_at", days: 7}`. Accepted on create only. |

    ### `vectorStores` (action: `search`)

    ```json
    {
      "name": "vectorStores",
      "arguments": {
        "action": "search",
        "vector_store_id": "<knowledge base id>",
        "query": "How do I reset my password?",
        "limit": 5,
        "min_score": 0.3,
        "filter": { "op": "eq", "field": "tags.year", "value": "2026" }
      }
    }
    ```

    | Parameter | Required | Description |
    |-----------|----------|-------------|
    | `action` | Yes | Must be `search`. |
    | `vector_store_id` | Yes | Knowledge base to search. |
    | `query` | Yes | Natural-language query. The tool schema documents a 2048 character maximum. |
    | `limit` | No | Number of hits, from `1` to `100`, `10` by default. |
    | `min_score` | No | Score threshold below which hits are dropped, `0` by default. |
    | `filter` | No | Structured filter AST over `tags.*` fields: a leaf `{ op, field, value }` with `op` in `eq`, `ne`, `in`, `nin`, `gt`, `gte`, `lt`, `lte`, composed with `{ and: [...] }`, `{ or: [...] }`, `{ not: {...} }`. |
    | `scope` | No | Search scope. Use `conversation` together with `conversation_id` to restrict the search to one conversation. |
    | `conversation_id` | No | Required when `scope` is `conversation`. |

    <Warning>
      Raw Elasticsearch filter syntax is rejected with `400`. Only the structured AST is accepted, and only `tags.*` fields are filterable. `max_num_results` and `filters` are still accepted as deprecated aliases of `limit` and `filter`; `rewrite_query` and `ranking_options` are accepted and ignored, so use `min_score` for the score threshold.
    </Warning>

    <Note>
      Search is rate limited to 100 calls per 60 seconds per user by the Storage backend.
    </Note>

    ### `vectorStoreFiles` (action: `add`)

    ```json
    {
      "name": "vectorStoreFiles",
      "arguments": {
        "action": "add",
        "vector_store_id": "<knowledge base id>",
        "native_file_id": "<platform file id>",
        "filename": "onboarding-handbook.pdf",
        "tags": { "topic": "onboarding", "year": "2026" },
        "metadata": { "owner": "support-team" }
      }
    }
    ```

    | Parameter | Required | Description |
    |-----------|----------|-------------|
    | `action` | Yes | Must be `add`. |
    | `vector_store_id` | Yes | Target knowledge base. |
    | `native_file_id` | No* | Native platform file id to ingest. Legacy alias: `file_id`. |
    | `source_url` | No* | URL the Storage backend fetches and ingests. Legacy alias: `url`. |
    | `source_type` | No | `uploaded_file`, `web_page` or `external`. Inferred from the source when omitted. |
    | `fetch_url` | No | Fetch override for external sources. |
    | `filename` | No | Display name of the document. Legacy alias: `file_name`. |
    | `mime_type` | No | Content type hint for the ingested URL, for example `text/html`. |
    | `bytes` | No | Declared size of the source. |
    | `chunking_strategy` | No | Per-document chunking override. |
    | `expires_at` | No | Document expiration as unix seconds. |
    | `tags` | No | Key/value **object**, for example `{"connector": "sharepoint"}`. Used later as search filters. |
    | `metadata` | No | Free-form key/value object. |

    <Note>
      \* At least one of `native_file_id` or `source_url` is required. Adds are **upserts** on the source key: re-adding the same source returns the existing document and reschedules indexing rather than creating a duplicate. `force_recrawl` and `headers` are accepted and ignored.
    </Note>

    ### `access` (action: `grant`)

    ```json
    {
      "name": "access",
      "arguments": {
        "action": "grant",
        "vector_store_id": "<knowledge base id>",
        "principal_type": "group",
        "principal_id": "<group id>",
        "role": "editor"
      }
    }
    ```

    | Parameter | Required | Description |
    |-----------|----------|-------------|
    | `action` | Yes | Must be `grant`. |
    | `vector_store_id` | Yes | Target knowledge base. |
    | `principal_type` | Yes | `user`, `group`, `org` or `agent`. |
    | `principal_id` | Yes | The user id, group id or organization slug. |
    | `role` | Yes | `reader`, `editor` or `admin`. |

    <Note>
      `owner` is not a grantable role: it belongs to the knowledge base creator. `org` sharing only works with the knowledge base's own organization, and `agent` principals are reserved to trusted workspaces and platform administrators. A `user` principal must be an active member of the organization, and a `group` principal must exist in it.
    </Note>

    ### `apiKeys` (action: `create`)

    ```json
    {
      "name": "apiKeys",
      "arguments": {
        "action": "create",
        "vector_store_id": "<knowledge base id>",
        "name": "integration-test-suite",
        "slug": "qa-tests",
        "permissions": ["vector_stores:read"],
        "expires_at": 1798761599
      }
    }
    ```

    | Parameter | Required | Description |
    |-----------|----------|-------------|
    | `action` | Yes | Must be `create`. |
    | `vector_store_id` | Yes | Target knowledge base. |
    | `name` | No | Human-readable key name. |
    | `slug` | No | Stable identifier. Generated when omitted. |
    | `permissions` | No | Resource-shaped allowlist values, for example `vector_stores:read` or `files:read`. Falls back to the platform default when omitted. |
    | `expires_at` | Yes* | Expiry as unix seconds. |
    | `expiresAt` | Yes* | Expiry as an ISO 8601 string. Legacy form. |

    <Warning>
      \* An expiry is required: without `expires_at` or `expiresAt` the call fails with `400` and `expires_at is required (unix seconds; ISO expiresAt also accepted)`. Permissions must be resource-shaped: values are prefixed with `storage:` server-side, so a bare `read` becomes `storage:read` and is rejected. When the platform has no default permission list configured, omitting `permissions` fails with `At least one permission is required (no api_key_default_permissions configured)`.
    </Warning>

    <Warning>
      The plaintext key `secret` is returned only once, by `create` and by `rotate`. Store it in a secret manager immediately; the platform keeps only a hash and cannot show it again.
    </Warning>

  <Tab title="Workspace builder (DSUL)">
    ## Workspace builder

    **Goal:** install the connector in a workspace and call Storage operations from your automations.

    ## Installation

    1. Go to **Apps** in your workspace
    2. Search for **Prisme.ai Storage** and install it
    3. Open the app instance configuration and check that both read-only fields are populated

    On install, the connector requests a signed MCP API key from the central connector workspace and writes it, together with the MCP endpoint, into the app instance configuration. There is no credential to enter.

    <Note>
      Those three steps are the whole installation. This deprecated connector does **not** follow the [standard connector installation flow](/apps-store/marketplace/connectors/install-in-workspace): it ships no configuration app, has no credential to save, no [authorized-agents allowlist](/apps-store/marketplace/connectors/install-in-workspace#authorize-the-agents-that-may-call-the-connector) and no per-instance MCP endpoint, since every tenant shares `slug:storage-client` and is told apart by the signed **MCP API Key**. Only the [workspace role required to install an app](/apps-store/marketplace/connectors/install-in-workspace#before-you-begin) carries over.
    </Note>

    ## Configuration

    | Field | Description |
    |-------|-------------|
    | **MCP Endpoint** | Read-only, populated on install. URL of the MCP endpoint used by agents. |
    | **MCP API Key** | Read-only, generated on install. Identifies this app instance's workspace to the shared MCP endpoint. Send it as a request header from the agent capability. |

    <Note>
      If **MCP API Key** is empty after installing, the key request failed. Reconfigure or reinstall the app instance to retrigger it: the connector regenerates the key on both the install and the configure events, and skips regeneration when a key is already present.
    </Note>

    App-mode instructions do not use the MCP endpoint or its key: they call the Storage backend of the current environment directly. Pick one of the two authentication modes:

    | Auth mode | What you provide | Best for |
    |-----------|------------------|----------|
    | **Caller identity** (default) | Nothing. The caller's user and workspace identity is forwarded automatically on cross-workspace calls. | Agents and automations that should reach exactly what their user reaches. Permissions are enforced per call by the Storage backend. |
    | **Credential override** | An `accessToken` argument on the instruction: an organization API key (`iak_…`), a user access token (`at:…`) or a session JWT. | Unattended flows (crons, anonymous webhooks) that have no user identity to forward, or that must always act under one fixed identity. |

    <Note>
      The connector routes the credential by kind: an `iak_…` organization key travels on the `x-prismeai-api-key` header, every other credential on `Authorization: Bearer`. Sending an organization key on `Authorization: Bearer` fails before it reaches the Storage backend.
    </Note>

    <Warning>
      A credential override is a **shared identity**. Every caller of that automation acts as the backing account, and the Storage audit trail attributes their reads and writes to it rather than to the individual user. Scope the backing account to the minimum set of knowledge bases, and prefer caller identity whenever a real user is present.
    </Warning>

    <Note>
      The Storage backend rejects anonymous calls. A cron or an anonymous webhook has no user identity to forward, so it needs a credential override.
    </Note>

    ## Available Instructions

    Instruction names keep the historical `vector store` vocabulary, while the backend resources they address are knowledge bases and documents. Every instruction accepts an optional `accessToken` argument.

    ### Knowledge bases

    | Instruction | Description |
    |-------------|-------------|
    | `listVectorStores` | List knowledge bases; `scope` (`owned`, `shared`, `all`, `agents`), `name`, `status`, `agent_id`, `limit`, `page`. Legacy `pageSize`, `scope: own` and `include_agents` are translated. |
    | `createVectorStore` | Create one; `name` plus optional `description`, `provider`, `embedding`, `dimensions`, `chunking_strategy`, `parser`, `file_parsing`, `expires_after`, `agent_id`. |
    | `getVectorStore` | Get one by `vector_store_id`; `include: "processing"` embeds the processing status. |
    | `updateVectorStore` | Update `name`, `description`, `chunking_strategy`, `parser`, `file_parsing`. `expires_after` is ignored. |
    | `deleteVectorStore` | Delete one. Answers `202` and cascades asynchronously. |
    | `searchVectorStore` | Semantic search; `query` plus optional `limit`, `min_score`, `filter`, `scope`, `conversation_id`, `agent_id`. |
    | `reindexAllFiles` | Deprecated legacy bulk reindex. Use `listVectorStoreFiles` plus `reindexFile`. |
    | `getVectorStoreAdminUrl` | Format the admin deep link. No HTTP call. Returns `{ url, vector_store_id }` directly, not the standard envelope. |

    ### Documents

    | Instruction | Description |
    |-------------|-------------|
    | `listVectorStoreFiles` | List documents; filters `status`, `source_type`, `origin`, `web_source_id`, `scope`, `conversation_id`, `search`, `tags`, `metadata`, `limit`, `page`, `agent_id`. |
    | `addFileToVectorStore` | Attach `native_file_id` and/or `source_url`; optional `source_type`, `fetch_url`, `filename`, `mime_type`, `bytes`, `chunking_strategy`, `expires_at`, `tags` object, `metadata`, `agent_id`. Upsert on the source key. |
    | `getVectorStoreFile` | Get a document by `vector_store_id` and `document_id`. |
    | `updateVectorStoreFile` | Update `tags`, `metadata`, `expires_at`, `filename`. |
    | `deleteVectorStoreFile` | Delete a document and its chunks. |
    | `getFileChunks` | List a document's chunks; `limit`, `page`. Legacy `offset` is converted to the nearest page. |
    | `reindexFile` | Re-index a document; optional `parser`, `chunking_strategy`, `reason`. `404` when the document does not exist. |
    | `getVectorStoreFileSourceUrl` | Resolve a browser-usable source URL for a document. |

    ### Web crawling

    | Instruction | Description |
    |-------------|-------------|
    | `getCrawlStatus` | Return the knowledge base with its `processing` counters. |
    | `getWebSourceCounts` | List the web sources with per-seed metrics plus a knowledge-base-level `summary`; `limit`, `page`. |
    | `recrawlWebSources` | Fan out a recrawl over matching seeds; optional `websites` exact-match list, empty for all seeds. |

    ### Access bindings

    | Instruction | Description |
    |-------------|-------------|
    | `listVectorStoreAccess` | List bindings; `limit`, `page`. Requires `admin` or `owner`. |
    | `grantVectorStoreAccess` | Grant `role` (`reader`, `editor`, `admin`) to `principal_type` (`user`, `group`, `org`, `agent`) and `principal_id`. |
    | `updateVectorStoreAccess` | Change an existing binding's `role`. |
    | `revokeVectorStoreAccess` | Remove a binding by `principal_type` and `principal_id`. |

    ### API keys

    | Instruction | Description |
    |-------------|-------------|
    | `listAPIKeys` | List keys; `limit`, `page`. Metadata only. |
    | `createAPIKey` | Mint a key; `name`, `slug`, `permissions`, and `expires_at` or `expiresAt`. Returns the one-time `secret`. |
    | `revokeAPIKey` | Revoke by `key_id`. Returns `{ deleted: true }`. |
    | `rotateAPIKey` | Rotate by `key_id`. Returns the key with a new one-time `secret`. |

    ### Skills

    | Instruction | Description |
    |-------------|-------------|
    | `listSkills` | List skills; `search`, `pageSize`, `page`. |
    | `createSkill` | Create; `name`, `display_name`, `description`, `instructions`, `tools`. |
    | `getSkill` | Get by `skill_id`. |
    | `updateSkill` | Update `name`, `display_name`, `description`, `instructions`. `tools` is not updatable. |
    | `deleteSkill` | Delete by `skill_id`. |

    ### Admin and deprecated files registry

    | Instruction | Description |
    |-------------|-------------|
    | `getStorageStats` | Aggregate counters; `scope` (`own`, `shared`, `all`, default `own,shared`). |
    | `healthCheck` | End-to-end backend probe. Platform superadmins only. |
    | `listFiles`, `uploadFile`, `getFile`, `deleteFile`, `downloadFileContent` | Deprecated legacy files registry. Migrate to the native platform files API plus the document instructions. |

    <Note>
      **Return shape.** Except for `getVectorStoreAdminUrl`, instructions return a normalized envelope, not the raw API object: `{ operation, itemType, structuredData, jsonData, location: "storage", identifier }`, with `items` and `hint` added for list operations. Read the payload from `structuredData` (or `items`).
    </Note>

    <Note>
      Instructions never throw on an API failure: they return `{ error: { isError: true, content: [{ type: "text", text: "…" }] } }`. Test `{{result.error}}` in your automation before consuming the payload.
    </Note>

    ## DSUL Examples

    ### Attach a platform file to a knowledge base

    ```yaml
    - Prisme.ai Storage.addFileToVectorStore:
        vector_store_id: '{{config.knowledgeBaseId}}'
        native_file_id: '{{uploadedFileId}}'
        filename: 'q2-results.pdf'
        tags:
          report: 'quarterly'
          year: '2026'
        output: added
    ```

    ### Run a semantic search with a tag filter

    ```yaml
    - Prisme.ai Storage.searchVectorStore:
        vector_store_id: '{{config.knowledgeBaseId}}'
        query: '{{body.question}}'
        limit: 8
        min_score: 0.3
        filter:
          op: 'eq'
          field: 'tags.year'
          value: '2026'
        output: hits
    ```

    ### Create a knowledge base and share it with a team

    ```yaml
    - Prisme.ai Storage.createVectorStore:
        name: 'Customer support knowledge base'
        description: 'Searchable knowledge base for the support team'
        embedding:
          model: 'text-embedding-3-large'
          dimensions: 3072
        chunking_strategy:
          type: 'auto'
        output: store
    - Prisme.ai Storage.grantVectorStoreAccess:
        vector_store_id: '{{store.structuredData.id}}'
        principal_type: 'group'
        principal_id: '{{supportTeamGroupId}}'
        role: 'editor'
        output: binding
    ```

    ### Trigger a recrawl of selected web sources

    ```yaml
    - Prisme.ai Storage.recrawlWebSources:
        vector_store_id: '{{config.knowledgeBaseId}}'
        websites:
          - 'https://docs.example.com/'
        output: recrawl
    ```

    The fan-out returns `{ vector_store_id, seeds_total, seeds_triggered, results }`, where each entry of `results` carries `seed_id`, `url` and `status` (`triggered` or `error`), so a seed already crawling reports its `409` without failing the whole call.

    ### Mint a scoped, expiring API key for an external client

    ```yaml
    - Prisme.ai Storage.createAPIKey:
        vector_store_id: '{{config.knowledgeBaseId}}'
        name: 'integration-test-suite'
        slug: 'qa-tests'
        permissions:
          - 'vector_stores:read'
        expires_at: 1798761599
        output: created
    ```

    Read the one-time secret from `{{created.structuredData.secret}}` and store it in a workspace secret straight away. It is never returned again.

## Verify the connection

Run these checks after installing the app or after changing an authentication mode.

<Steps>
  <Step title="Check the app instance configuration">
    Open the app instance configuration. Both **MCP Endpoint** and **MCP API Key** must be populated. An empty key means the install-time key request failed; reconfigure the app instance to retrigger it.
  </Step>
  <Step title="Confirm App mode from a Builder automation">
    Call `Prisme.ai Storage.listVectorStores` with `limit: 1` and inspect the output. An envelope with `operation: "list"`, `itemType: "knowledge base"` and an `items` array confirms the instruction path. An `error` object means authentication or permissions failed.
  </Step>
  <Step title="Confirm MCP mode from the agent">
    Ask the published agent to list your knowledge bases. It should return only the ones the signed-in user owns or holds a binding on. An authentication error instead means the capability is not sending the **MCP API Key** header.
  </Step>
  <Step title="Check the negative case">
    Ask the agent about a knowledge base the signed-in user holds no binding on. The call must fail rather than return content. This confirms that the Storage backend, not the connector, is enforcing permissions.
  </Step>
  <Step title="Check the administrative surface">
    On a knowledge base you own, call `access` action `list`. It returns the bindings, including the owner binding. A `403` with `Listing access bindings requires the admin or owner role` confirms that the role check is applied.
  </Step>
</Steps>

## Rotation, revocation and removal

| Task | How |
|------|-----|
| Rotate a per-knowledge-base API key | Call `apiKeys` action `rotate` with the `key_id`, store the returned one-time `secret`, and update the client that uses it. |
| Revoke a per-knowledge-base API key | Call `apiKeys` action `revoke` with the `key_id`. The response is `{ deleted: true }`. |
| Revoke one principal's access | Call `access` action `revoke` with the `principal_type` and `principal_id`. The next call from that principal fails with `403`. |
| Downgrade instead of revoking | Call `access` action `update` with `role: "reader"`. Write calls then fail while search keeps working. |
| Rotate a credential override | Mint a new organization API key or access token, update the automation's `accessToken` source, then revoke the old credential where it was issued. |
| Return to caller identity | Remove the `accessToken` argument from the instruction. The connector falls back to forwarding the caller's identity. |
| Offboard a user | Nothing to do on the connector in caller-identity mode: disabling the user's platform account removes their access on the next call. Also revoke any binding granted to them directly, and rotate any credential override backed by their account. |
| Remove the connector | Uninstall the app instance from **Apps**. Its **MCP Endpoint** and **MCP API Key** go with it, and agents pointing at the endpoint with the old key stop resolving. |
| Migrate off this connector | Install [Knowledges](/apps-store/marketplace/connectors/knowledges) and repoint agents and automations at it. Keep this connector installed only while you still need API keys, access bindings, skills or diagnostics. |

<Warning>
  Uninstalling the connector does **not** delete any knowledge base. Knowledge bases, documents and chunks live in the Storage backend and survive the uninstall. To remove the data, delete the knowledge bases themselves (`vectorStores` action `delete`, or the Knowledges product UI) before uninstalling.
</Warning>

## Error Handling

The Storage backend uses standard HTTP status codes. The connector normalizes them into a single text message that names the failing operation.

| HTTP status | Connector message | Typical cause |
|-------------|-------------------|----------------|
| `400` | `Bad request while <operation>: <detail>` | Missing required argument, invalid `principal_type` or `role`, raw Elasticsearch filter syntax, `tags` sent as an array instead of an object, missing API key expiry. |
| `401` | `Authentication failed while <operation>. Detail: <detail>` | No caller identity was forwarded and no `accessToken` was supplied, or the supplied credential was rejected. |
| `403` | `Forbidden while <operation>. Detail: <detail>` | The caller's role on the knowledge base is too low, or the action is reserved (agent principals, platform superadmin probes). |
| `404` | `Not found while <operation>. Detail: <detail>` | Unknown knowledge base, document, binding, key or skill. `reindex` on a document that does not exist. |
| `409` | `Conflict while <operation> (e.g. a crawl is already running on this knowledge base). Detail: <detail>` | A recrawl was requested while a crawl is already running. |
| `429` | `Rate limit exceeded while <operation>. Detail: <detail>` | Too many calls in a short window. Search is capped at 100 calls per 60 seconds per user. |
| `502` | `Upstream error while <operation> (crawler or vector index unavailable). Detail: <detail>` | The crawler or the vector index is unreachable. |
| Other | `Error <status> while <operation>: <detail>` | Any other backend failure, including `500`. Retry with exponential backoff. |

### Common Issues

**Missing required header** (JSON-RPC error `-32001`), reported as:

```text
Missing required header: mcp-api-key
```

The agent capability is calling the MCP endpoint without the app instance's **MCP API Key** header. Add it to the capability configuration.

**`Invalid API key: Invalid signature`** or **`Invalid API key: Invalid key format`** (JSON-RPC error `-32001`): the key does not match the endpoint's signing secret, usually because it was copied from an app instance in another environment. Copy the **MCP API Key** from the app instance in the environment you are calling.

**`Credentials lookup failed (<status>)`** (JSON-RPC error `-32001`): the endpoint could not reach the tenant app instance that the key points at. The app instance was probably uninstalled or renamed. Reinstall it and copy the fresh key.

**Missing action argument**, reported as:

```text
Missing required argument `action` for <tool>. Available: <sorted action list>
```

The tool was called without an `action`. The message lists the available actions for that tool.

**Unknown action or unknown tool**, reported as:

```text
Unknown action `<action>` for <tool>. Available: <sorted action list>
Unknown entity: <tool>
```

The action or tool name does not exist. The eight tool names are `files`, `vectorStores`, `vectorStoreFiles`, `crawling`, `access`, `apiKeys`, `skills` and `admin`.

**`Missing path parameter: vector_store_id`**: a knowledge-base-scoped action was called without `vector_store_id`. Ask the agent to list knowledge bases first, then reuse the returned `id`.

**`Authentication failed`, from a cron or an anonymous webhook**: scheduled runs and anonymous webhooks carry no user identity to forward. Pass an `accessToken` credential override on the instruction.

**`Forbidden` on a knowledge base you can see**: listing a knowledge base does not imply write access. Adding documents needs `editor`, managing bindings and keys needs `admin`, deleting the knowledge base needs `owner`. Ask the owner to grant the right binding with `access` action `grant`.

**An empty list when listing knowledge bases**: the default scope is `owned,shared`. Add `agents` to include agent-owned knowledge bases, or `all` for the organization-wide listing, which is reserved to privileged callers.

**A filter matches nothing**: only `tags.*` fields are filterable, and tags must have been written as a key/value **object** at ingestion time (`{"topic": "onboarding"}`, not `["onboarding"]`).

**A search finds nothing while documents are listed**: check each document's `status` with `vectorStoreFiles` action `get`. Documents still queued or in progress are not searchable yet.

**Re-adding a source creates no new document**: this is intended. `vectorStoreFiles` action `add` is an upsert on the source key: the same `source_url` or `native_file_id` returns the existing document and reschedules indexing.

**`filename` was ignored when ingesting a URL, or `force_recrawl` had no effect**: `force_recrawl` and `headers` are accepted and ignored. For full filename control, upload the file through the native platform files API and pass `native_file_id` with `filename`.

**A document id is rejected as a file id**: document actions address documents by `document_id`. The `file_id` alias carries the same document id, never an id from the deprecated files registry.
