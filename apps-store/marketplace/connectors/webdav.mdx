The WebDAV app provides read/write access to any [WebDAV](https://datatracker.ietf.org/doc/html/rfc4918)-compatible file server: Nextcloud, ownCloud, a generic Apache `mod_dav` instance, or any vendor-specific WebDAV endpoint. It can be consumed three ways: as a remote MCP server that **Agent Creator** agents call as tools, as a Builder app whose instructions you call directly from DSUL, and as a Knowledge connector that syncs files into a knowledge base. The MCP surface is a single entity tool, `files`, driven by an `action` argument. Authentication is a **shared service credential held by the installing workspace**: an HTTP Basic username and password, or a Bearer token. There is no OAuth and no per-user sign-in.

## Operating model and runtime identity

Read this before configuring anything: it determines what the WebDAV server sees and how much a single misconfiguration can expose.

- **Single shared service credential.** The connector holds one WebDAV credential per app instance, stored in the installing workspace. Every agent, every automation and every knowledge sync reaches the server as that one account. WebDAV has no portable per-user access-control mechanism, so the connector cannot narrow results per end user.
- **Tenant app-instance context.** The MCP endpoint belongs to the workspace that installed the app, and resolves that workspace's own configuration. There is no central credential and no platform-wide OAuth client.
- **Provider-side attribution.** The WebDAV server logs the configured account for every operation, not the individual Prisme.ai user. Platform-side attribution stays in the Prisme.ai activity feed.
- **Perimeter, not identity.** The optional **Allowed path** is the only scope restriction the connector enforces. Combine it with a WebDAV account that is itself least-privileged.

<Warning>
  Because the credential is shared, its blast radius is everything that account can reach on the WebDAV server. Provision a dedicated service account, grant it the smallest possible share, and set an **Allowed path** whenever the account can see more than you intend to expose.
</Warning>

Two authentication modes are available, and they are not interchangeable. Choose from what your provider issues:

| Mode | Config value of `type` | What you provide | Choose it when |
|---|---|---|---|
| Basic authentication | `basic` | A username plus a password or app password | Nextcloud, ownCloud and generic `mod_dav` servers that accept HTTP Basic |
| Bearer token | `token` | A Bearer token issued by the provider | Your provider issues API tokens instead of passwords |

## Prerequisites

- A reachable **WebDAV server** with a stable base URL. The base URL is the folder the account lands in, not the server root. Examples:
  - Nextcloud or ownCloud: `https://cloud.example.com/remote.php/dav/files/<username>`
  - Generic Apache `mod_dav`: `https://files.example.com/dav`
  - Vendor-specific: see the provider's documentation for its WebDAV endpoint.
- A credential matching the chosen mode: a username and password for `basic`, or a Bearer token for `token`.
- A Prisme.ai workspace you administer, in which you can install apps and write workspace secrets. The exact roles are listed under [Before you begin](/apps-store/marketplace/connectors/install-in-workspace#before-you-begin). The connector answers Resource calls only to members of that workspace.
- Optional: the subtree you want to expose, to enter as **Allowed path**.

<Warning>
  On a Nextcloud or ownCloud account with two-factor authentication enabled, the main account password is rejected. Create a dedicated app password in the account settings under **Security > Devices & sessions > Create new app password** and use it as the password. This procedure is documented by the vendor in the [Nextcloud user manual](https://docs.nextcloud.com/server/latest/user_manual/en/session_management.html#managing-devices).
</Warning>

  ## Declare the capability in AI Governance

  The procedure is the standard one, documented in [Declare the capability manually in AI Governance](/apps-store/marketplace/connectors/declare-capability#declare-the-capability-manually-in-ai-governance): create a capability of type `mcp` in **Governance > Org > Capabilities**, point its server URL at the **MCP endpoint** shown in the connector's configuration app, then save.   - **Access to the catalog** follows your organization's existing roles; there is no per-capability role grant for this connector.

  A workspace admin can perform the equivalent org-wide publication without leaving the connector: the configuration app has a **Capabilities catalog (org-wide)** section with **Add to catalog** and **Update catalog entry** buttons that write the same entry, including the scope. That action requires catalog write rights in your organization; without them the app reports that the operation is forbidden and that catalog write rights are needed. See [Publish the connector to the Capabilities catalog](/apps-store/marketplace/connectors/declare-capability#publish-the-connector-to-the-capabilities-catalog).

    ## Tool catalog

    The MCP server exposes a single entity tool, `files`. Its required `action` argument selects the operation. Ten actions are meant for the model; `checkAccess` is reserved for Knowledge sync and must not be called by an agent.

    | Action | Description | Risk |
    |---|---|---|
    | `list` | List files and directories at a path, with `depth` `0` or `1`. | Read |
    | `get` | Download file content. | Read |
    | `getProperties` | Return metadata for a file or directory without its content. | Read |
    | `upload` | Create or overwrite a file. | Write, overwrites by default |
    | `delete` | Delete a file or a directory, recursively. | Destructive |
    | `move` | Move or rename a file or directory. | Write, overwrites by default |
    | `copy` | Copy a file or directory. | Write, overwrites by default |
    | `getTree` | Return the full nested directory tree under a path. | Read, expensive |
    | `search` | Recursive search by file name and modification date, paginated. | Read, expensive |
    | `createDir` | Create a directory. The parent must already exist. | Write |
    | `checkAccess` | Report which canonical Resource URIs may be served. Called by Knowledge sync, never by the model. | Read |

    Every action also accepts `outputFormat`, which controls the MCP response shape:

    - `verbose` (default): human-readable text for the model.
    - `structured`: machine-readable JSON in `structuredContent`.
    - `both`: text and structured content together.

    ## Action arguments

    ### `files` with action `list`

    ```json
    {
      "name": "files",
      "arguments": {
        "action": "list",
        "path": "/Documents",
        "depth": 1
      }
    }
    ```

    | Parameter | Required | Description |
    |---|---|---|
    | `action` | Yes | Must be `list`. |
    | `path` | No | Directory to list. Defaults to `/`. Replaced by the configured allowed path when one is set. |
    | `depth` | No | `1` (default) for immediate children, or `0` for the path's own information only. No other value is accepted. |

    ### `files` with action `upload`

    ```json
    {
      "name": "files",
      "arguments": {
        "action": "upload",
        "path": "/Generated/summary.md",
        "content": "# Daily summary\n\nFirst line.",
        "contentType": "text/markdown"
      }
    }
    ```

    | Parameter | Required | Description |
    |---|---|---|
    | `action` | Yes | Must be `upload`. |
    | `path` | Yes, unless a chat attachment supplies the file name | Target file path. An existing file at that path is overwritten. |
    | `content` | Yes, unless a chat attachment supplies the bytes | Text content of the file. |
    | `contentType` | No | MIME type. Defaults to `text/plain`. Common values: `text/markdown`, `application/json`, `text/csv`. |

    <Note>
      When the capability scope includes `attachment_urls` and the user attached a file in the chat, the connector fetches the first attachment and uploads its bytes instead of asking the model for `content`. It derives the file name from the attachment URL when `path` is absent, and the MIME type from the attachment response when `contentType` is absent. Explicit `content` always wins over the attachment.
    </Note>

    ### `files` with action `move` or `copy`

    ```json
    {
      "name": "files",
      "arguments": {
        "action": "move",
        "sourcePath": "/Exports/report.csv",
        "destinationPath": "/Archive/report.csv",
        "overwrite": false
      }
    }
    ```

    | Parameter | Required | Description |
    |---|---|---|
    | `action` | Yes | `move` or `copy`. |
    | `sourcePath` | Yes | Current path of the file or directory. |
    | `destinationPath` | Yes | Target path. Both paths must sit inside the allowed path when one is configured. |
    | `overwrite` | No | Overwrite the destination if it exists. Defaults to `true`. |

    ### `files` with action `search`

    ```json
    {
      "name": "files",
      "arguments": {
        "action": "search",
        "path": "/Reports",
        "query": "q2",
        "dateFrom": "2026-04-01T00:00:00Z",
        "dateTo": "2026-07-01T00:00:00Z",
        "sortOrder": "desc",
        "page": 1,
        "pageSize": 25
      }
    }
    ```

    | Parameter | Required | Description |
    |---|---|---|
    | `action` | Yes | Must be `search`. |
    | `path` | No | Search root. Defaults to `/`, and is replaced by the configured allowed path when one is set. The search is always recursive. |
    | `query` | No | Case-insensitive substring match on the file name. |
    | `dateFrom` | No | ISO 8601 date. Only files modified on or after this date. |
    | `dateTo` | No | ISO 8601 date. Only files modified on or before this date. |
    | `sortOrder` | No | `desc` (default, newest first) or `asc`. |
    | `page` | No | Page number, 1-indexed. Defaults to `1`. |
    | `pageSize` | No | Items per page. Defaults to `50`. |

    Results contain files only; directories are excluded from the matches. Filtering, sorting and pagination are applied by the connector after it has walked the tree, so a large subtree costs the same server round trip whatever the page size.

    ### `files` with action `getTree`

    ```json
    {
      "name": "files",
      "arguments": {
        "action": "getTree",
        "path": "/Projects/Acme"
      }
    }
    ```

    | Parameter | Required | Description |
    |---|---|---|
    | `action` | Yes | Must be `getTree`. |
    | `path` | No | Root of the tree. Defaults to `/`, and is replaced by the configured allowed path when one is set. |

    The returned tree contains directories only, not files.

    <Warning>
      `getTree` and `search` both issue a single `PROPFIND` with `Depth: infinity`. Many WebDAV servers, Nextcloud among them, refuse that header, and the call then fails with `Error: PROPFIND with Depth: infinity failed. The server may not support infinite depth requests.` Every WebDAV request also has a 15 second deadline. Prefer `list` with `depth: 1` and walk one level at a time when a server refuses infinite depth or a subtree is large.
    </Warning>

    ## Workspace builder path

    **Goal:** install the connector in a workspace, store the WebDAV credential, allow the agents that may use it, and call WebDAV operations from your automations.

    ## Install and configure

    WebDAV follows the standard App + MCP installation flow: install **WebDAV** from **Builder > Apps**, open the **Configuration app** link on the app instance, save the credential, then allowlist the agents. Each step, with the roles it requires, is documented in [Install a connector in your workspace](/apps-store/marketplace/connectors/install-in-workspace#install-the-app). What follows is only what is specific to WebDAV.

    **What the install provisions.** The connector computes the **MCP Endpoint** for this workspace, generates the **Configuration app** link, and creates three empty workspace secrets ready to be filled: `webdavPassword`, `webdavToken` and `webdavAuthorizedAgents`. See [What installing provisions](/apps-store/marketplace/connectors/install-in-workspace#what-installing-provisions).

    ### Credential fields

    Under **WebDAV credentials** in the [configuration app](/apps-store/marketplace/connectors/install-in-workspace#configure-credentials-in-the-configuration-app), fill in:

    | Field | What to enter |
    |---|---|
    | **Base URL** | The folder the account lands in, for example `https://cloud.example.com/remote.php/dav/files/alice` |
    | **Authentication** | **Username + password**, or **Bearer token** |
    | **Username** and **Password** | The account and its password or app password, in Basic mode |
    | **Bearer token** | The token issued by your provider, in token mode |
    | **Allowed path (optional)** | A subtree such as `/Documents`. Everything outside it is refused: browsing, reading and knowledge sync alike. Leave empty for the whole account. |

    Select **Save credentials**. The password and the token go to your workspace's secret store; the base URL, the authentication type, the username and the allowed path go to the app instance configuration, which is what the connector reads at runtime. WebDAV has no OAuth mode, so there is no callback URL to register and no per-user account to connect.

    Then select **Test connection**. The configuration app saves first, then asks the connector itself to reach the server with the values the runtime will read. It probes the allowed path when one is set, and the account root otherwise.

    ### Authorized agents

    Under **Authorized agents**, tick each agent allowed to call this connector's MCP endpoint. Each change is saved immediately. For a ticked agent, **Install capability** also attaches the MCP tool to that agent with the correct scope, replacing any previous instance of it. See [Authorize the agents that may call the connector](/apps-store/marketplace/connectors/install-in-workspace#authorize-the-agents-that-may-call-the-connector).

    To disable the per-agent gate entirely, select **Allow all agents (disables selection + verification)**. The app then displays a standing warning that any agent can call this connector.

    <Warning>
      With a shared WebDAV service credential, **Allow all agents** means any agent in the workspace can read and write everything the account can reach inside the allowed path. Keep it for a private test workspace only. See [The allow-all wildcard](/apps-store/marketplace/connectors/install-in-workspace#the-allow-all-wildcard).
    </Warning>

    ## Configuration reference

    | Field | Stored in | Description |
    |---|---|---|
    | **WebDAV Base URL** (`baseUrl`) | App instance config | WebDAV server base URL. Every path in a call is resolved relative to it. |
    | **Authentication Type** (`type`) | App instance config | `basic` for username and password, `token` for a Bearer token. |
    | **Username** (`username`) | App instance config | Username for Basic authentication. Ignored in token mode. |
    | **Password** (`password`) | Workspace secret `webdavPassword` | Password or app password for Basic authentication. |
    | **Bearer Token** (`token`) | Workspace secret `webdavToken` | Bearer token for token mode. |
    | **Allowed path (optional)** (`allowedPath`) | App instance config | Restricts MCP tool calls and Resource calls to this subtree. Leave empty for no restriction. |
    | **Max inlined file size (bytes)** (`connectorInlineMaxBytes`) | App instance config | Files larger than this are reported as unfetchable by the Knowledge Resource reader instead of being inlined. Defaults to `1400000`. |
    | **Configuration app** (`configAppUrl`) | App instance config, read-only | Generated on install. Opens the configuration app for this instance. |
    | **Authorized agents** (`authorizedAgents`) | Workspace secret `webdavAuthorizedAgents` | Comma-separated agent ids allowed to call the MCP endpoint. `*` allows every agent. Managed by the configuration app. |
    | **MCP Endpoint** (`mcpEndpoint`) | App instance config, read-only | Generated on install. The URL an agent or a Knowledge connection is given. |

    <Warning>
      Do not edit the `password`, `token` or `authorizedAgents` fields by hand in the raw app configuration. They hold generated binding literals that resolve to the workspace secrets; overwriting them breaks credential resolution. Use the configuration app, or Builder's **Secrets** panel, instead.
    </Warning>

    ## App instructions

    App instructions resolve the credential from the workspace configuration through the same code path as the MCP tools. Paths are interpreted relative to `baseUrl`.

    | Instruction | Arguments | Returns |
    |---|---|---|
    | `listFiles` | `path` (default `/`), `depth` (`1` default, or `0`) | `{ path, depth, totalItems, items: [{ href, url, name, isDirectory, size, contentType, lastModified, etag }] }` |
    | `getFile` | `path` (required) | `{ path, content, contentType, size }` |
    | `getFileProperties` | `path` (required) | `{ path, name, isDirectory, size, contentType, lastModified, etag }` |
    | `uploadFile` | `path` (required), `content` (required), `contentType` (default `text/plain`) | `{ success, path, status, created, contentType }` |
    | `deleteFile` | `path` (required) | `{ success, path, status }` |
    | `moveFile` | `sourcePath` (required), `destinationPath` (required), `overwrite` (default `true`) | `{ success, sourcePath, destinationPath, status }` |
    | `copyFile` | `sourcePath` (required), `destinationPath` (required), `overwrite` (default `true`) | `{ success, sourcePath, destinationPath, status }` |
    | `getDirectoryTree` | `path` (default `/`) | `{ rootPath, tree: { name, path, url, children: [...] } }` |
    | `searchFiles` | `path` (default `/`), `query`, `dateFrom`, `dateTo`, `page` (default `1`), `pageSize` (default `50`), `sortOrder` (default `desc`) | `{ searchPath, dateFrom, dateTo, query, sortOrder, totalItems, page, pageSize, totalPages, items }` |
    | `createDirectory` | `path` (required) | `{ success, path, status }` |

    Any failure is returned as `{ error: "<message>" }` rather than raised, so test for `error` before using the result.

    <Warning>
      **Allowed path is not enforced on App instructions.** The subtree restriction is applied by the MCP endpoint only. A DSUL automation calling `WebDAV.getFile` can reach any path the credential can reach. Treat the allowed path as a restriction on agents and Knowledge sync, and control automation scope through your workspace's own access rules.
    </Warning>

    ## DSUL examples

    ```yaml
          size: '{{report.size}}'
    ```

    ```yaml
    - WebDAV.uploadFile:
        path: '/Generated/{{run.date}}-summary.md'

          # Daily summary

        contentType: 'text/markdown'
    ```

## Use WebDAV as a Knowledge connector

Beyond tool calls, the MCP endpoint implements the Resource methods that a knowledge base uses to browse, read and re-check documents. The end-to-end procedure for attaching a WebDAV account to a knowledge base is documented in [Knowledges connectors](/products/ai-knowledge/connectors); this section states what the connector itself guarantees.

- **Addressing.** A file or folder is addressed as `webdav://files/{path}`, where each path segment is percent-encoded and the path is relative to the configured base URL. Resource URIs therefore survive a change of base URL host.
- **Discovery.** `webdav://profile/knowledge` is a fixed public descriptor served anonymously, along with `resources/templates/list` and `initialize`. Nothing in them touches the WebDAV server or its credential.
- **Authorization.** `resources/list` and `resources/read` are authorized against the workspace that holds the configuration: the caller must be able to read that workspace. The agent allowlist does not apply to them. An anonymous caller, or one presenting only an API key, is refused with `This connector answers Resource calls to its workspace members, or to the trusted Knowledge Sync workspace.`
- **Listing.** `resources/list` with no parent URI starts at the allowed path when one is set, and at `/` otherwise. The page size defaults to `200` and is capped at `1000`. The cursor is opaque and carries the parent path and the active query, so paging without resending the same query is not possible. Delta listing is not supported: each pass lists and compares.
- **Reading.** A folder returns identity only. A file returns its metadata plus its bytes inlined as a data URL, because WebDAV has no anonymous pre-signed URL. Files above `connectorInlineMaxBytes` (default `1400000`) are returned marked unfetchable rather than truncated, as are files whose size the server does not report.
- **Freshness.** The revision compared between syncs is the WebDAV `getetag` property, falling back to `getlastmodified`.
- **Access re-check.** Knowledge sync calls the `files` tool with `action: "checkAccess"` and a list of Resource URIs, and receives the subset that is still inside the allowed path and still present on the server. At most `200` URIs are accepted per call; a longer batch is refused with `Too many resource URIs in one access check (<n>); this connector answers at most 200 per call.` The check covers freshness and perimeter, never identity: the connector holds one credential, so the verdict is the same for every reader.

<Warning>
  Per-user access control is not available for WebDAV. Every reader of a knowledge base fed by this connector can retrieve any document the service credential can read, within the allowed path. Scope the account and the allowed path accordingly before syncing.
</Warning>

## Verify the setup

Run these checks in order. Each has an observable result. They are the WebDAV form of the generic checks in [Verify the installation](/apps-store/marketplace/connectors/install-in-workspace#verify-the-installation); WebDAV has no "who am I" operation, because every call uses the same service credential.

<Steps>
  <Step title="Verify the credential reaches the server">
    In the configuration app, select **Test connection**. Success reports that the server answered, naming the path that was probed: the allowed path when one is set, the account root otherwise. A refusal reports the HTTP status: `401` means wrong credentials, and `404` means a wrong base URL or a nonexistent allowed path.
  </Step>
  <Step title="Verify a read-only tool call from the agent">
    In the agent's playground, ask for a plain directory listing, for example `List the files at the top level of the WebDAV share`. The agent should call `files` with `action: "list"` and return the entries. Do this before any write test.
  </Step>
  <Step title="Verify the perimeter is enforced">
    With an **Allowed path** configured, ask the agent to read a path outside it. The call must fail with `Access denied - path outside allowed scope`. A success here means the allowed path was not saved.
  </Step>
  <Step title="Verify the allowlist blocks an unlisted agent">
    From an agent that is not ticked under **Authorized agents**, trigger any tool. The call must be refused with `This agent is not authorized to use this connector.` If it succeeds, check that **Allow all agents** is not enabled.
  </Step>
  <Step title="Verify a controlled write">
    Ask the agent to upload a small text file to a disposable path, then confirm it in the WebDAV interface, then delete it. Confirm that the agent asked you before deleting, per its system prompt.
  </Step>
</Steps>

## Error handling

### Configuration errors

These are returned by the connector before any request reaches the WebDAV server.

| Message | Cause | Fix |
|---|---|---|
| `WebDAV not configured. Please set baseUrl, type, and credentials in the app configuration.` | `baseUrl` is empty on the app instance. | Enter the **Base URL** in the configuration app and save. |
| `Basic Auth requires username and password.` | `type` is `basic` but the username or the password is empty. | Fill both. On a two-factor account, use an app password. |
| `Token auth requires a Bearer token.` | `type` is `token` but no token is stored. | Paste the token under **Bearer token** and save. |
| `Unknown auth type: <value>. Expected "basic" or "token".` | `type` holds an unsupported value. | Set **Authentication** through the configuration app rather than editing the raw config. |

### Authorization errors

These are JSON-RPC errors returned by the MCP endpoint.

| Code | Message | Cause | Owner |
|---|---|---|---|
| `-32003` | `This agent is not authorized to use this connector.` followed by the agent id and the remediation | The calling agent is not on the tenant allowlist. | Workspace admin, in the configuration app |
| `-32003` | ``No agent id reached this connector. Add `agent_id` to the MCP capability scope so agent-factory injects it.`` | The capability was declared without `agent_id` in its **Scope**. | Agent builder or Governance admin, on the capability |
| `-32001` | `Access denied - path outside allowed scope` | A tool call names a path outside the configured allowed path. The error carries the allowed path in its `data`. | Caller, or workspace admin if the perimeter is wrong |
| `-32602` | `This path is outside the configured allowed path.` | Same perimeter check on a Resource read or list. | Caller, or workspace admin |
| `-32003` | `This connector answers Resource calls to its workspace members, or to the trusted Knowledge Sync workspace.` | A Resource call arrived with no identity and from no trusted caller. An API key is refused here too. | Caller |
| `-32003` | `You do not have the rights to read this connector on the workspace that holds its configuration.` | The caller is identified but cannot read the workspace holding the credential. | Workspace admin, by granting read on that workspace |
| `-32001` | `This connector could not authenticate the call, so membership of the workspace holding its configuration could not be established. This is not a missing role.` | The platform declined to authenticate the call, for example an organization enforcing multi-factor authentication. | Organization admin |

### Argument errors

| Message | Cause |
|---|---|
| ``Missing required argument `action` for files. Available: copy, createDir, delete, get, getProperties, getTree, list, move, search, upload`` | The tool call omitted `action`. |
| ``Unknown action `<value>` for files. Available: …`` | The `action` value is not one of the supported operations. |
| `Tool not found: <name>` | The tool name is not `files` and does not match a known operation. |
| `Method not found: <method>` | The JSON-RPC method is not implemented by this endpoint. |
| `Invalid dateFrom: <value>` or `Invalid dateTo: <value>` | A `search` filter is not a parsable date. Use ISO 8601, for example `2026-04-01T00:00:00Z`. |

### Server errors

The connector surfaces the WebDAV server's own status in messages of the form `Error listing files: HTTP <status> <statusText> - <body>`, `Error downloading file (HTTP <status>)`, `Error uploading file (HTTP <status>)`, `Error deleting file (HTTP <status>)`, `Error moving file (HTTP <status>)` and `Error creating directory (HTTP <status>)`. Interpret the status with the [WebDAV specification](https://datatracker.ietf.org/doc/html/rfc4918#section-11): `401` for authentication, `403` for a permission the account lacks, `404` for a missing path, `405` when the target already exists, `409` when the parent of a new directory does not exist, `412` when `overwrite` is `false` and the destination exists, `423` when another client holds a lock, and `507` when the account is over quota.

A request that the server never answers is reported with status `0` and `timeout after 15s`.

### Common issues

**Nextcloud or ownCloud returns `401` with a password you know is right.** The account has two-factor authentication enabled, which rejects the main password over WebDAV. Create an app password and use it instead.

**`Error: PROPFIND with Depth: infinity failed.`** The server refuses infinite-depth listings, which `getTree` and `search` both need. Use `list` with `depth: 1` and walk one level at a time.

**Every tool call is refused although the credential tests fine.** The calling agent is not allowlisted, or the capability scope is missing `agent_id`. Check **Authorized agents** in the configuration app, and the capability's **Scope** field.

**An agent uploads invented text instead of the file the user attached.** The capability scope is missing `attachment_urls`, so the connector never receives the attachment URL and the model fills `content` itself. Add `attachment_urls` to the scope and reinstall the capability.

**`Failed to fetch the uploaded attachment (HTTP <status>).`** The attachment URL injected by Agent Creator could not be retrieved. Ask the user to re-attach the file, then retry.

**A knowledge base returns fewer documents than the folder holds.** Files larger than `connectorInlineMaxBytes`, and files whose size the WebDAV server does not report, are marked unfetchable and skipped. Raising `connectorInlineMaxBytes` above roughly 1.4 MB does not help: the bytes travel as a base64 data URL whose content field is capped at 2,000,000 characters downstream.

**A directory listing returns `404`.** Some WebDAV servers are strict about trailing slashes on collections. Retry the path with a trailing `/`.

## Revoke, rotate and remove

These are the WebDAV specifics of [Rotate credentials and uninstall](/apps-store/marketplace/connectors/install-in-workspace#rotate-credentials-and-uninstall).

- **Rotate the credential.** Change the password or token at the provider, then enter the new value in the configuration app and select **Save credentials**, then **Test connection**. No agent or automation needs to be reconfigured: they never hold the credential.
- **Revoke one agent.** Untick it under **Authorized agents**. The change takes effect on the next call; the agent then receives the `-32003` refusal. Removing the MCP capability from the agent itself is a separate action, done in Agent Creator.
- **Revoke every agent at once.** Clear the allowlist, or if **Allow all agents** is enabled, turn it off first. An empty allowlist refuses every agent.
- **Narrow the perimeter.** Set or tighten **Allowed path** and save. It applies immediately to MCP tool calls and Resource calls, including knowledge syncs already attached.
- **Offboard the account.** Disable or delete the WebDAV service account at the provider. Every path through the connector fails at once, which is the intended fail-closed behavior.
- **Remove the connector.** Uninstall the WebDAV app from the workspace, then delete the `webdavPassword`, `webdavToken` and `webdavAuthorizedAgents` secrets from the workspace's **Secrets** panel, since uninstalling the app does not clear them. Detach any knowledge base connection that pointed at the endpoint, and delete the Governance capability if one was declared for it, as described in [Remove or update a capability](/apps-store/marketplace/connectors/declare-capability#remove-or-update-a-capability).

<Warning>
  Treat the MCP endpoint URL as sensitive and share it only with the people who administer the connector. The **Authorized agents** list matches the agent id presented in the call, so it routes and filters traffic rather than cryptographically authenticating the caller. The Resource methods do not rely on it: they authorize each caller against membership of the workspace that holds the credential.
</Warning>
