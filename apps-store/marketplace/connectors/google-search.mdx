The Google Search connector (workspace slug `google-search`) exposes Google web search through a single operation named `search`. It can be consumed two ways: as a remote MCP server that **Agent Creator** agents attach as a capability, or as a Builder app whose `search` instruction you call directly from DSUL. It runs in the **tenant app-instance context**, which means it resolves the installing workspace's own Google credential, and it routes automatically between two backends:

- **Gemini Grounding** (default, when no `cx` is configured): calls the Gemini `generateContent` endpoint with the `google_search` tool enabled, and returns a synthesized `answer` plus the sources Gemini cited.
- **Custom Search JSON API** (legacy, when a Programmable Search Engine ID `cx` is configured): calls `customsearch/v1` and returns ranked organic results, with rich filters (result count, date, site, language, file type) and image search. Its coverage is whatever the Programmable Search Engine behind `cx` is configured to search.

Authentication is a **Google Cloud API key** (`AIza...`, sent as the `X-goog-api-key` header) or a **service-account JSON** (signed into a JWT and exchanged for a short-lived bearer token). There is no per-user sign-in. Agents are identified by the `agent_id` that Agent Creator injects through the capability **Scope** `context_id,agent_id,user_id`, and are gated by a per-workspace authorized-agents allowlist.

## Operating model and runtime identity

Understand what the connector does on your behalf before you configure it.

| Property | Value |
|---|---|
| Authentication methods | A Google Cloud API key, or a Google service-account JSON exchanged for an OAuth 2.0 bearer token through the `urn:ietf:params:oauth:grant-type:jwt-bearer` grant |
| Runtime identity seen by Google | The API key or the service account configured on the workspace, never the end user |
| Credential scope | Shared across every agent and every automation that can reach the app instance of that workspace |
| Fallback identity | A workspace with no credential of its own proxies its searches through the core `google-search` workspace and runs on the platform global key, if a maintainer set one |
| Caller authorization | `tools/call` accepts an agent only if its `agent_id` is in the workspace allowlist, or if the allowlist holds the `*` sentinel, or if the call reaches the core workspace endpoint while a platform global key is set |
| Audit attribution in Google | All searches appear as the configured key or service account, not as the invoking user |
| Write access | None. The connector performs read-only web search and writes nothing to your systems |

<Warning>
  The Google credential is a shared service credential. Every agent you allowlist, and every automation in the workspace, searches with the same identity and consumes the same Google quota. Keep the allowlist tight, and prefer ticking individual agents over enabling **Allow all agents**, which disables the calling-agent verification entirely.
</Warning>

### Choose a backend

The backend is not a free choice per call: it is decided by the workspace configuration, before the call is routed.

| Backend | Selected when | Choose it for |
|---|---|---|
| **Gemini Grounding** (default, recommended) | No `cx` is configured | Whole-web questions where a synthesized answer with cited sources is the useful output. Requires the Generative Language API. |
| **Custom Search JSON API** (legacy) | A `cx` is configured | Deterministic ranked results, enforced filters, pagination and structured image results, scoped to your Programmable Search Engine. Requires the Custom Search API. |

Because the backend is resolved from the workspace configuration before routing, passing `options.cx` on a call does **not** switch a Grounding workspace to Custom Search. It only overrides the engine when the workspace already runs the Custom Search backend.

## Prerequisites

### Google prerequisites

- A **Google** account with a **Google Cloud project**.
- The API matching your backend enabled in that project, from **APIs & Services > Library**:
  - **Generative Language API** (`generativelanguage.googleapis.com`) for Gemini Grounding. Grounding is not a separate API to enable; it is the `google_search` tool inside the Gemini `generateContent` call.
  - **Custom Search API** (`customsearch.googleapis.com`) for the legacy `cx` backend.
- A credential, one of:
  - A **Google Cloud API key** (`AIza...`), created from **APIs & Services > Credentials > Create credentials > API key**.
  - A **service-account key JSON**, for server-to-server use. The connector signs an RS256 JWT with the `private_key` in that JSON, requests the scopes `https://www.googleapis.com/auth/generative-language` and `https://www.googleapis.com/auth/cloud-platform`, and exchanges it at the `token_uri` declared in the JSON, which defaults to `https://oauth2.googleapis.com/token`.
- For the Custom Search backend only: a **Programmable Search Engine**, created at [programmablesearchengine.google.com](https://programmablesearchengine.google.com), whose engine ID is the `cx` value. The engine returns results only from the sources its own configuration covers.

<Note>
  The Gemini API free tier is low, around 20 requests per day for `gemini-2.5-flash`. Enable billing on the Cloud project for production traffic, or switch to the Custom Search backend. Check the [Gemini API rate limits](https://ai.google.dev/gemini-api/docs/rate-limits) and the [Custom Search JSON API pricing](https://developers.google.com/custom-search/v1/overview) for the quotas that apply to your project.
</Note>

### Prisme.ai prerequisites

- **Workspace builder**: the `owner`, `editor` or `admin` role on the Builder workspace where you install the app, as described in [Before you begin](/apps-store/marketplace/connectors/install-in-workspace#before-you-begin).
- **Agent builder**: an agent in Agent Creator that you can edit.
- **Platform maintainer**: the `owner`, `editor` or `admin` role on the core `google-search` workspace. This role is checked on that workspace itself; being a platform superadmin elsewhere does not grant it.
- **Capabilities catalog publishing**: the `org:owner` or `org:admin` role in the organization, as described in [Before you begin](/apps-store/marketplace/connectors/declare-capability#before-you-begin).

  ## 1. Set the global key

  <Steps>
    <Step title="Prepare the Google credential">
      In the Google Cloud project that will carry the platform quota, enable the **Generative Language API** for Grounding, or the **Custom Search API** plus a Programmable Search Engine for the legacy backend, then create an API key or a service-account key JSON as described in the prerequisites.
    </Step>
    <Step title="Open the maintainer view">
      In Builder, open the core `google-search` workspace and open its configuration app. Hosted on that workspace, the app renders the **Platform global Google key** maintainer view instead of the per-workspace configuration form. If you see **Access restricted** instead, you do not hold `owner`, `editor` or `admin` on the core workspace.
    </Step>
    <Step title="Fill in the form and save">
      Set **Connection type** to **Gemini Grounding** or **Legacy Custom Search**, paste the credential into **API credential (API key or service-account JSON)**, then fill in **Programmable Search Engine ID (cx)** for the legacy mode or **Gemini model** for Grounding. Select **Save global key**. The app confirms that the global key is saved, and clears the credential field. Reopening the view shows that a global key is set, and prefills `cx` and the Gemini model; the credential itself is never returned. To change only `cx` or the model later, leave the credential field empty and save again.
    </Step>
  </Steps>

  The credential is written to the `googleSearchCentralAuth` secret of the core workspace. It never leaves that workspace: a workspace without its own credential posts its query to the core `centralSearch` webhook, which runs the search and returns only the results.

  <Warning>
    Setting the global key changes who may call the core workspace's own MCP endpoint. On that endpoint the per-agent allowlist stops applying and every calling agent is accepted, because the global key itself is the gate. Per-workspace app instances are unaffected: they keep enforcing their own allowlist.
  </Warning>

  ## 2. Publish the connector to the Capabilities catalog

  Publishing the connector to the organization Capabilities catalog lets agent builders attach it from the catalog instead of pasting an endpoint URL. Follow [Publish the connector to the Capabilities catalog](/apps-store/marketplace/connectors/declare-capability#publish-the-connector-to-the-capabilities-catalog); the **Capabilities catalog** section sits in this same maintainer view, and its button stays disabled until the global key is saved. To author the entry by hand instead, follow [Declare the capability manually in AI Governance](/apps-store/marketplace/connectors/declare-capability#declare-the-capability-manually-in-ai-governance).

  These are the values this connector publishes:

  | Field | Value |
  |---|---|
  | Capability type | `mcp` |
  | Name | `google_search`, displayed as **Google Search** |
  | Server URL | The core `google-search` workspace MCP endpoint |
  | **Scope** | `context_id,agent_id,user_id` |
  | Authorization block | None. Authentication is a server-side Google credential, not a per-user flow |

  <Warning>
    Publishing the capability makes the connector reachable; it does not by itself authorize a specific agent against a specific workspace. A workspace running its own app instance still gates callers with its **Authorized agents** allowlist. See [Availability is not authorization](/apps-store/marketplace/connectors/declare-capability#availability-is-not-authorization). There is no OAuth authorization block to attach: authentication is a server-side Google credential, not a per-user flow.
  </Warning>
</Accordion>

    ## Tool reference

    The connector exposes one tool.

    | Tool | Description |
    |------|-------------|
    | `search` | Google web search returning top organic results plus, when available, a synthesized `answer` with cited sources. The backend is selected per workspace: Custom Search when a `cx` is configured, Gemini Grounding otherwise. Only `q` is required. |

    ### search arguments

    | Argument | Type | Required | Description |
    |---|---|---|---|
    | `q` | string | Yes | Search query. Supports Google operators such as `site:`, `intitle:`, `-exclude` and `"exact phrase"`. An empty value returns an error result. |
    | `options` | object | No | Fine-grained search parameters. Enforced by Custom Search, transposed into prompt hints by Grounding. |
    | `outputFormat` | string | No | `verbose` (default), `structured` or `both`. Controls only the MCP response shape, not the search. |

    ### options reference

    | Option | Type | Description |
    |---|---|---|
    | `cx` | string | Programmable Search Engine ID. Overrides the workspace `cx` for this call, and only when the workspace already runs the Custom Search backend. |
    | `num` | number | Number of results, from 1 to 10. Defaults to 10. Custom Search only. |
    | `start` | number | Index of the first result, from 1 to 91. Pagination, Custom Search only. |
    | `lr` | string | Language restriction in `lang_XX` form, for example `lang_fr`. |
    | `gl` | string | Country boost, ISO 3166-1 alpha-2 code, for example `fr`. |
    | `cr` | string | Country restriction, for example `countryFR`. |
    | `hl` | string | Interface language for results, for example `en`. |
    | `safe` | string | SafeSearch level, `active` or `off`. Defaults to `off`. |
    | `dateRestrict` | string | Date restriction as `d{n}`, `w{n}`, `m{n}` or `y{n}`, for example `d7` for the last 7 days. |
    | `exactTerms` | string | A phrase that every result must contain verbatim. |
    | `excludeTerms` | string | A word or phrase that no result may contain. |
    | `orTerms` | string | Space-separated terms; results contain at least one. |
    | `siteSearch` | string | Limit results to a site, for example `wikipedia.org`. |
    | `siteSearchFilter` | string | `i` to include only `siteSearch`, `e` to exclude it. |
    | `fileType` | string | Restrict to a file type, for example `pdf`. |
    | `filter` | string | Duplicate-content filter, `1` on (default) or `0` off. |
    | `sort` | string | Sort expression, for example `date`. |
    | `searchType` | string | Set to `image` for an image search. |
    | `imgSize` | string | `huge`, `icon`, `large`, `medium`, `small`, `xlarge` or `xxlarge`. |
    | `imgType` | string | `clipart`, `face`, `lineart`, `stock`, `photo` or `animated`. |
    | `imgColorType` | string | `color`, `gray`, `mono` or `trans`. |
    | `imgDominantColor` | string | `black`, `blue`, `brown`, `gray`, `green`, `orange`, `pink`, `purple`, `red`, `teal`, `white` or `yellow`. |
    | `rights` | string | Creative Commons rights filter, for example `cc_publicdomain`. |
    | `c2coff` | string | Toggle Simplified and Traditional Chinese search, `1` disables it. |
    | `linkSite` | string | Results must contain a link to this URL. |
    | `hq` | string | Additional terms appended with AND logic. |
    | `lowRange` | string | Search range starting value. |
    | `highRange` | string | Search range ending value. |

    <Note>
      In Grounding mode these options are not sent to Google as parameters. Those that can be expressed in words are prepended to the prompt as instructions, so Gemini follows them only when it finds them reasonable. The ones that cannot be expressed in words, `start`, `sort`, `filter`, `rights`, `c2coff`, `linkSite`, `hq`, `lowRange`, `highRange` and `cx`, are dropped and listed in the `warnings` array of the response. `searchType: image` is likewise turned into a prompt hint: Grounding returns image-bearing web pages rather than the structured image fields that Custom Search provides, and it adds a warning saying so.
    </Note>

    ### Call example

    ```json
    {
      "name": "search",
      "arguments": {
        "q": "prisme.ai pricing",
        "options": {
          "dateRestrict": "m1",
          "siteSearch": "prisme.ai",
          "num": 5
        }
      }
    }
    ```

    ### Response format

    `outputFormat` controls the MCP response shape:

    - **`verbose`** (default): a single text block holding a markdown view with the answer, the numbered sources with links and snippets, the queries Gemini actually ran, and any warnings.
    - **`structured`**: the structured payload as `structuredContent`, with its JSON also rendered in the text block.
    - **`both`**: same as `structured`.

    Whatever the format, when the result carries sources, `url_citation` annotations are attached to the first content block so the interface can render clickable source cards.

    The structured payload has this shape:

    ```json
    {
      "query": "prisme.ai pricing",
      "backend": "grounding",
      "answer": "synthesized answer, Grounding only",
      "totalResults": "3",
      "searchTime": 0,
      "searchQueries": ["prisme ai pricing"],
      "items": [
        { "title": "...", "link": "...", "displayLink": "...", "snippet": "..." }
      ],
      "warnings": []
    }
    ```

    `backend` is `grounding` or `customSearch`. In Grounding mode `answer` holds the synthesized response, `items` are the cited sources, `searchQueries` are the queries Gemini ran, `totalResults` is the number of cited sources, and `searchTime` is `0`. In Custom Search mode `answer` is empty, `searchQueries` is empty, `totalResults` and `searchTime` are Google's own estimate and timing, `items` are the ranked organic results, and each item may also carry `fileFormat` and, for image searches, an `image` object with `contextLink`, `thumbnailLink`, `width` and `height`.

    Failures inside the tool come back as a tool result with `isError` set to `true` and a text block carrying the message, not as a JSON-RPC error.

    ## MCP protocol surface

    The endpoint speaks JSON-RPC 2.0 over HTTP POST.

    | Method | Result |
    |--------|--------|
    | `initialize` | Handled by MCP Core, with `serverInfo` `{ "name": "google-search-mcp", "version": "1.0.0" }` |
    | `tools/list` | Handled by MCP Core; returns the `search` tool definition and its input schema |
    | `tools/call` | Authorizes the calling agent, resolves the credential, routes to the selected backend, and returns the tool result |
    | Notifications | Any request without a JSON-RPC `id`, such as `notifications/initialized`, returns HTTP `202` with an empty body |

    ## Configuration reference

    | Field | Description |
    |-------|-------------|
    | **Configuration app** | Read-only, filled in on install. Opens the app that manages the credential, the backend and the agent allowlist. |
    | **Connection type** | **Gemini Grounding** (recommended) or **Legacy Custom Search**. Selecting Grounding clears `cx` when you save, which is how the server detects the backend. |
    | **API credential (API key or service-account JSON)** | A Google Cloud API key starting with `AIza`, sent as `X-goog-api-key`, or a full service-account JSON starting with `{`, signed into a JWT and exchanged for a bearer token. |
    | **Programmable Search Engine ID (cx)** | Legacy mode only. The Custom Search engine to query. |
    | **Gemini model** | Grounding mode only, optional. Defaults to `gemini-2.5-flash`. |

    The values are stored in the workspace secrets, not in a visible configuration field:

    | Secret | Content |
    |---|---|
    | `googleSearchAuth` | Object holding the credential and the backend configuration: `apiKey`, `cx`, `geminiModel`, `baseUrl`. |
    | `googleSearchAuthorizedAgents` | Comma-separated agent IDs allowed to call the MCP endpoint, or `*` for all. |

    <Note>
      `baseUrl` overrides the Google host the connector calls, defaulting to `https://generativelanguage.googleapis.com` for Grounding and `https://customsearch.googleapis.com` for Custom Search. The configuration app does not expose it; set it directly on the `googleSearchAuth` secret if you need it.
    </Note>

    <Note>
      A workspace with no credential of its own does not fail. Its searches are proxied to the core `google-search` workspace and run on the [platform global Google key](#platform-maintainer-set-the-platform-global-google-key), if a maintainer set one. To keep searches on your own quota, always save a credential.
    </Note>

    ## Available instructions

    The instruction resolves the credential and the backend from the workspace configuration.

    | Instruction | Description | Returns |
    |-------------|-------------|---------|
    | `search` | Runs a Google web search. `q` is required; combine Google operators inside it. `options` carries the fine-grained filters. | `{ query, backend, answer, totalResults, searchTime, searchQueries, items, warnings }`, or `{ error }` on failure |

    The `options` object accepts the same parameters as the MCP tool, except `filter`, `sort`, `c2coff`, `linkSite`, `hq`, `lowRange` and `highRange`, which the instruction does not declare. See the [options reference](#options-reference) table in the [Agent builder](#agent-builder-agent-creator) tab for the full list. The instruction has no `outputFormat` argument: it always returns the structured payload.

    ```yaml
      output: result
    # result.answer holds the synthesized answer, result.items the cited sources
    ```

    Recent news restricted to a site:

    ```yaml
    - Google Search.search:
        q: "AI regulation"
        options:
          dateRestrict: w2
          siteSearch: lemonde.fr

          num: 5
    ```

    Image search, which needs the Custom Search backend and therefore a configured `cx`:

## Verify the connector

Run these checks in order. Stop at the first failure and use the matching entry in the troubleshooting section.

1. In the configuration app, select **Test connection**. It saves the credential, then makes one lightweight authenticated call: `GET v1beta/models` in Grounding mode, which costs no model usage, or `customsearch/v1` with `num=1` in legacy mode. Expected result: a success message reporting the resolved backend, `grounding`, `customSearch`, or `central` when the workspace runs on the platform global key.
2. From Builder, run the `search` instruction with `q` set to any question. Expected result: an output object whose `backend` matches the backend you configured, with a non-empty `items` array and, in Grounding mode, a non-empty `answer`.
3. From an agent that has the capability, ask a question that requires a fresh web source. Expected result: the agent calls `search` and answers with the links returned by the tool, rendered as source cards.
4. From an agent you did **not** tick, ask the same question. Expected result: the call is denied with `This agent is not authorized to use this connector`. A success means the allowlist holds `*`, or the agent is calling the core workspace endpoint while a platform global key is set.

For the generic post-install and capability checks, see [Verify the installation](/apps-store/marketplace/connectors/install-in-workspace#verify-the-installation) and [Verify the capability](/apps-store/marketplace/connectors/declare-capability#verify-the-capability). The "who am I" check listed there does not apply: this connector exposes no identity operation, because it never acts as the end user.

## Error handling

Google errors are normalized before they reach the caller. `<operation>` is the action in progress, such as `searching Google via Grounding`, `searching Google`, `testing Gemini Grounding auth`, or `testing Custom Search auth`. `<detail>` is the message Google returned, or `(no further detail)` when the response carries none.

| Status | Message |
|--------|---------|
| `400` | `Bad request while <operation>: <detail>` |
| `401` | `Authentication failed while <operation>. Check the Google API key. Detail: <detail>` |
| `403` | `Forbidden while <operation>. Check the key has access and the matching Google API is enabled (Generative Language API for Grounding, or Custom Search API for the legacy cx backend). Detail: <detail>` |
| `404` | `Resource not found while <operation>. Detail: <detail>` |
| `429` | `Rate limit / quota exceeded while <operation>. <detail>` |
| `500` | `Google server error while <operation>. Detail: <detail>` |
| Any other | `Error <status> while <operation>: <detail>` |

The raw Google response body is never echoed back, so credentials or provider metadata in an unrecognized error shape cannot leak into an agent transcript.

## Troubleshooting

Installation and capability failures shared by every App + MCP connector are documented in [Install a connector in your workspace](/apps-store/marketplace/connectors/install-in-workspace#troubleshooting) and [Declare a connector capability](/apps-store/marketplace/connectors/declare-capability#troubleshooting). The entries below are the ones specific to Google Search.

**`This agent is not authorized to use this connector`**: the calling agent is not in the workspace allowlist. Tick it under **Authorized agents**, or use **Install capability**, which allowlists and wires in one step. See [Authorize the agents that may call the connector](/apps-store/marketplace/connectors/install-in-workspace#authorize-the-agents-that-may-call-the-connector).

**`The calling agent could not be identified, so it cannot be authorized`**: the MCP capability **Scope** does not declare `agent_id`, so Agent Creator never injects the agent identity. Set the capability **Scope** to `context_id,agent_id,user_id`, which is separate from any OAuth scope, then allowlist the agent. See [What the Scope means](/apps-store/marketplace/connectors/declare-capability#what-the-scope-means).

**``Google API credential is malformed: Credential starts with `{` but is not valid JSON.``**: the pasted service-account JSON is truncated or corrupted. Re-copy the whole key file from the Google Cloud Console.

**`Google API credential is malformed: JSON does not look like a Google service account (missing type/client_email/private_key).`**: the pasted JSON parses but is not a service-account key. Download a service-account key from **IAM & Admin > Service Accounts > Keys**, not an OAuth client JSON.

**`Service account missing client_email or private_key.`** or **`JWT signing failed: <message>`**: the service-account JSON is incomplete, or its `private_key` is not a usable RSA private key, often because newlines were lost when copying. Paste the file contents unchanged.

**`OAuth2 token exchange failed (HTTP <status>). Detail: <detail>`**: Google refused the JWT exchange. Check that the service account still exists and is enabled, that its key has not been deleted, and that the project has the Generative Language API enabled.

**`The platform global Google key is not configured on the Google Search core workspace.`** or **`No platform global Google key is configured. Set your own credential in the connector config app, or ask the platform administrator to set the global service key on the Google Search core workspace.`**: the workspace has no credential of its own and no global key exists. Save a credential in the configuration app, or ask a platform maintainer to set the global key.

**`Central Google Search proxy error - HTTP <status>.`**: the fallback call to the core `google-search` workspace failed. Confirm that the core workspace is reachable and that its global key is still valid, or save a credential of your own to stop using the fallback.

**`Authenticated, but the Google test call failed (status <status>).`**: the credential resolved but Google rejected the call. In Grounding mode, enable the Generative Language API on the key's project. In legacy mode, check the `cx` value and enable the Custom Search API.

**`` `q` is required and must be a non-empty string. ``**: the call carried no query. Have the agent always pass a non-empty `q`.

**``Missing `cx` (Programmable Search Engine ID). Pass it as an argument or configure it on the app instance.``**: the Custom Search backend ran without an engine ID. Set **Programmable Search Engine ID (cx)** in the configuration app, or pass `options.cx` on the call.

**`Forbidden - you must be an editor of the Google Search core workspace.`**: you tried to set the platform global key without the `owner`, `editor` or `admin` role on the core `google-search` workspace. Ask a member of that workspace to grant it, or to set the key for you.

**Filters seem ignored**: in Grounding mode the options are prompt hints, not enforced parameters, and the ones that cannot be expressed in words are dropped. Read the `warnings` array of the response to see what was skipped, and configure a `cx` to switch to Custom Search, where filters are enforced.

**Image search returns pages instead of images**: Grounding returns image-bearing web pages, not structured image fields. Configure a `cx` to switch to the Custom Search backend, which returns `image` objects with thumbnails and dimensions.

**A rotated credential is not picked up**: with an API key the change applies on the next call. With a service account the exchanged bearer token is cached for about 50 minutes, keyed by a fingerprint of the JSON, so replacing the JSON invalidates the cache immediately, while re-uploading the same JSON does not.

## Rotate credentials and remove access

The generic revoke, rotate and uninstall flow is documented in [Rotate credentials and uninstall](/apps-store/marketplace/connectors/install-in-workspace#rotate-credentials-and-uninstall), and capability removal in [Remove or update a capability](/apps-store/marketplace/connectors/declare-capability#remove-or-update-a-capability). These are the Google Search specifics.

- **Rotate the Google credential**: create the new key or service-account key in Google Cloud, paste it into **API credential** in the configuration app, select **Test connection** to confirm it works, then delete the old credential in Google Cloud.
- **Switch backend**: change **Connection type** and select **Save credential**. Saving keeps only the fields of the selected mode, so leaving legacy mode clears `cx` and returns the workspace to Grounding.
- **Revoke one agent**: in the configuration app, untick the agent under **Authorized agents**. The change is saved immediately. Removing the MCP capability from the agent in Agent Creator also stops it from discovering the tool.
- **Disable the connector for a workspace**: clear the **API credential** field and save. Be aware that this does not stop searches when a platform global key exists, because the workspace then falls back to it. To stop them entirely, also untick every agent and turn off **Allow all agents**.
- **Disable the fallback platform-wide**: a platform maintainer replaces or clears the global key from the maintainer view on the core `google-search` workspace. Every workspace without its own credential then fails with the missing-global-key message instead of searching.
- **Uninstall completely**: remove the MCP capability from every agent that points at the endpoint, uninstall the **Google Search** app from the workspace, delete the `googleSearchAuth` and `googleSearchAuthorizedAgents` secrets, then delete the API key or service account in Google Cloud if nothing else uses it.
