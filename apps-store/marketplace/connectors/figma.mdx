The Figma connector exposes 46 [Figma](https://www.figma.com) REST API operations covering files, nodes, rendered images, comments, projects, components, styles, webhooks, variables, dev resources, library analytics, organization activity logs and oEmbed metadata. It has two surfaces backed by the same code:

- An **MCP server** that **Agent Creator** agents call as tools. The 46 operations are grouped into **13 entity tools**, each driven by an `action` argument.
- A **Builder app** whose 46 instructions you call deterministically from DSUL as `Figma.<instruction>`.

## How the connector works

The MCP server runs in the **tenant app-instance context**: it resolves the installing workspace's own credentials and authorizes the calling agent against that workspace's allowlist. A single connector workspace serves every tenant; there is no per-tenant deployment and no HMAC key.

Every call goes through the same chain: the MCP endpoint identifies the calling agent, checks the workspace allowlist, resolves a Figma access token for the invoking user, then dispatches to the entity tool, which calls `https://api.figma.com`.

### Runtime identity

In all three authentication modes, Figma sees a **single Figma account**, and Figma enforces that account's own file and team permissions. Prisme.ai never widens what the account can reach.

| Mode | Figma identity used at runtime | Consent and revocation | Scope of the credential |
|---|---|---|---|
| `oauthCentral` | The invoking Prisme.ai user's own Figma account | Each user consents once; each user disconnects their own session | Personal to the user, per workspace |
| `oauth` | The invoking Prisme.ai user's own Figma account | Each user consents once against your workspace's OAuth client | Personal to the user, per workspace |
| `accessToken` | The owner of the token you configured | The workspace editor who stored the token holds revocation | Shared by every user and agent of the workspace |

<Warning>
  In `accessToken` mode every user of the workspace, and every allowlisted agent, acts as the single Figma account behind that token. Figma audit records attribute all reads and writes to that account, so individual attribution is lost. Use it only for unattended automation against intentionally shared design files, and grant the account the narrowest Figma access that works.
</Warning>

### Authentication modes

The connector resolves credentials server-side; no token is ever sent by the caller.

- **Per-user OAuth2 on the central client** (`oauthCentral`, recommended): one Figma OAuth application is registered once by the platform maintainer on the core `figma` workspace. Every end user signs in with their own Figma account. Nothing to register per workspace: each one installs the app and its users select **Connect**.
- **Per-user OAuth2 on a tenant client** (`oauth`): you store your own Figma OAuth client ID and secret in the connector configuration app. Each user signs in with their own account against your client.
- **Direct access token** (`accessToken`): a caller-managed Figma access token, used as-is with no exchange.

Both OAuth modes use the authorization-code flow with PKCE (`S256`), authorize at `https://www.figma.com/oauth` and exchange at `https://api.figma.com/v1/oauth/token`, requesting `access_type=offline` and `prompt=consent` so Figma issues a refresh token.

<Note>
  When no mode is stored, the connector behaves as `oauth`. If the workspace has not provided its own client ID and secret, it falls back to the central platform client, so an unconfigured workspace on a platform where the central client exists works like `oauthCentral`.
</Note>

<Warning>
  The `accessToken` mode sends the value as `Authorization: Bearer <token>`. A Figma **personal access token** is sent with the `X-Figma-Token` header instead and is therefore not usable in this mode. Supply a Figma OAuth access token.
</Warning>

## Prerequisites

- A **Figma** account, and Figma access to the files, projects and teams the agent will read.
- For the **OAuth modes**: a Figma OAuth application created at [Figma developer apps](https://www.figma.com/developers/apps). Copy its Client ID and Client Secret. The platform maintainer registers one application for the central mode; a workspace can register its own for the tenant mode.
- For the **`accessToken` mode**: a Figma OAuth access token with the scopes the operations you call require.
- Base URL, fixed by the connector: `https://api.figma.com`. Paths already carry their `/v1` or `/v2` prefix.

### Figma OAuth scopes

Unless the configuration app overrides them, the connector requests exactly these scopes:

```text
current_user:read file_content:read file_metadata:read file_versions:read file_comments:read projects:read
```

That default is read-only. The tools listed below are not covered by it, and Figma answers `403` until you add the matching scope to the **Scopes** field in the configuration app and every user reconnects.

| Add this scope | To unlock |
|---|---|
| `file_comments:write` | `comments` actions `create`, `delete`, `addReaction` and `deleteReaction` |
| `webhooks:read` and `webhooks:write` | every `webhooks` action |
| `file_variables:read` | `variables` actions `getLocal` and `getPublished` (Enterprise) |
| `file_variables:write` | `variables` action `modify` (Enterprise) |
| `file_dev_resources:read` and `file_dev_resources:write` | every `devResources` action |
| `library_analytics:read` | every `analytics` action (Enterprise) |
| `org:activity_log_read` | `activityLogs` action `list` (Enterprise, organization admin) |

Figma names the missing scope in the body of its `403` response, and the connector passes that detail through. See the [Figma scopes reference](https://developers.figma.com/docs/rest-api/scopes/) for the authoritative list.

<Warning>
  Adding a write scope grants every allowlisted agent in the workspace the ability to post and delete comments, create and delete webhooks, modify variables or modify dev resources with the connected user's Figma permissions. Keep the default read-only list unless an agent genuinely needs to write, and instruct the agent to confirm with the user before any destructive action.
</Warning>

<Note>
  Figma variables, library analytics and organization activity logs are gated by plan tier. The connector exposes them on every plan, but Figma answers `403` when the account is not entitled. Figma also lists `projects:read` as superseded by `folders:read`; the connector still requests `projects:read`, which is what the `projects` tool needs.
</Note>

  **Goal:** two one-time tasks: (1) configure the shared **central OAuth client** so every workspace lets its users sign in with their own Figma account, and (2) optionally expose Figma as a reusable **capability** in AI Governance so agent builders can enable it without pasting endpoint URLs.

This section carries only the Figma values you need while you follow them. Throughout, `<api-url>` is your environment's API URL (`https://api.studio.prisme.ai/v2` on production) and `<studio>` is your Studio URL.

  You need the **owner**, **editor** or **admin** role on the core `figma` workspace, or the platform `superadmin` role. Any other caller receives `403 Forbidden` from the configuration webhook. The full precondition list is in [Before you begin](/apps-store/marketplace/connectors/central-oauth#before-you-begin).

  ## 1. Configure the central OAuth client

  Follow [Configure the central client](/apps-store/marketplace/connectors/central-oauth#configure-the-central-client), substituting these Figma values.

  | Value in the shared flow | Figma |
  |---|---|
  | Provider console | [Figma developer apps](https://www.figma.com/developers/apps) |
  | Core callback URL to register | `<api-url>/workspaces/slug:figma/webhooks/oauthCallback` |
  | Scopes to grant and to store | The list in [Figma OAuth scopes](#figma-oauth-scopes) |
  | Maintainer view | `<studio>/apps/figma`, for example `https://studio.prisme.ai/apps/figma` |
  | Core workspace secret written | `figmaCentralOAuth` |
  | Core MCP endpoint | `<api-url>/workspaces/slug:figma/webhooks/mcp` |

  On production the callback is `https://api.studio.prisme.ai/v2/workspaces/slug:figma/webhooks/oauthCallback`. Register that single URI as the authorized redirect URI of the Figma application; the per-instance shape a tenant-owned client uses is different, as [Callback URLs](/apps-store/marketplace/connectors/central-oauth#callback-urls) explains. Figma shows the **Client Secret** only once, so copy it before leaving the page.

  The maintainer view writes the whole client object into the core workspace secret `figmaCentralOAuth`. Do not edit that secret by hand. The client secret never leaves the core workspace: tenant instances read only the public part (client ID and scopes) through the core `getOAuthClientPublic` webhook, and every token exchange is proxied through the core `centralTokenExchange` webhook, as described in [How the client secret stays in the core workspace](/apps-store/marketplace/connectors/central-oauth#how-the-client-secret-stays-in-the-core-workspace).

  Each consuming workspace then selects auth mode `oauthCentral` in its own configuration app, with no client ID or secret to enter, and its users select **Connect**. Hand them [Select the central client in a workspace](/apps-store/marketplace/connectors/central-oauth#select-the-central-client-in-a-workspace), then confirm the result with [Verify the central client](/apps-store/marketplace/connectors/central-oauth#verify-the-central-client).

  From the same maintainer view, **Add to catalog** publishes Figma to the organization-wide Capabilities catalog. The button stays disabled until the central client is saved. Once published, every agent builder in the organization can enable Figma from the catalog without pasting an endpoint, as described in [Option A](#option-a-for-the-shared-catalog-capability).

  <Warning>
    Once the central client is stored, the core workspace MCP endpoint (`<api-url>/workspaces/slug:figma/webhooks/mcp`) becomes a **shared global endpoint that accepts every calling agent**: the per-agent allowlist no longer applies there, and per-user OAuth is the only remaining gate. Agent builders who need per-agent control must install the connector in their own workspace, as described in [Option B](#option-b-for-your-own-workspace-instance). Read [Agent authorization on the core endpoint](/apps-store/marketplace/connectors/central-oauth#agent-authorization-on-the-core-endpoint) before you publish that endpoint to the catalog.
  </Warning>

  ## 2. Declare the capability in AI Governance

  As an alternative to, or in addition to, the catalog button, you can declare Figma as a named **capability** in AI Governance. Agent builders then enable that capability on their agents instead of pasting a raw MCP endpoint. Follow [Declare the capability manually in AI Governance](/apps-store/marketplace/connectors/declare-capability#declare-the-capability-manually-in-ai-governance) with these Figma values.

  | Capability field | Figma |
  |---|---|
  | Name | `Figma` |
  | Server URL (**SSE/WebSocket URL**) | The connector's MCP endpoint, core or workspace instance |
  | **Scope** | `context_id,agent_id,user_id` |
  | Authorization block | The connector's own `oauthConnect`, `oauthStatus` and `oauthDisconnect` webhooks |

  The `agent_id` in the **Scope** is what lets the connector identify and authorize the calling agent. This **Scope** is unrelated to the Figma OAuth scopes; [What the Scope means](/apps-store/marketplace/connectors/declare-capability#what-the-scope-means) covers the distinction.

  To verify, from an agent that has the capability, in a workspace configured for `oauthCentral`, call the `users` tool with `action: "getMe"`. The user is prompted to sign in to Figma once, and the tool then returns that user's own Figma profile. Subsequent calls reuse the stored token and refresh it automatically. [Verify the capability](/apps-store/marketplace/connectors/declare-capability#verify-the-capability) lists the remaining checks, including the deliberate denial test.

  <Warning>
    Declaring the capability makes the connector **available**; it does not by itself authorize a specific agent against a tenant instance. This connector follows the **tenant-context model**: on a workspace-installed instance, which agents may call it is gated by the **authorized agents** allowlist in the configuration app (see [Workspace builder](#workspace-builder-dsul)). There is also no OAuth auth-config JSON to attach in Governance: connect, status and disconnect are handled by the connector's own `oauthConnect`, `oauthStatus` and `oauthDisconnect` webhooks, which Agent Creator uses as the capability's `connect_url`, `status_url` and `disconnect_url`. See [Availability is not authorization](/apps-store/marketplace/connectors/declare-capability#availability-is-not-authorization).
  </Warning>
</Accordion>

    ## Agent builder

    **Goal:** let an agent you build in Agent Creator use Figma through MCP tools.

    <Note>
      Before an agent can call a workspace-installed instance, a workspace builder must have installed and configured the Figma app in a workspace (see [Workspace builder](#workspace-builder-dsul)), and, for the central OAuth mode, a platform maintainer must have provisioned the shared OAuth client (see [Platform maintainer setup](#platform-maintainer-setup-one-time-central-oauth-client)).
    </Note>

    On a workspace-installed instance your agent is authorized two ways at once: it is identified by the `agent_id` that Agent Creator injects through the capability **Scope**, and that agent must appear in the connector's **authorized agents** allowlist. The Figma access token itself is resolved server-side from the configured auth mode, per invoking user.

    There are two ways to wire it up. Pick based on how much isolation you need.

    ## Option A for the shared catalog capability

    The fastest path: a [platform maintainer](#platform-maintainer-setup-one-time-central-oauth-client) has already published a **Figma** capability to the Capabilities catalog, so you pick it from the catalog. Open your agent in Agent Creator, browse the capability catalog, select **Figma**, and enable it. The MCP endpoint URL and the **Scope** (`context_id,agent_id,user_id`) are already wired by the maintainer, so there is nothing to paste and no allowlist step on your side.

    On the first tool call, an unconnected user is prompted to sign in and Agent Creator surfaces a `connect_url` to Figma's authorization page. After sign-in the per-user token is stored and reused on subsequent calls. To verify, ask the agent to call the `users` tool with `action: "getMe"`: it returns the signed-in user's own Figma profile, which confirms both the wiring and the per-user identity.

    <Warning>
      The catalog capability points at the shared core instance. Because that instance is where the central OAuth client lives, it **accepts every agent that is granted the capability**: the per-agent allowlist does not apply to it, as [Agent authorization on the core endpoint](/apps-store/marketplace/connectors/central-oauth#agent-authorization-on-the-core-endpoint) explains. Its Figma OAuth client is also owned by the platform maintainer, not by you. Prefer [Option B](#option-b-for-your-own-workspace-instance) for anything beyond quick experiments.
    </Warning>

    ## Option B for your own workspace instance

    For production agents, install the connector in **your own workspace** and point the agent at that workspace's MCP endpoint:

    ```text
    <api-url>/workspaces/slug:<your-workspace-slug>/webhooks/<app-instance-slug>.mcp
    ```

    <Warning>
      **Prefer this mode for security.** Because the MCP server runs in *your* app-instance context, the Figma credentials, the per-user OAuth tokens and the authorized agents allowlist are all scoped to your workspace rather than shared platform-wide. You decide exactly which agents may call it and which auth mode backs them, and a misconfiguration elsewhere cannot expose your data.
    </Warning>

    <Steps>
      <Step title="Install and configure the connector in your workspace">
        Follow [Workspace builder](#workspace-builder-dsul): install **Figma** in your workspace, open its configuration app, choose the auth mode, and connect a Figma account.
      </Step>
      <Step title="Allowlist your agent and attach the capability">
        Run [Install the capability on one agent](/apps-store/marketplace/connectors/declare-capability#install-the-capability-on-one-agent) from that workspace's configuration app. **Install capability** allowlists your agent and attaches the MCP tool in one action, with the endpoint and the **Scope** already set. To do it by hand instead, tick your agent under **Authorized agents**, select **Save**, then add a capability pointing at your workspace's MCP endpoint URL with this **Scope**:

        ```text
        context_id,agent_id,user_id
        ```

        The `agent_id` is what lets the connector identify and authorize your agent. Without it, every call is rejected with a message stating that the calling agent could not be identified. This **Scope** is unrelated to the Figma OAuth scopes.
      </Step>
      <Step title="Connect a Figma account">
        On the first tool call the user is prompted to sign in, or they can select **Connect** in the configuration app. The per-user token is stored and reused, and refresh is automatic.
      </Step>
      <Step title="Verify with a read-only call">
        Ask the agent to call the `users` tool with `action: "getMe"`, then a real read such as `files` with `action: "getMeta"` on a file you can open in Figma. Both must succeed before you allow any write scope. [Verify the capability](/apps-store/marketplace/connectors/declare-capability#verify-the-capability) adds the checks that prove a non-allowlisted agent is still denied.
      </Step>
    </Steps>

    ## Brief the agent in its system prompt

    Whichever option you pick, wiring the capability is not enough: the agent must know the connector exists and when to reach for it. Add a short paragraph to the agent's system prompt. Copy-pasteable starter:

    ```text
    You have access to the Figma MCP server. Use it whenever the user asks about Figma content: files, nodes, rendered images, comments, projects, components, styles, webhooks, variables, dev resources or library analytics. Examples: "Summarize the comments on this Figma file", "Render the hero frame as a PNG", "List the published components in our design system". Each tool is an entity that takes an `action` argument. Prefer calling a tool over guessing, and always confirm with the user before a write or destructive action: posting or deleting a comment, creating or deleting a webhook, modifying variables, or modifying dev resources.
    ```

    Refine the trigger keywords (file keys, team names, component conventions) so the agent reliably picks up the right intent in your context.

    <Note>
      **Legacy AI Knowledge agents** without a native MCP picker: add the connector under **Advanced > Tools > MCP** and paste the MCP endpoint URL. The agent still has to be allowlisted in the configuration app, and its identity must be propagated so the connector can read its `agent_id`.
    </Note>

    ## Available tools

    Each tool is an entity. Pass the `action` argument to select the operation, plus the parameters that operation needs. Actions marked as writes need an extra OAuth scope, as listed in [Figma OAuth scopes](#figma-oauth-scopes).

    | Tool | Actions | Writes |
    |------|---------|--------|
    | `files` | `get`, `getNodes`, `getMeta`, `getVersions` | None |
    | `images` | `render`, `getFills` | None |
    | `comments` | `list`, `create`, `delete`, `listReactions`, `addReaction`, `deleteReaction` | `create`, `delete`, `addReaction`, `deleteReaction` |
    | `projects` | `listByTeam`, `listFiles` | None |
    | `components` | `listByTeam`, `listByFile`, `get`, `listSetsByTeam`, `listSetsByFile`, `getSet` | None |
    | `styles` | `listByTeam`, `listByFile`, `get` | None |
    | `users` | `getMe` | None |
    | `webhooks` | `list`, `create`, `get`, `update`, `delete`, `listByTeam`, `getRequests` | `create`, `update`, `delete` |

    ## Output formats

    Every tool accepts an `outputFormat` argument that controls the MCP response shape:

    - `verbose` (default): a human-readable text block wrapping the JSON payload, for LLM consumption.
    - `structured`: machine-readable JSON in `structuredContent`.
    - `both`: text and structured content together.

    ## Tool arguments

    `action` is required on every tool. Omitting it, or passing an unknown value, returns an error listing the available actions for that tool.

    ### files tool

    Read document data for a file.

    ```json
    {
      "name": "files",
      "arguments": {
        "action": "get",
        "file_key": "omLm4Pdg2a3BzTKU8EcDo7",
        "depth": 1
      }
    }
    ```

    | Argument | Type | Used by | Description |
    |---|---|---|---|
    | `file_key` | string | all actions | File key from the Figma file URL |
    | `ids` | string | `get`, `getNodes` | Comma-separated node ids |
    | `depth` | number | `get`, `getNodes` | Tree traversal depth, which limits the document JSON size |
    | `version` | string | `get`, `getNodes` | Specific file version id, defaults to current |
    | `geometry` | string | `get`, `getNodes` | Set to `paths` to export vector geometry |
    | `plugin_data` | string | `get`, `getNodes` | Comma-separated plugin ids, or `shared` |
    | `branch_data` | boolean | `get` | Include branch metadata |
    | `page_size` | number | `getVersions` | Page size |
    | `before`, `after` | string | `getVersions` | Pagination bounds |

    ### images tool

    Render nodes as images, or fetch the download links of a file's image fills.

    ```json
    {
      "name": "images",
      "arguments": {
        "action": "render",
        "file_key": "omLm4Pdg2a3BzTKU8EcDo7",
        "ids": "1:23,1:45",
        "format": "png",
        "scale": 2
      }
    }
    ```

    | Argument | Type | Used by | Description |
    |---|---|---|---|
    | `file_key` | string | all actions | Target file key |
    | `ids` | string | `render` | Comma-separated node ids to render |
    | `format` | string | `render` | `jpg`, `png`, `svg` or `pdf` |
    | `scale` | number | `render` | Render scale, from `0.01` to `4` |
    | `version` | string | `render` | Specific file version id |
    | `svg_outline_text`, `svg_include_id`, `svg_include_node_id`, `svg_simplify_stroke` | boolean | `render` | SVG output options |
    | `contents_only` | boolean | `render` | Exclude overlapping content outside the node bounds |
    | `use_absolute_bounds` | boolean | `render` | Use full node dimensions regardless of cropping |

    | Argument | Type | Used by | Description |

    ### users tool

    `getMe` takes no argument other than `action` and the optional `outputFormat`. It returns the profile of the Figma account whose token the connector resolved, which makes it the safest way to check whose identity an agent is running as.

    ### webhooks tool

    Manage Figma v2 webhooks subscribing to file and library events.

    ```json
    {
      "name": "webhooks",
      "arguments": {
        "action": "create",
        "event_type": "FILE_UPDATE",
        "context": "file",
        "context_id": "omLm4Pdg2a3BzTKU8EcDo7",
        "endpoint": "https://example.com/figma-hook",
        "passcode": "a-shared-secret"
      }
    }
    ```

    | Argument | Type | Used by | Description |
    |---|---|---|---|
    | `event_type` | string | `create`, `update` | Event type, for example `FILE_UPDATE`, `FILE_COMMENT` or `LIBRARY_PUBLISH` |
    | `endpoint` | string | `create`, `update` | HTTPS endpoint that receives webhook events |
    | `passcode` | string | `create`, `update` | Shared passcode sent with each event |

These are the Figma values you supply as you go.

    | Value in the shared flow | Figma |
    |---|---|
    | App to search for in **Apps** | **Figma** |
    | Secrets provisioned on install | `figmaAuth` and `figmaAuthorizedAgents` |
    | Configuration app | `<studio>/apps/figma`, opened from the **Configuration app** link with the `workspaceId`, `workspaceSlug` and `appInstance` query parameters filled in |

    <Warning>
      Skip the *Test the credential* step of the shared flow on this connector. Its `testAuth` endpoint is a leftover from the connector scaffold: it calls `https://www.figmaapis.com/drive/v3/about`, a Google Drive path on a host that does not exist, so a test-connection action reports a failure even when the stored credentials are valid.     ## Configuration

    The app instance exposes a single visible field. Everything else is driven from the configuration app.

    | Field | Description |
    |-------|-------------|
    | **Configuration app** | Auto-populated on install. Open this link to choose the auth mode, store credentials, connect a Figma account and manage the authorized agents allowlist. |

    From the configuration app you pick one of:

    | Auth mode | What you provide | Best for |
    |-----------|------------------|----------|
    | `oauthCentral` | Nothing beyond selecting **Connect** | Workspaces on a platform where the maintainer set up the central Figma client |
    | `oauth` | Your own Figma **Client ID** and **Client Secret** | You manage your own Figma OAuth application |
    | `accessToken` | A Figma OAuth access token | Unattended automation against intentionally shared files |

    In `oauth` mode, register this redirect URI on your own Figma application, copied from the configuration app rather than assembled by hand:

    ```text
    <api-url>/workspaces/slug:<your-workspace-slug>/webhooks/<app-instance-slug>.oauthCallback
    ```

    In `oauthCentral` mode you register nothing: the redirect URI is the core workspace one, held by the platform maintainer. [Callback URLs](/apps-store/marketplace/connectors/central-oauth#callback-urls) contrasts the two shapes.

    The connector stores what you enter in workspace secrets and resolves them server-side:

    | Secret | Holds |
    |---|---|
    | `figmaAuth` | The auth object: `mode`, `oauthClientId`, `oauthClientSecret`, `scopes`, `accessToken` |
    | `figmaAuthorizedAgents` | Comma-separated agent ids allowed to call this instance's MCP endpoint, or `*` for all |
    | `figRefresh_<userId>` | One per connected user, holding that user's Figma refresh token for non-interactive runs |

    <Warning>
      Never paste a Figma client secret or access token into an agent's system prompt, a chat message, an automation literal or a Git repository. Enter it only in the configuration app, which writes it to a workspace secret. `figmaCentralOAuth`, which holds the central platform client, lives on the core `figma` workspace and is never readable from a tenant workspace.
    </Warning>

    ### Token lifecycle

    - Access tokens are cached in user scope with an expiry. The connector refreshes proactively when fewer than 120 seconds remain, and assumes a 3300 second lifetime when Figma omits `expires_in`.
    - Figma does not reissue the refresh token on refresh, so the stored one is kept.
    - When Figma permanently rejects the refresh token (any `4xx`), the connector deletes the stored connection so the user is prompted to reconnect instead of hitting repeated failures. A `5xx` is treated as transient and the connection is kept.
    - The refresh token is additionally written to the workspace secret `figRefresh_<userId>` so scheduled automations can resolve that user without an interactive session. That write requires the connecting user to be a workspace editor or owner; for anyone else it is skipped silently and only the interactive path works.

## Error handling

The connector normalizes every Figma failure into a message naming the operation and the detail Figma returned. It never echoes the raw response body when it carries no recognized error field.

### HTTP errors from Figma

| Status | Message shape | Resolution |
|--------|---------------|------------|
| `400` | `Bad request while <operation>` | Check argument shapes: node ids, dates, enum values, and the body objects for `variables` and `devResources`. |
| `401` | `Authentication failed while <operation>` | The resolved token was rejected. Reconnect in the OAuth modes, or replace the token in `accessToken` mode. |
| `403` | `Forbidden while <operation>` | The token lacks the required OAuth scope, or the Figma account lacks the plan entitlement or the file permission. Figma names the missing scope in the detail. |
| `404` | `Resource not found while <operation>` | Verify the `file_key`, `team_id`, `project_id`, `webhook_id` or resource key. |
| `429` | `Rate limit / org limit exceeded while <operation>` | Back off and retry. See [Rate limits](#rate-limits). |
| `500` | `Figma server error while <operation>` | Transient Figma issue. Retry after a few seconds. |

### Connector errors

**`This agent is not authorized to use this connector`**: the calling agent is not in the allowlist of the workspace-installed instance. Open the configuration app, open **Authorized agents**, select this agent (its id is quoted in the message), and select **Save**. **Install capability** does this for you, and **Allow all agents** stores `*` to disable the gate. Owner: workspace builder.

**`The calling agent could not be identified`**: the MCP capability **Scope** does not declare `agent_id`, so Agent Creator never injects the agent identity. Set the Scope to `context_id,agent_id,user_id` on the capability, which is separate from the Figma OAuth scopes, then allowlist the agent in the configuration app. Owner: agent builder.

**`Figma is not connected for this user`**: no per-user OAuth token is stored for the caller. Open the configuration app in an OAuth mode and select **Connect**, or use the agent's connect flow. Owner: end user.

**`Figma token refresh failed`**: Figma rejected the stored refresh token, usually because it was revoked or expired. The connector drops the stored connection, so the user must reconnect from the configuration app. Owner: end user.

**`Figma token endpoint temporarily unavailable`**: Figma's token endpoint returned a `5xx`. This is transient, the stored connection is kept, and no reconnection is needed. Retry shortly. Owner: nobody, retry.

**`Figma OAuth is not configured`**: neither a tenant OAuth client nor the central platform client is available. Store the client ID and secret in the configuration app for the tenant mode, or ask the platform maintainer to provision the central OAuth client from the core `figma` workspace. Owner: workspace builder or platform maintainer.

**`Figma is not authenticated`**: no auth mode resolved at all, usually an instance installed but never configured. Open the configuration app, choose the mode, and store its credentials. Owner: workspace builder.

**`No stored Figma token for this user`**: a scheduled or otherwise non-interactive run tried to act on behalf of a user who has no `figRefresh_<userId>` secret. That secret is only written when the user connects while holding the workspace editor or owner role. Have them connect once from the configuration app with that role. Owner: workspace builder.

**`Direct calls are not allowed`**, returned as `403`: an entity automation was called directly instead of through the MCP endpoint. Point the caller at the MCP endpoint URL, or use the `Figma.<instruction>` App instructions from DSUL. Owner: agent builder or workspace builder.

**`Unknown tool`**: the requested tool name does not exist on this instance. Check the spelling against [Available tools](#available-tools). Owner: agent builder.

**`Missing required argument action`** or **`Unknown action`**: the tool call omitted `action` or passed a value outside its enum. The message lists the available actions for that tool. Owner: agent builder.

**Activity logs need an OAuth token**: `activityLogs` requires the `org:activity_log_read` scope, which Figma grants only to an organization admin on an Enterprise plan. A token without that scope is rejected with `403`.

## Rate limits

Figma applies per-minute limits that vary by seat type, endpoint tier and plan, and returns `429` with a `Retry-After` header telling you how long to wait. The `files` and `images` operations sit in Figma's most restrictive tier, so prefer narrowing reads with `ids` and `depth` over fetching whole documents in a loop. See the [Figma rate limits reference](https://developers.figma.com/docs/rest-api/rate-limits/) for the current figures.

## Disconnect, rotate and remove

The generic version of these controls is in [Rotate credentials and uninstall](/apps-store/marketplace/connectors/install-in-workspace#rotate-credentials-and-uninstall), and, for the central client, [Rotate and revoke the central client](/apps-store/marketplace/connectors/central-oauth#rotate-and-revoke-the-central-client). What follows is what differs for Figma.

- **A user disconnects their own account**: from the configuration app, or from the agent's disconnect action, which both open the connector's `oauthDisconnect` webhook. It deletes the stored access and refresh tokens and the user's `figRefresh_<userId>` workspace secret. Figma exposes no token revocation endpoint, so the tokens are dropped on the Prisme.ai side rather than revoked at Figma. To revoke at Figma, the user removes the application from their Figma account.
- **Offboard a user**: have them disconnect, or delete their `figRefresh_<userId>` workspace secret. Their user-scoped token disappears with their Prisme.ai account.
- **Rotate a tenant OAuth client secret**: generate a new secret at Figma, store it in the configuration app, and select **Save**. Existing refresh tokens minted with the old secret stop working, so every user of that workspace must reconnect.
- **Rotate the central OAuth client secret**: the platform maintainer stores the new secret in the maintainer view of `<studio>/apps/figma`. Every user across every workspace on `oauthCentral` must then reconnect.
- **Change the requested scopes**: update the **Scopes** field and have every user reconnect. Existing tokens keep the scopes they were granted.
- **Revoke an agent's access**: remove it from **Authorized agents** and select **Save**, or clear **Allow all agents**. This takes effect on the next call. It does not apply to the shared core instance, which accepts every agent granted the capability.
- **Remove the connector**: uninstall the Figma app from the workspace, then delete the `figmaAuth`, `figmaAuthorizedAgents` and `figRefresh_<userId>` secrets so no credential material is left behind. Uninstalling does not delete them for you. If Figma was published to the Capabilities catalog, remove that entry too, as described in [Remove or update a capability](/apps-store/marketplace/connectors/declare-capability#remove-or-update-a-capability).
