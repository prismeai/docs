The Gryzzly app exposes the [Gryzzly](https://www.gryzzly.io) time-tracking SaaS (v1 REST-RPC API) through entity tools. It can be consumed two ways: as a remote MCP server that **Agent Creator** agents call as tools, or as a Builder app whose instructions you call directly from DSUL. It runs in the **tenant app-instance context** (it resolves the installing workspace's own Gryzzly API key) and covers customers, projects, tasks, declarations (time entries), leave periods, discounts, purchases, users, groups, groupsets, tags, tagsets and project metrics.

Authentication is a **Gryzzly API key** sent server-side as `Authorization: Bearer <token>`, never exposed to the agent. Agents are identified by the capability **Scope** `context_id,agent_id,user_id` and gated by a per-workspace authorized-agents allowlist.

## Operating model

Gryzzly ships a single authentication mode, so there is no credential decision to make: the connector authenticates with one **static Gryzzly API key** per workspace, stored as a workspace secret and sent server-side.

| Property | Value |
|----------|-------|
| Credential model | Shared static API key (`apiKey` mode), one per installing workspace |
| Runtime identity at Gryzzly | The **owner of the API key**, never the invoking end user or agent builder |
| Where the credential lives | The `gryzzlyAuth` workspace secret, provisioned on install as `{ mode, token, baseUrl }` |
| Who may call the MCP endpoint | Only agents in the workspace's authorized-agents allowlist (`gryzzlyAuthorizedAgents` secret) |
| Delegated per-user OAuth | Not supported by this connector |
| Transport | `POST {baseUrl}/{resource}.{action}` with a JSON body; there are no GET, path or query endpoints |

<Warning>
  Because every call uses one shared API key, Gryzzly attributes all reads and writes to the key owner, and every allowlisted agent inherits that account's permissions. Grant the key the narrowest Gryzzly role that covers your use case, and keep the allowlist tight rather than enabling **Allow all agents** in production.
</Warning>

## Prerequisites

- A **Gryzzly** account allowed to create API keys.
- A **Gryzzly API key**, created in Gryzzly under **Administration > API Keys** ([app.gryzzly.io/administration/api-keys](https://app.gryzzly.io/administration/api-keys)).
- The API key owner must hold the Gryzzly role required for the resources you intend to use; a key with an insufficient role fails writes with `403`.
- The Gryzzly API base URL. The connector defaults to `https://api.gryzzly.io/v1` when you leave it empty.
- To install the connector in a workspace: the `owner`, `editor` or `admin` role on that Builder workspace, as described in [Before you begin](/apps-store/marketplace/connectors/install-in-workspace#before-you-begin).

<Accordion title="Platform admin (Governance): one-time platform setup" icon="shield-halved">
  **Goal:** Gryzzly is a **per-workspace** connector: each workspace configures its own Gryzzly API key (see [Workspace builder](#workspace-builder-dsul)), so there is **no platform-wide credential to provision**. The only optional platform task is to publish Gryzzly as a reusable **capability** in your organization's Capabilities catalog so agent builders can enable it from the catalog instead of wiring a raw MCP endpoint.

    ## Agent builder

    **Goal:** let an agent you build in Agent Creator use Gryzzly through MCP tools.

    <Note>
      Before an agent can call the connector, a *Workspace builder* must have installed and configured the Gryzzly app in a workspace (see [Workspace builder](#workspace-builder-dsul)). Optionally, a *Platform admin* may have published a Gryzzly capability in the Capabilities catalog (see [Platform admin setup](#platform-admin-governance-one-time-platform-setup)).
    </Note>

    This connector runs in the **tenant app-instance context**: your agent is identified by the `agent_id` that Agent Creator injects through the capability *Scope*, and that agent must appear in the connector's **authorized-agents allowlist** (managed in the configuration app). The Gryzzly API key itself is resolved server-side, never exposed to the agent. The MCP server announces itself as `gryzzly-mcp` version `1.0.0`, and its tool manifest is derived from the connector's own tool automations, so `tools/list` always returns the 13 entity tools below.

    The wiring itself is the standard connector flow, documented in [Declare a connector capability](/apps-store/marketplace/connectors/declare-capability). Shortest path: run [Install the capability on one agent](/apps-store/marketplace/connectors/declare-capability#install-the-capability-on-one-agent) from the workspace's configuration app, which allowlists your agent and attaches the MCP tool in a single action. If an organization owner or admin already [published Gryzzly to the catalog](/apps-store/marketplace/connectors/declare-capability#publish-the-connector-to-the-capabilities-catalog), select **Gryzzly** there instead: the endpoint and Scope are pre-wired, but the workspace allowlist still applies, so your agent must be ticked (step 2 below).

    <Steps>
      <Step title="Install and configure the connector in your workspace">
        Follow [Workspace builder](#workspace-builder-dsul): install **Gryzzly** in your workspace, open its **Configuration app**, paste your Gryzzly API key (and the base URL if you are not on the default host), and click **Test connection**.
      </Step>
      <Step title="Allowlist your agent">
        In that workspace's configuration app, open **Authorized agents** and tick your agent (the **Install capability** button does this for you), or enable **Allow all agents**. Save. See [Authorize the agents that may call the connector](/apps-store/marketplace/connectors/install-in-workspace#authorize-the-agents-that-may-call-the-connector).
      </Step>
      <Step title="Add the MCP capability to your agent">
        In your agent, add a capability pointing at **your workspace's MCP Endpoint** URL, and set its **Scope** to:

        ```text
        context_id,agent_id,user_id
        ```

        The `agent_id` is what lets the connector identify and authorize your agent; without it, every call is rejected with an explicit "agent could not be identified" message. Gryzzly consumes no chat attachments, so it never needs `attachment_urls`.
      </Step>
      <Step title="Brief the agent">
        Tell the agent the tools exist and when to use them. Copy-pasteable starter:

        ```text
        You have access to the Gryzzly MCP server. Use it whenever the user asks about time-tracking data: customers, projects, tasks, declarations (time entries), leave periods, purchases or project metrics. Each tool takes an `action` argument (list, get, create, update, delete, invite). Examples: "How many hours were declared on this task last week?", "Create a new project under customer Acme", "List the leave periods for this user", "Show the metrics of this project". Prefer calling a tool over guessing, and confirm with the user before any destructive action (delete a project, remove a declaration, delete a leave period).
        ```

        Refine the trigger keywords (customer names, project codes, internal task labels) so the agent reliably picks up the right intent in your context.
      </Step>
      <Step title="Verify with a read-only call">
        Ask the agent something that resolves to a read, for example "List the Gryzzly projects". A correct setup returns a project list. An unauthorized agent returns `This agent is not authorized to use this connector.` and a workspace with no API key returns `Gryzzly is not configured for this workspace.` Work through [Verify the capability](/apps-store/marketplace/connectors/declare-capability#verify-the-capability) for the full check, including confirming that a non-allowlisted agent is still denied.
      </Step>
    </Steps>

    <Note>
      **Legacy AI Knowledge agents** (no native MCP picker): add the connector under **Advanced > Tools > MCP** and paste the **MCP Endpoint** URL. The agent still has to be allowlisted in the configuration app and its identity propagated so the connector can read its `agent_id`.
    </Note>

    ## Available tools

    Each tool maps to a Gryzzly entity and takes an `action` argument selecting the concrete operation, plus the per-action parameters. All IDs are UUIDs returned by Gryzzly. Every list action except `metrics` accepts `limit` (max `1000`) and `offset` for pagination, and every tool accepts `outputFormat`.

    | Tool | Actions | Required arguments |
    |------|---------|--------------------|
    | `customers` | `list`, `get`, `create`, `update`, `delete` | `create`: `name`. `update`: `id`, `name`. `get` / `delete`: `id`. |
    | `projects` | `list`, `get`, `create`, `update`, `delete` | `create`: `start_at`. `update`: `id`, `start_at`. `get` / `delete`: `id`. |
    | `tasks` | `list`, `get`, `create`, `update`, `delete` | `create`: `name`, `project_id`, `start_at`. `update` / `get` / `delete`: `id`. |
    | `declarations` | `list`, `create`, `update`, `delete` | `list`: `task_ids`, `user_ids`. `create`: `date`, `duration`, `task_id`, `user_id`. `update`: `id`, `date`, `duration`, `task_id`. `delete`: `id`. |
    | `leavePeriods` | `list`, `get`, `create`, `update`, `delete` | `get`: `id`. `update` / `delete` address the record through `id`. |
    | `discounts` | `list`, `get`, `create`, `update`, `delete` | `create`: `name`. `get` / `delete`: `id`. `update` addresses the record through `id`. |
    | `purchases` | `list`, `get`, `create`, `update`, `delete` | `get` / `delete` / `update`: `id`. |
    | `users` | `list`, `get`, `invite` | `get`: `id`. |
    | `groups` | `list`, `get` | `get`: `id`. |
    | `groupsets` | `list`, `get` | `get` addresses the record through `id`. |
    | `tags` | `list`, `get` | `get`: `id`. |
    | `tagsets` | `list`, `get` | `get` addresses the record through `id`. |
    | `metrics` | `get`, `list` | `list`: `project_ids`. `get` addresses the project through `project_id`. |

    <Note>
      There is no `get` action on `declarations`: read a single time entry through `declarations` / `list` filtered on `task_ids` and `user_ids`. The `leavePeriods` tool maps to the Gryzzly `leavesPeriods` resource, which is why the Builder instruction names read `listLeavesPeriods` and `getLeavesPeriod`.
    </Note>

    <Warning>
      The tool automations only accept calls dispatched by the connector's own MCP endpoint. Calling a tool webhook directly returns HTTP `403` with `Direct calls are not allowed — use the MCP endpoint.`
    </Warning>

    ## Output formats

    Every tool accepts an `outputFormat` argument that controls the MCP response shape:

    - **`verbose`** (default): a human-readable text block that wraps the API payload as JSON, optimized for LLM consumption.
    - **`structured`**: the API payload serialized as JSON in `content[0].text` and repeated as `structuredContent`.
    - **`both`**: identical to `structured`.

    ## Tool details

    ### declarations: create

    Log a time entry on a task for a specific user.

    ```json
    {
      "name": "declarations",
      "arguments": {
        "action": "create",
        "user_id": "user-uuid",
        "task_id": "task-uuid",
        "date": "2026-04-20",
        "duration": 7200,
        "description": "Implementation review"
      }
    }
    ```

    | Parameter | Required | Description |
    |-----------|----------|-------------|
    | `action` | Yes | `create`. |
    | `date` | Yes | Declaration date (`YYYY-MM-DD`). |
    | `duration` | Yes | Duration in seconds. |
    | `task_id` | Yes | UUID of the task. |
    | `user_id` | Yes | UUID of the user. |
    | `description` | No | Free-form text, max 256 characters. |

    ### projects: create

    ```json
    {
      "name": "projects",
      "arguments": {
        "action": "create",
        "name": "Website Revamp",
        "start_at": "2026-01-06",
        "customer_id": "customer-uuid",
        "visibility": "private",
        "managers": ["manager-uuid"]
      }
    }
    ```

    | Parameter | Required | Description |
    |-----------|----------|-------------|
    | `action` | Yes | `create`. |
    | `start_at` | Yes | Project start date (`YYYY-MM-DD`). |
    | `name` | No | Project name. |
    | `code` | No | Project code, max 36 characters. |
    | `visibility` | No | `public` or `private`; `contributors` must be empty when `public`. |
    | `is_billable` | No | Defaults to `false`. See the billing warning below. |
    | `customer_id`, `end_at`, `managers`, `contributors`, `groups`, `tags` | No | Optional structure; `managers`, `contributors`, `groups` and `tags` are UUID arrays. |

    `projects` / `list` filters on `status`, an array of `active`, `done` and `archived`.

    <Warning>
      **Billing trap:** the API cannot set `is_billable: true`; Gryzzly rejects it with `409 business: can't handle billable project`. Billing modes (fixed-fee, package, time-and-material) live at the **task** level and must be configured in the Gryzzly UI (`app.gryzzly.io`). Always create and update projects with `is_billable: false` (the default), then configure billing tasks in the UI. The billable to non-billable transition is irreversible and wipes financial data.
    </Warning>

    ### tasks: create

    ```json
    {
      "name": "tasks",
      "arguments": {
        "action": "create",
        "project_id": "project-uuid",
        "name": "Design System",
        "start_at": "2026-01-06",
        "budget_type": "time",
        "planned_duration": 80
      }
    }
    ```

    | Parameter | Required | Description |
    |-----------|----------|-------------|
    | `action` | Yes | `create`. |
    | `name` | Yes | Task name. |
    | `project_id` | Yes | UUID of the parent project. |
    | `start_at` | Yes | Task start date (`YYYY-MM-DD`). |
    | `budget_type` | No | `none`, `detailed`, `global` or `time`. |
    | `budget_amount` | No | Budget amount. |
    | `hourly_rate_mode` | No | `task`, `group` or `contributor`. |
    | `hourly_rate` | No | Hourly rate applied when `hourly_rate_mode` is `task`. |
    | `planned_duration` / `estimated_duration` | No | Integer durations. |
    | `parent_id` / `is_container` | No | Build sub-tasks (`parent_id`) and parent containers (`is_container`). |
    | `end_at`, `groups`, `tags` | No | Optional structure. |

    `tasks` / `update` also accepts `completed_at`, a `date-time` marking the task as completed.

    {
      "name": "leavePeriods",
      "arguments": {
        "action": "create",
        "user_id": "user-uuid",
        "start_at": "2026-05-10",

    ## Installation

    The install, credential and allowlist procedure is the standard one, documented step by step in [Install a connector in your workspace](/apps-store/marketplace/connectors/install-in-workspace). Gryzzly-specific points along that path:

    | Shared step | What Gryzzly needs |
    |-------------|--------------------|
    | [Install the app](/apps-store/marketplace/connectors/install-in-workspace#install-the-app) | Search for **Gryzzly** in **Apps**. The install [provisions](/apps-store/marketplace/connectors/install-in-workspace#what-installing-provisions) the `gryzzlyAuth` and `gryzzlyAuthorizedAgents` workspace secrets and fills the **Configuration app** link. |
    | [Configure credentials](/apps-store/marketplace/connectors/install-in-workspace#configure-credentials-in-the-configuration-app) | There is only one mode to select. Paste the Gryzzly API key, and set the base URL only if you are not on `https://api.gryzzly.io/v1`. Save. There is no callback URL to register and no per-user account to connect. |
    | Test connection | **Test connection** performs an authenticated `users.list` call limited to one record and reports the resolved base URL on success. A failure means the key is invalid, revoked, or pointed at the wrong base URL; no credential value is ever echoed back. |
    | [Authorize agents](/apps-store/marketplace/connectors/install-in-workspace#authorize-the-agents-that-may-call-the-connector) | Open **Authorized agents**, tick each agent allowed to reach the MCP endpoint (or enable **Allow all agents**), and Save. |

    | [Verify the installation](/apps-store/marketplace/connectors/install-in-workspace#verify-the-installation) | Use `users` / `list` as the read-only check and `declarations` / `list` as the narrow query. Every response reflects the API key owner's Gryzzly permissions, not the caller's. |

    ## Configuration

    | Field | Description |
    |-------|-------------|
    | **Configuration app** | Read-only, auto-generated on install. Open this link to set the Gryzzly API key and base URL and to manage the authorized-agents allowlist. |

    The configuration app drives everything; the app instance itself has no per-field credential form. From it you provide:

    | Auth mode | What you provide | Best for |
    |-----------|------------------|----------|
    | `apiKey` (only mode) | A Gryzzly **API key** and, optionally, the **base URL** (default `https://api.gryzzly.io/v1`) | All setups: the key is stored as a workspace secret and sent server-side as `Authorization: Bearer <token>` |

    The values land in two workspace secrets:

    | Secret | Contents |
    |--------|----------|
    | `gryzzlyAuth` | `{ mode: "apiKey", token, baseUrl }`. `mode` is always `apiKey`; an empty `token` makes every call fail with `Gryzzly is not configured for this workspace.` |
    | `gryzzlyAuthorizedAgents` | Comma-separated agent IDs allowed to call the MCP endpoint. The `*` sentinel allows every agent. |

    <Note>
      Both secrets are written through the configuration app. Edit them there rather than by hand so the workspace config bindings that make `config.auth` and `config.authorizedAgents` resolve stay intact.
    </Note>

    ## Rotate, revoke and remove

    The generic rules, including the fact that uninstalling does **not** delete the workspace secrets, are in [Rotate credentials and uninstall](/apps-store/marketplace/connectors/install-in-workspace#rotate-credentials-and-uninstall). What that means for Gryzzly:

    - **Rotate the API key:** create a new key in Gryzzly under **Administration > API Keys**, paste it in the configuration app, click **Test connection**, then delete the old key in Gryzzly. Calls in flight with the old key fail with `401` until the new key is saved.
    - **Revoke access immediately:** delete the key in Gryzzly. Every tool call and instruction then fails with the `401` authentication message; the connector holds no cached token.
    - **Cut off one agent:** untick it under **Authorized agents** (or remove its ID from `gryzzlyAuthorizedAgents`) and Save. The next call from that agent is refused with `This agent is not authorized to use this connector.`
    - **Cut off every agent at once:** clear the allowlist, including the `*` sentinel if it is set.
    - **Remove the connector:** uninstall the **Gryzzly** app from the workspace, then delete the `gryzzlyAuth` and `gryzzlyAuthorizedAgents` secrets so the credential does not survive the uninstall. Detach any capability that pointed at this workspace's MCP endpoint, as described in [Remove or update a capability](/apps-store/marketplace/connectors/declare-capability#remove-or-update-a-capability).

    ## Available instructions

    Every instruction resolves credentials from the workspace configuration. All IDs are UUIDs returned by Gryzzly. Most list operations accept `limit` (max `1000`) and `offset` for pagination.

    ### Customers

## Error handling

Gryzzly replies with an HTTP status and a body shaped `{error_type, error_description}`. The connector normalizes both into one message, quoting the Gryzzly detail after `Detail:`.

| HTTP Status | Message the connector returns | Solution |
|-------------|-------------------------------|----------|
| 400 | `Bad request while <operation>` | Check argument names, enum values and date formats (`YYYY-MM-DD`). |
| 401 | `Authentication failed while <operation>. Your Gryzzly API key may be invalid or revoked.` | Re-paste the API key in the configuration app and click **Test connection**. |
| 403 | `Forbidden while <operation>. The API key lacks permissions for this operation.` | Raise the Gryzzly role of the API key owner, or use an operation the key is allowed to perform. |
| 404 | `Resource not found while <operation>` | Verify the UUIDs for customer, project, task, user and so on. |
| 429 | `Rate limit exceeded while <operation>. Wait before retrying.` | Back off and retry with an increasing delay. |
| 500 | `Gryzzly server error while <operation>` | Transient Gryzzly failure; retry shortly. |
| 500 with `gapi: internal server error` | `Resource not found while <operation>. Gryzzly returned a generic internal error, which usually means the provided id is missing or invalid.` | Gryzzly answers write endpoints with a generic 500 when the target `id` does not exist. Re-read the record before updating or deleting it. |
| Any other status | `Error <status> while <operation>` | Read the quoted `error_type` and `error_description` from Gryzzly. |

### Common issues

Problems that are not Gryzzly-specific, such as an empty **Configuration app** field after install or an allowlist secret still holding an unresolved binding, are covered in [Troubleshooting](/apps-store/marketplace/connectors/install-in-workspace#troubleshooting) and [Troubleshooting a capability](/apps-store/marketplace/connectors/declare-capability#troubleshooting).

**`This agent is not authorized to use this connector.`**: the calling agent is not in the allowlist. Open the configuration app, go to **Authorized agents**, tick this agent (the message quotes its ID) or enable **Allow all agents**, and Save.

**`The calling agent could not be identified, so it cannot be authorized.`**: the MCP capability *Scope* does not declare `agent_id`, so Agent Creator never injects the agent identity. Set the Scope to `context_id,agent_id,user_id` on the capability, then allow the agent in the configuration app.

**`Gryzzly is not configured for this workspace.`**: no API key is set. Open the configuration app and paste the Gryzzly API key created under **Administration > API Keys**, plus the base URL if you are not on the default host.

**``Unknown tool `<name>`.``**: the agent called a tool that this connector does not expose. Only the 13 entity tools listed above exist; re-check the tool name against `tools/list`.

**``Missing required argument `action` for `<tool>`.``** or **``Unknown action `<value>` for `<tool>`.``**: the agent omitted `action` or used a value outside the tool's enum. The message lists the accepted actions for that tool.

**``Direct calls are not allowed — use the MCP endpoint.``** (HTTP `403`): a tool webhook was called directly instead of through the connector's MCP endpoint. Route the call through the **MCP Endpoint** URL.

**`409 business: can't handle billable project`**: you tried to create or update a project with `is_billable: true`. Leave it `false`; billing modes are configured at the task level in the Gryzzly UI (`app.gryzzly.io`), not through the API.

**`contributors` rejected on a public project**: set `visibility: private` or leave `contributors` empty.
